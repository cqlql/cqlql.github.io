桌面启动器与本地网页面板（通用实现手册）

桌面启动器与本地网页面板（通用实现手册）

状态：母本 · 现行（2026-11-05 从 pass-up.ops 与 suikouji 两次实战提炼）

这份文档的用法：新项目要做「桌面上双击一个图标 → 直接打开本地网页面板」时， 把这一篇整份丢给 AI，让它按第 3–11 节施工，按第 12 节验收。不需要再去读那两个项目的源码。

本文只写通用判据与可复制骨架；具体常量（项目名、exe 路径、端口、配置目录）见第 13 节。

0. 一页速用

目标形态，三段结构，形状固定：

桌面 .lnk  →  仓库根「启动<工具名>.cmd」  →  <exe> <动词>
（只存路径）   （构建 / 配置 / 单实例 / 前后台）   （真正干活）

无参双击时，动词是 ui --background：启动器前台进程几百毫秒内退出， 一条隐藏的 cmd 托管 ui，浏览器自动打开带 token 的地址，桌面不留黑窗口。

三句红线，先记住：

  1. 🔴 .lnk 只指启动器，不指 exe。指 exe 会绕过构建、配置模板、单实例判断， 换台机器必然「双击没反应」，而且错误现场没有任何提示。
  2. 🔴 双击不执行写操作。落地页必须只读；唯一的写要人显式点击（还要二次确认/输密码）。
  3. 🔴 后台失败必须可见。隐藏窗口里的失败 = 用户眼里的「双击没反应」， 这是本类工具最高频的投诉，必须在架构上堵死（见 5.6）。

1. 适用与不适用

适用：本地单二进制工具（Go / Rust / Node 打包均可），已经有或想要一个本地 Web 面板， 用户不想记命令、不想开终端。

不适用（别硬套）：

  • 服务端程序。本文全部动作发生在本机，不碰远端。
  • 需要开机自启 / 托盘常驻 / 安装器的产品。本文明确不做这些（\.lnk 只写桌面一个文件）。
  • macOS / Linux 的等价物。.lnk 与 WScript.Shell 是 Windows 专属； 其它平台应明确报「请自己建一个指向启动器的入口」，不要假装成功。

2. 三段结构：每层只干一件事

层文件职责不能做
快捷方式桌面 <名字>.lnkTargetPath / WorkingDirectory / IconLocation / Description / WindowStyle不带业务参数、不直接指 exe、不写配置
启动器仓库根 启动<工具名>.cmd定位或构建 exe、首次写配置模板、单实例、前后台、日志、参数透传不实现业务逻辑、不判断该跑哪个远端动作
程序<exe> <动词>真正的命令（init / ui / backup deploy …）不关心自己是被双击还是被手敲启动的

为什么启动器放仓库根：%~dp0 天然是仓库根，配置目录、兄弟仓库的相对路径都从这里算； 放深一层就得靠 .. 拼，容易和「向上找启动器」的层级判断打架。

3. 代码分层与依赖方向

以 Go 为例（其它语言照搬职责划分）：

main.go                       只做命令分发 + 注入
internal/shared/              跨能力共用：配置目录、单实例、共享模型
internal/<能力>/              各能力的实现与 CLI 分发
internal/ui/                  网页面板服务端 + 后台调度
internal/launcher/            桌面快捷方式 + 交互菜单

🔴 依赖方向只许单向：main → {能力包, ui, launcher} → shared。 ui 与 launcher 之间不能互相 import。两条实操结论：

需求错的做法对的做法
界面要调「建快捷方式」ui import launcher（而 launcher 已 import ui → 成环）main 把函数注给 ui：ui.CmdUI(args, static, createShortcut)
界面与菜单都要「单实例」各写一份 Windows API 胶水下沉 shared.AcquireSingleton(name)，两边各传不同名字
界面要回传快捷方式结果在 ui 里再定义一份结构体模型下沉 shared.ShortcutInfo，两边共用

注入的签名要窄：只传函数，不传整个包。菜单同理：launcher.CmdMenu(args, exec, probe) 由 main 注入 run 与「这个动词注册了吗」。

4. 启动器契约（.cmd）

4.1 固定顺序

cd /d "%~dp0" + chcp 65001
  → 剥启动器自己的开关（--bg / --fg / --menu），其余留作透传
  → --bg（隐藏守护专用）：直接跑 ui，不构建不 init，所有 pause 都跳过
  → 定位 exe；缺 exe：找工具链（PATH → 常见安装目录回退）→ 构建
  → 缺配置模板：跑 init（首次才占窗口，且不覆盖已有配置）
  → 分流：显式子命令 → 原样转发；--menu → 菜单；首次 / --fg → 前台 ui
  → 日常：<exe> ui --background --launcher "%~f0" [透传参数]
          Go 侧用命名互斥体判单实例：已有实例只把浏览器指过去
          否则 spawn 一条隐藏 cmd（--bg），前台 exit 0，黑窗口立刻消失
  → 退出码：0 正常；非 0 报错（后台不 pause）；后台启动失败则回退前台

4.2 参数分流（顺序不能换）

调用走到哪
无参ui --background --launcher "%~f0"（隐藏守护 + 开浏览器）
--port 7790 / --no-open 等以 - 开头同上，参数透传给后台的 ui
--fg（可叠加参数）前台 ui，保留窗口看 stdout
--menu交互菜单（如果项目有）
help / list / deploy --dry-run 等显式子命令原样转发 exe，前台
--bg内部专用：隐藏守护里的 启动<工具名>.cmd --bg 直接跑 ui

🔴 显式子命令优先于 --fg：启动X.cmd --fg help 必须等于 X.exe help， 不能变成 ui help。判据是「透传串的第一个字符是不是 -」。

4.3 可复制骨架

@echo off
setlocal
title <工具名>
rem Go 输出 UTF-8；默认 GBK 控制台会乱码。本文件正文全是 ASCII，切代码页安全。
chcp 65001 >nul
cd /d "%~dp0"

set "EXE=%~dp0<exe>"
set "CFG=%APPDATA%\<vendor>\<tool>.env"
if defined <TOOL>_ENV set "CFG=%<TOOL>_ENV%"

rem ---- 0) 剥掉本文件自己的开关：一条一句，不要放进 ( ) 块 ----
set "PASS=%*"
if /i "%~1"=="--bg" set "BG=1"
if /i "%~1"=="--fg" set "FG=1"
if /i "%~1"=="--menu" set "MENU=1"
if defined BG set "PASS=%PASS:--bg =%"
if defined BG if /i "%PASS%"=="--bg" set "PASS="
if defined FG set "PASS=%PASS:--fg =%"
if defined FG if /i "%PASS%"=="--fg" set "PASS="
if defined MENU set "PASS=%PASS:--menu =%"
if defined MENU if /i "%PASS%"=="--menu" set "PASS="

rem ---- 1) 显式子命令优先（脚本化 / 向后兼容）----
set "FWD="
if defined PASS if not "%PASS:~0,1%"=="-" set "FWD=1"

rem ---- 2) 隐藏守护：不构建、不 init，直接跑 ui ----
if not defined BG goto ensure
if not exist "%EXE%" goto no_exe
goto run_ui

rem ---- 3) 缺 exe 才构建 ----
:ensure
if exist "%EXE%" goto env_check
set "FIRST=1"
set "GO="
set "GO_DIR="
where go >nul 2>nul
if not errorlevel 1 set "GO=go"
if not defined GO if exist "%USERPROFILE%\go\bin\go.exe" call :pick "%USERPROFILE%\go\bin"
if not defined GO if exist "%ProgramFiles%\Go\bin\go.exe" call :pick "%ProgramFiles%\Go\bin"
if not defined GO goto no_exe
echo [ops] go build -o <exe>
"%GO%" build -o "%EXE%" .
if errorlevel 1 goto build_failed
goto env_check

rem 记住工具链目录：业务命令可能 shell out 到它（如 deploy 里的 go build），
rem 只把 go.exe 路径存进 GO 是不够的——子进程要靠 PATH 才找得到。
:pick
set "GO=%~1\go.exe"
set "GO_DIR=%~1"
goto :eof

rem ---- 4) 首次写配置模板，绝不覆盖 ----
:env_check
if exist "%CFG%" goto dispatch
set "FIRST=1"
echo [ops] first run - writing %CFG%
"%EXE%" init
if errorlevel 1 goto init_failed

rem ---- 5) 分流 ----
:dispatch
rem 业务命令可能 shell out 到工具链（如 deploy 里的 go build）：找到的目录也要进 PATH。
if defined GO_DIR set "PATH=%GO_DIR%;%PATH%"
if defined FWD goto forward
if defined MENU goto run_menu
if defined FIRST goto run_ui
if defined FG goto run_ui
goto background

:background
echo [ops] starting the UI in the background (browser opens; stop it from the page)
"%EXE%" ui --background --launcher "%~f0" %PASS%
if not errorlevel 1 exit /b 0
echo [ops] background start FAILED - falling back to the foreground:
goto run_ui

:run_menu
"%EXE%" menu
set "RC=%errorlevel%"
goto done

:run_ui
"%EXE%" ui %PASS%
set "RC=%errorlevel%"
goto done

:forward
"%EXE%" %PASS%
set "RC=%errorlevel%"
goto done

:no_exe
echo [ops] cannot start: no exe and no toolchain found.
if not defined BG pause
exit /b 1

:build_failed
echo [ops] build FAILED.
if not defined BG pause
exit /b 1

:init_failed
echo [ops] init FAILED.
if not defined BG pause
exit /b 1

:done
if not "%RC%"=="0" (
  echo.
  echo [ops] exited with code %RC%
  if defined BG echo        (details: %APPDATA%\<vendor>\<tool>-ui.log)
  echo.
  if not defined BG pause
)
exit /b %RC%

4.4 八个坑（都是实测踩过的）

坑症状对策
后台 pause 变隐形僵尸进程永远不退出，任务管理器里一堆 cmd每个 pause 都包 if not defined BG
set 放进 ( ) 块变量赋值「没生效」一条一句，块内 %VAR% 在解析期展开
cmd /c 剥引号路径带空格就散架整行走 /s /c ""<launcher>" --bg ..."，且必须用 SysProcAttr.CmdLine；os/exec 默认的 \" 转义 cmd 不认
隐藏窗口 ≠ 无控制台子进程写 stdout 失败CREATE_NO_WINDOW (0x08000000) 是「有控制台、没窗口」
中文横幅乱码窗口里全是「鏈湴」开头 chcp 65001 >nul；.cmd 正文保持 ASCII
.cmd 用 LF 保存个别 Windows 上标签/续行解析异常CRLF 保存；注释用英文
每次双击都重新构建双击后要等几秒只在缺 exe 时构建；要自重建就单独做「退出码 75」那套（见第 8 节）
启动器内联业务参数换台机器要改 .cmd参数只透传，业务参数走配置/清单

5. 后台网页模式

5.1 --background 的职责

它是父进程，只活几百毫秒，做三件事：

  1. 抢单实例锁：已被占 → 读 ui.json，只开浏览器，返回 0；
  2. 没被占 → 立刻释放锁（真正该持有它的是守护里的 ui）；
  3. spawn 隐藏 cmd 重跑启动器（--bg），等 ui.json 被新进程写出，成功返回 0，超时返回非 0。

参数约定（由启动器拼好，不给人手敲）：

<exe> ui --background --launcher <启动器绝对路径> [透传给 ui 的参数...]

5.2 隐藏守护（Windows）

const createNoWindow = 0x08000000 // 有控制台、没窗口

func spawnBackgroundGuard(launcher string, args []string, logPath string) error {
	logFile, err := openRotatedLog(logPath, 512<<10)
	if err != nil {
		return err
	}
	defer logFile.Close()

	// cmd 的 /c 老坑：整行以引号开头会剥掉首尾引号，路径带空格就散架。
	// 官方写法 /s /c 再整体包一层引号；整行必须走 CmdLine。
	line := `/s /c ""` + launcher + `" --bg`
	for _, a := range args {
		line += " " + quoteArg(a)
	}
	line += `"`

	c := exec.Command("cmd.exe")
	c.SysProcAttr = &syscall.SysProcAttr{
		HideWindow:    true,
		CreationFlags: createNoWindow,
		CmdLine:       line,
	}
	c.Stdout = logFile
	c.Stderr = logFile
	c.Dir = filepath.Dir(launcher)
	return c.Start() // 不 Wait：父进程退得越快，黑窗口闪得越短
}

非 Windows 平台让 --background 明确报错：「Linux/macOS 直接 ui &，或交给 systemd-run」， 不要静默降级成前台。

5.3 单实例

🔴 用内核持有的命名互斥体，不用 tasklist / pid 文件：

  • tasklist 会把「刚起来的短命子进程」也算成「界面在跑」，双击后只打开一个连不上的标签页；
  • pid 文件在进程被强杀后会残留，把工具永久锁死；
  • 互斥体由进程持有，进程退出（哪怕被强杀）自动释放。

🔴 互斥体名必须带配置目录指纹：

func uiSingletonKey(dir string) string {
	sum := sha1.Sum([]byte(strings.ToLower(filepath.Clean(dir))))
	return fmt.Sprintf(`Local\<prefix>-ui-%s`, hex.EncodeToString(sum[:6]))
}

为什么：互斥体是机器级的，而配置目录常被环境变量覆盖（测试 / 多环境）。 用固定名字时，A 目录的界面会把 B 目录的启动挡掉，然后指着 B 目录里根本不存在的 ui.json 让你「删掉再试」——排查起来完全反直觉。

菜单与界面是两个独立的单实例域，用两个不同的名字，互不干扰。

5.4 ui.json：怎么进来

落配置目录，权限 0600（里面是 token）：

{"port": 7789, "token": "…32 字节 hex…"}
  • 每次启动覆写；进程退出后留着，下次启动再覆写（不参与单实例判定）；
  • 第二次双击 / 手工再跑一次 ui，都读它把浏览器指回同一个实例；
  • 🔴 读它时校验 port > 0 && token != ""，残缺内容不能当成「已有实例」， 否则会把浏览器指到一个连不上的地址。

5.5 日志轮转

后台没有窗口，stdout/stderr 只能落文件：

func openRotatedLog(path string, limit int64) (*os.File, error) {
	if st, err := os.Stat(path); err == nil && st.Size() > limit {
		_ = os.Remove(path)
	}
	if err := os.MkdirAll(filepath.Dir(path), 0o700); err != nil {
		return nil, err
	}
	return os.OpenFile(path, os.O_CREATE|os.O_WRONLY|os.O_APPEND, 0o600)
}

超过上限整个重写（不按天/按份切）：这里的内容基本是「又启动了一次」， 留最近一截就够。上限 512 KB 是实测够用的值。

5.6 就绪等待：把「静默失败」变成「可见失败」

🔴 spawn 成功 ≠ 服务起来了。端口被占、配置写不了、二进制崩了，都发生在隐藏窗口里， 父进程如果直接返回 0，用户看到的就是「黑窗口一闪，什么都没发生」。

做法：spawn 前记下 ui.json 的修改时间，spawn 后轮询它被新进程更新且内容完整， 超时（建议 6 秒）就返回非 0。启动器见到非 0 会自动回退前台 ui， 错误就出现在可见窗口里。

before := uiInfoStamp(dir)
if err := spawnGuard(...); err != nil { return 1 }
if err := waitUIReady(dir, before, 6*time.Second); err != nil {
	fmt.Fprintf(os.Stderr, "ERROR: 后台界面没能起来：%v\n", err)
	fmt.Fprintf(os.Stderr, "       详情：%s\n", filepath.Join(dir, logName))
	fmt.Fprintln(os.Stderr, "       下面回退到前台运行，错误会直接显示在这个窗口里。")
	return 1 // .cmd 见到非 0 → 前台 ui
}

6. 端口策略

🔴 默认端口只是「起点」，不是必须抢到的端口：

  • 未显式 --port：从默认端口起试最多 20 个回环端口，被占就递增；
  • 显式 --port：严格绑定，被占直接报错——静默换端口等于没尊重用户的要求；
  • 实际端口写进 ui.json，浏览器地址、Origin 校验、单实例复用全用它。

为什么必须递增：同一台开发机上往往有好几个本地工具，默认端口撞车是常态。 绑死单端口的后果是隐藏窗口里 bind 失败、浏览器永远不开——就是「双击没反应」的真身。

func uiListen(requested int, explicit bool) (net.Listener, int, error) {
	tries := 20
	if explicit {
		tries = 1
	}
	var lastErr error
	for i := 0; i < tries; i++ {
		p := requested + i
		if p < 0 || p > 65535 {
			break
		}
		ln, err := net.Listen("tcp", net.JoinHostPort("127.0.0.1", strconv.Itoa(p)))
		if err == nil {
			return ln, ln.Addr().(*net.TCPAddr).Port, nil // --port 0 也能拿到真实端口
		}
		lastErr = err
	}
	if explicit {
		return nil, 0, fmt.Errorf("监听 127.0.0.1:%d 失败：%v（显式端口被占用，换一个或去掉 --port）", requested, lastErr)
	}
	return nil, 0, fmt.Errorf("从 %d 起连试 %d 个端口都不可用：%w", requested, tries, lastErr)
}

前端 dev 代理要跟着走：vite.config.ts 里 /api 的 target 不要写死， 读环境变量（如 UI_PORT），否则后端递增后 dev 会代理到别的工具上。

7. 配置不全时的降级页

🔴 首次运行绝不能静默退出。init 生成的往往是空配置/空清单，而 ui 启动时 通常会先加载配置——一旦失败就 return 1，在隐藏窗口里就是一次无声失败。

做法：ui 把加载错误记在状态里，照样起服务；页面回一页能照做的说明（503）：

  • 说清「网页面板已启动，但配置还没准备好」；
  • 把原始错误原文放出来（路径、缺哪个键）；
  • 给「按顺序补」的步骤 + 一个「补好了，重新加载」按钮；
  • 每次请求都重读配置：补完刷新即可，不用重启界面（隐藏窗口下没人能去重启）；
  • API 侧同样回 503 + 中文原因，不要回 500（这不是服务坏了，是还差一份配置）。

8. 关闭与重启：只做一半也是对的

能力做法是否建议做
关闭界面页面按钮 → POST /api/shutdown → 进程以 0 退出，守护随之结束✅ 必做。后台窗口是隐藏的，没有它只能去任务管理器杀进程
重启界面（自重建）进程重建自己 → 退出 75 → 启动器把 exe.new 换成正身 → 带 --takeover 重跑（同端口同 token，页面自己重连）◐ 可选。链路长，出错时同样无人看见

做关闭的注意点：先写响应、sleep 300ms 再 os.Exit，否则浏览器拿到的是 「连接被重置」，而它本来该显示「界面已关闭」。前端收到成功响应后要把页面切成 「已关闭，重新双击启动器可再打开」。

不做自重建的理由（如果前端是独立工程，更该这么选）：重建要跑 npm/打包， 链路长、失败面大，而失败发生在隐藏进程里；源码改动让开发者手动 build 一次更诚实。 决定了不做，就写进文档，别让后来的人以为「点了重启会生效」。

9. 安全边界（本地服务不等于安全）

127.0.0.1 不等于安全：你浏览器里任何一个页面都能向 127.0.0.1:<port> 发请求。

层做法
监听只绑 127.0.0.1，不绑 0.0.0.0
token每次启动随机生成（≥16 字节）；地址栏 ?token= 或 #t=，请求头 X-Ops-Token
Origin写操作校验 Origin 必须等于本服务源，否则 403（挡别的网页借浏览器打本机）
Host校验 Host 是 127.0.0.1:<port> / localhost:<port>（挡 DNS rebinding）
静态产物/assets/*、/favicon.ico 不过 token：它们是代码/图标，不含数据；<script src> 带不上自定义头，也拿不到地址栏参数。真正的边界是 API
写操作必须 POST；只接受清单里存在的 id/name，未知值 404，绝不代理任意目标
敏感信息私钥路径、密码、token 不出现在命令行参数、输出、日志里；密码只经 stdin

10. 桌面快捷方式

10.1 唯一实现 + 注入

🔴 创建逻辑只能有一份：CreateShortcutOnDesktop(name) (ShortcutInfo, error)。 命令行（shortcut 动词）与页面按钮（POST /api/shortcut）都调它。 界面自己再拼一遍路径，必然漂移成「命令行建出来能用、界面建出来指向别处」。

界面侧通过 main 注入（见第 3 节），不要反向 import。

10.2 用 PowerShell 建 .lnk

.lnk 是没有公开文档的复合结构，手写等于把「微软哪天改一格」变成自己的 bug； 为一次调用引 COM 库又会给单二进制工具加依赖。用 WScript.Shell 最划算：

$ErrorActionPreference = 'Stop'
$lnk = '<lnk>'
$parent = Split-Path -Parent $lnk
if (-not (Test-Path -LiteralPath $parent)) { New-Item -ItemType Directory -Path $parent -Force | Out-Null }
$wsh = New-Object -ComObject WScript.Shell
$sc = $wsh.CreateShortcut($lnk)
$sc.TargetPath = '<launcher>'
$sc.Arguments = ''
$sc.WorkingDirectory = '<launcher 所在目录>'
$sc.IconLocation = '<ico 路径>,0'
$sc.Description = '<项目名>：双击打开本地运维界面'
$sc.WindowStyle = 7
$sc.Save()

调用：powershell -NoProfile -NonInteractive -ExecutionPolicy Bypass -Command <script>。

细节要求省了会怎样
IconLocation 的 ,0必须带部分 Windows 解析失败，图标空白
WindowStyle = 7最小化启动双击闪一大块黑窗口
Arguments = ''显式置空覆盖旧 .lnk 时残留上一次参数
Test-Path -LiteralPath先建父目录桌面被重定向/不存在时直接失败
单引号转义 ' → ''必须用户名 O'Neil 会把脚本拼断，报的语法错看不出跟名字有关
ErrorActionPreference = 'Stop'必须COM 失败被吞掉，函数却返回成功

10.3 图标：一份字节，两个去处

go:embed <icon>.ico  →  var iconBytes []byte
                        ├─ 网页 /favicon.ico（直接读内存）
                        └─ <配置目录>/<tool>.ico（落盘，.lnk 指这里）

🔴 IconLocation 不能指 exe：Go 编出来的 exe 没嵌 Windows 图标资源，指过去只有空白图标。 🔴 落盘后要补一次 os.Stat 确认写成功，否则 .lnk 会悄悄变成空白图标。

10.4 桌面目录：问系统，不要拼

顺序：测试覆盖变量 → [Environment]::GetFolderPath('Desktop')（会把 OneDrive 重定向算进去） → %USERPROFILE%\Desktop → %OneDrive%\Desktop。

🔴 调 GetFolderPath 前设 [Console]::OutputEncoding = [System.Text.Encoding]::UTF8： 中文用户名下桌面路径是中文，默认 GBK 读回来是乱码，最后建到一条不存在的路径上。

10.5 名字校验与幂等删除

strings.ContainsAny(name, `\/:*?"<>|`) // Windows 非法字符
name == "." || name == ".."            // 相对路径
strings.TrimSpace(name) == ""          // 空名

--remove 对「本来就没有」返回「没删，但不是错误」：重复点两次不该弹红叉。 非 Windows 创建/删除都返回一句人话，不假装写了个文件。

10.6 接口形状

POST /api/shortcut，要 token + Origin，但不受「配置是否齐全」限制 （只碰本机桌面），也不进业务锁（不与别的写操作互斥）。成功回 {path, launcher, icon}，失败回 500 + 原始中文原因（环境问题，不是请求写错）。

11. 前端配套

  • 页面右上角放三个动作：创建桌面快捷方式（低频，default）、检查/刷新（primary）、 关闭界面（default + 二次确认）。
  • 建快捷方式成功后，把完整 .lnk 路径显示在提示里（按钮只有一行字，塞不下 C:\…）。
  • 关闭成功后把整页切成「已关闭」状态，并告诉用户「重新双击启动器可再打开」。
  • 🔴 页面不自己算业务指标：判定与计算在后端，前端只做「状态码 → 文案 + 颜色」。
  • 前端 dev 代理端口要可配（见第 6 节），否则后端端口递增后 dev 会连错服务。

12. 测试与验收

12.1 自动（CI 能跑，不碰真桌面、不起真进程）

用例断言
默认端口被占uiListen(busy, false) 返回的端口 > 被占端口
显式端口被占uiListen(busy, true) 返回错误（不能静默递增）
单实例键不同配置目录 → 不同名字；同目录大小写不同 → 同名字
ui.json 读写残缺内容（缺 token）视为不可用
就绪等待新 ui.json 出现 → nil；不出现 → 超时错误
后台失败等待超时 → backgroundUI 返回非 0（否则启动器不回退）
日志轮转未超限追加、超限重写
参数引用含空格才加引号；空串变 ""
快捷方式接口无 token 401；成功 200 + 三个路径；失败 500 + 原因；配置缺失仍 200；未注入 501
静态产物边界/assets/*、/favicon.ico 无 token 也能取；页面与 API 无 token 401
配置降级配置缺失时页面 503 + 说明页；补好后同一进程刷新即 200

12.2 覆盖变量下的真机核对（不写真桌面）

用 *_CONFIG_DIR / *_DESKTOP_DIR 指向临时目录，然后：

  • 走真实启动器日常分支 → ui.json 生成、/api/servers（或对应只读接口）200；
  • 第二次启动 → 返回 0，只打印「已有界面在跑」；
  • POST /api/shutdown → 200，端口释放；
  • POST /api/shortcut → .lnk 存在、字节魔数 4C 00 00 00， 字节里能搜到启动器路径与图标路径（.lnk 的字符串常是 GBK，搜 GBK 段）；
  • 日志里有完整启动横幅与关闭记录。

12.3 真机人工（Windows，逐条打勾）

  • [ ] 双击 → 浏览器自动打开带 token 的页面，桌面不留黑窗口；
  • [ ] 首次运行（缺 exe / 缺配置）→ 可见窗口里构建/写模板，页面显示「配置还没准备好」；
  • [ ] 删掉 exe 再双击 → 自动构建；工具链不在 PATH 时回退能命中；
  • [ ] 已有实例时再双击 → 不启第二个进程，只把浏览器指回同一个实例；
  • [ ] 默认端口被别的程序占用 → 自动换端口，页面照常打开（横幅会打印实际端口）；
  • [ ] 点「关闭界面」→ 页面显示「已关闭」，进程退出；再双击能重新打开；
  • [ ] 点「创建桌面快捷方式」→ 桌面出现带正确图标的入口，双击它能打开面板；
  • [ ] 桌面被 OneDrive 重定向时，图标仍出现在「真正显示的那个桌面」；
  • [ ] 全程没有改远端、没有提权，日志里没有私钥路径/密码/token；
  • [ ] 🔴 双击后没有触发任何写操作。

14. 故障速查（按症状查）

症状最可能的原因修法
双击完全没反应，日志里有 bind: Only one usage…默认端口被别的工具占了，程序绑死单端口默认端口自动递增（第 6 节）
双击没反应，日志里有 ERROR: 但窗口里看不到失败发生在隐藏窗口，父进程 spawn 成功就返回 0就绪等待 + 超时回退前台（5.6）
双击后黑窗口一闪，什么都没有后台成功 exit 0；失败被 pause 吞了或没有回退失败必须回退前台；pause 包 if not defined BG
A 配置目录的界面挡住 B 目录的启动互斥体用了机器级固定名名字带目录指纹（5.3）
双击后页面白屏 / 503配置不全，ui 启动即退出或页面无数据降级页 + 每次请求重读（第 7 节）
窗口里中文是「鏈湴」GBK 控制台读 UTF-8 输出chcp 65001 >nul
后台进程关不掉没有关闭入口页面按钮 → /api/shutdown → 退出 0
快捷方式图标空白IconLocation 指了 exe / 少了 ,0独立 .ico + ,0
快捷方式指向别处界面自己拼了一遍路径只保留 CreateShortcutOnDesktop 一份实现
别的网页能调本机接口只校验 token，或没校验 Origintoken + Origin + 只允许 POST
改了前端但页面还是旧的产物是编进二进制的，没重新构建先 npm run build 再 go build
双击触发了写操作启动器默认动作是写默认只读，写要显式确认

15. 决策与备选

决策备选为什么选这个
.lnk 指启动器直接指 exe指 exe 绕过构建/配置/单实例，换机器就「双击没反应」
后台交给隐藏 cmdGo 自己当守护Windows 上双击 .cmd 必开控制台；cmd 不持有 exe 句柄，将来换身也不会锁死自己
命名互斥体tasklist / pid 文件内核持有、进程被杀自动释放；另两种会误判或残留
互斥体名带目录指纹全局固定名配置目录可被覆盖，固定名会让多环境互相挡
默认端口自动递增绑死端口 / 一律递增绑死会静默失败；一律递增会让显式 --port 形同虚设
就绪等待 + 回退前台spawn 成功即返回 0隐藏窗口里的失败必须变成可见错误
配置不全也起页面直接退出首次运行/隐藏窗口下退出 = 双击没反应
关闭按钮退出 0只给 --fg / 让用户杀进程后台窗口隐藏，页面必须有停止入口
不做自重建照搬「退出码 75 + .new 换身」链路长、失败面大且无人看见；源码改动手动 build 更诚实
快捷方式实现注入ui 直接 import launcher已有 launcher → ui，反过来成环
静态产物不过 token每个请求都校验<script src> 带不上自定义头，也拿不到地址栏参数；边界在 API

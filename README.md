## 投递策略（2026-10 市场数据）

> 数据来自职友集 2026-10 的招聘统计，样本量有限，**看数量级和趋势，不要当精确值**。

### 城市分层

| 城市 | 定位 | 主力方向 | 每周投递量 |
|---|---|---|---|
| **长沙** | 主战场 | 全栈 + AI 应用 + 前端 | 10~15 |
| 常德 | 本地保底 | 全栈 + 前端（不投 Java / AI） | 3~5 |
| 远程 | 补充 | AI 应用 + 全栈 | 看机会 |

### 为什么长沙是主战场

| 方向 | 长沙在招 | 常德在招 | 差距 |
|---|---|---|---|
| 前端 | **1269** | 4 | ~300 倍 |
| 全栈 | 369 | 个位数 | — |
| Java | 190 | 14 | ~14 倍 |
| AI 应用 | 54 | 基本没有 | — |

常德一个月可能只出两三个匹配岗位，只投本地等于把结果交给运气。

### 长沙的方向优先级

| 优先级 | 方向 | 在招 | 判断依据 |
|---|---|---|---|
| 1 | 全栈 | 369 | 差异化最强，38 岁不是减分项 |
| 2 | **AI 应用** | 54 | 岗位少但**竞争者也少**，薪资上限高（全国 1-3 年 15-30K） |
| 3 | 前端 | 1269 | 做量保底，但年龄敏感、全国岗位在萎缩（纯前端同比 -67%） |
| 4 | Java | 190 | 卡年龄（长沙有岗位明写「32 岁以内」） |

**AI 应用为什么能排第二**：不是因为它岗位多（54 个远少于前端），而是因为敢投的人少。JD 里普遍写着「RAG / Agent 经验」，很多人看到就放弃了；而你有真实的生产级 LLM 落地经验（实时语音链路、结构化输出、多模型路由），只缺 RAG 全链路和 Agent 这两块，补起来 3~4 周。

⚠️ **但 AI 岗位只在长沙有意义**。常德分不到这类岗位，不要投。

### AI 岗的真实缺口（决定投递时机）

| 岗位常问 | 现状 |
|---|---|
| 调 LLM API、流式输出、结构化输出 | ✅ 有生产经验 |
| 多模型适配、成本控制 | ✅ 有 |
| RAG（切分 / rerank / 评估） | ❌ 无（模板检索分支混了同事提交，已剔除） |
| Agent / Function Calling | ❌ 没做过 |

补完 RAG 与 Agent 之后再投「大模型应用」；只投「AI 应用开发」的话现在就能投——但简历上不要写 RAG 和 Agent。

### 薪资：按城市改，不按方向改

| 城市 | 写多少 | 依据 |
|---|---|---|
| 常德 | 8-10K | 本地市场价：前端均值 7.7K，Java 中位 9K |
| 长沙 | **10-13K，或「面议」** | 长沙 62% 的前端岗在 10-20K，写 8-10K 会被怀疑能力或稳定性 |

⚠️ 这是「各版本必须一致」的**唯一例外**：同一份简历投不同城市，薪资本来就该不同。投递前确认简历里写的是哪个版本，**期望城市也要跟着改**。

### 各简历投给谁

| 简历 | 投什么公司 | 避开 |
|---|---|---|
| 全栈开发 | 20~50 人产品公司、软件外包、系统集成商 | 大厂（要专才，不要全栈） |
| 前端开发 | 有专职前端团队的中大公司 | 只招 1 个前端的小作坊（会压价、活杂） |
| Java 后端 | 明确不卡年龄的岗位 | 写「32 岁以内」的（长沙有） |
| AI 应用 | 长沙 / 远程的 AI 团队，**主力之一** | 常德本地；JD 明写要 RAG/Agent 的（补完再投） |
| 大模型应用 | 暂不投 | — |

### 硬规则

1. **同一家公司只投一份**。常德 IT 圈子小，HR 之间大概率认识；投两份会被判定「方向不清」或「海投」
2. 长沙用 10-13K，常德用 8-10K，投递前检查简历里的城市和薪资是否配套
3. 面试被压价时用「全栈能顶两个人」来谈，不要直接降价——降一次，后面每一轮都弱

## 各版本必须一致的内容

改一处就要全改，否则投出去的两份简历会打架：

- 姓名、年龄、电话、邮箱
- 教育经历
- 早期工作经历（旅美美 2020.01-2022.06、深度教育 2014.12-2019.10、简乐 2012.07-2014.12）
- **项目名写法**：`面得过（PassUp）`，中文名在前、英文名作括号补充；首次出现用全称，之后可简称「面得过」
  - 对外文案用驼峰 `PassUp`：一个词，不会被读成英文习语 "pass up"（放弃/错过），PDF 里也不会被断行
  - 代码侧仍用 `pass-up`（仓库目录、`pass-up.backend` / `.ai` / `.frontend` / `.frontend-mp`、镜像名），kebab-case 是通行写法，**不要为了对齐简历去改仓库名**

**例外**：期望薪资与期望城市按投递城市调整（常德 8-10K / 长沙 10-13K），见上方「投递策略」。

## 导出

```bash
npm run build   # 生成 dist/*.html 与 dist/陈桥黎-<方向>.pdf
npm run html    # 只生成 HTML
npm run pdf     # 只生成 PDF（需先有 HTML）
```

- 渲染链路：Markdown → 打印级 HTML（`scripts/build-resume.mjs` 内含 CSS）→ Playwright + 本机 Edge 打印 A4
- 不需要下载 Chromium，用系统已有的 Edge 即可（`--channel msedge`）
- 改样式改 `scripts/build-resume.mjs` 里的 `CSS` 常量，重新 build
- 输出文件名自动是 `陈桥黎-<方向>.pdf`，可直接作为附件投递
- 已验证：5 份均为 2 页，分页点落在段落之间，不会切断列表项

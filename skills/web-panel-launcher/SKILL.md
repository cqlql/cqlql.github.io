# 桌面启动器与本地网页面板

给本机单二进制工具（Go / Rust / Node 打包均可）做「桌面上双击一个图标 → 直接打开本地网页面板」。

## 0. 目标形态与三句红线

三段结构，**形状固定**：

```text
桌面 .lnk  →  仓库根「启动<工具名>.cmd」  →  <exe> <动词>
（只存路径）   （构建 / 配置 / 单实例 / 前后台）   （真正干活）
```

无参双击时，动词是 **`ui --background`**：启动器前台进程几百毫秒内退出，一条**隐藏的** cmd 托管 `ui`，浏览器自动打开带 token 的地址，桌面不留黑窗口。

1. 🔴 **`.lnk` 只指启动器，不指 exe**。指 exe 会绕过构建、配置模板、单实例判断，换台机器必然「双击没反应」，而且现场没有任何提示。
2. 🔴 **双击不执行写操作**。落地页必须只读；唯一的写要人显式点击（还要二次确认）。
3. 🔴 **后台失败必须可见**。隐藏窗口里的失败 = 用户眼里的「双击没反应」，必须在架构上堵死（见 §4「就绪等待」）。

## 1. 适用与不适用

**适用**：本地单二进制工具，已有或想要一个本地 Web 面板，用户不想记命令、不想开终端。

**不适用**（别硬套）：

- 服务端程序。本文全部动作发生在**本机**，不碰远端。
- 需要开机自启 / 托盘常驻 / 安装器的产品。本文明确不做这些（桌面只放一个 `.lnk`）。
- macOS / Linux 的等价物。`.lnk` 与 `WScript.Shell` 是 Windows 专属；其它平台应明确报「请自己建一个指向启动器的入口」，不要假装成功。

## 2. 三层各干一件事

| 层 | 文件 | 职责 | 不能做 |
| :--- | :--- | :--- | :--- |
| 快捷方式 | 桌面 `<名字>.lnk` | `TargetPath` / `WorkingDirectory` / `IconLocation` / `Description` / `WindowStyle` | 不带业务参数、不直接指 exe、不写配置 |
| 启动器 | 仓库根 `启动<工具名>.cmd` | 定位或构建 exe、首次写配置模板、单实例、前后台、日志、参数透传 | 不实现业务逻辑、不判断该跑哪个远端动作 |
| 程序 | `<exe> <动词>` | 真正的命令（`init` / `ui` / `backup deploy` …） | 不关心自己是被双击还是被手敲启动的 |

**为什么启动器放仓库根**：`%~dp0` 天然是仓库根，配置目录、兄弟仓库的相对路径都从这里算；放深一层就得靠 `..` 拼，容易和「向上找启动器」的层级判断打架。

## 3. 代码分层与依赖方向

```text
main.go                       只做命令分发 + 注入
internal/shared/              跨能力共用：配置目录、单实例、共享模型
internal/<能力>/              各能力的实现与 CLI 分发
internal/ui/                  网页面板服务端 + 后台调度
internal/launcher/            桌面快捷方式 + 交互菜单
```

🔴 **依赖方向只许单向**：`main → {能力包, ui, launcher} → shared`。`ui` 与 `launcher` 之间**不能互相 import**。

| 需求 | 错的做法 | 对的做法 |
| :--- | :--- | :--- |
| 界面要调「建快捷方式」 | `ui` import `launcher`（而 `launcher` 已 import `ui` → 成环） | `main` 把函数注给 `ui`：`ui.CmdUI(args, static, createShortcut)` |
| 界面与菜单都要「单实例」 | 各写一份 Windows API 胶水 | 下沉 `shared.AcquireSingleton(name)` |
| 界面要回传快捷方式结果 | 在 `ui` 里再定义一份结构体 | 模型下沉 `shared.ShortcutInfo` |

**注入的签名要窄**：只传函数，不传整个包。

## 4. 启动器契约（`.cmd`）

固定顺序，不能换：

```text
cd /d "%~dp0" + chcp 65001
  → 剥启动器自己的开关（--bg / --fg / --menu），其余留作透传
  → --bg（隐藏守护专用）：直接跑 ui，不构建不 init，所有 pause 都跳过
  → 定位 exe；缺 exe：找工具链（PATH → 常见安装目录回退）→ 构建
  → 缺配置模板：跑 init（首次才占窗口，且不覆盖已有配置）
  → 分流：显式子命令 → 原样转发；--menu → 菜单；首次 / --fg → 前台 ui
  → 日常：<exe> ui --background --launcher "%~f0" [透传参数]
  → 退出码：0 正常；非 0 报错（后台不 pause）；后台启动失败则回退前台
```

| 调用 | 走到哪 |
| :--- | :--- |
| 无参 | `ui --background --launcher "%~f0"` |
| `--port 7790` / `--no-open` 等以 `-` 开头 | 同上，参数透传 |
| `--fg`（可叠加参数） | 前台 `ui`，保留窗口看 stdout |
| `--menu` | 交互菜单（如果项目有） |
| `help` / `list` / `deploy --dry-run` 等显式子命令 | 原样转发 exe，**前台** |
| `--bg` | 内部专用：隐藏守护里的启动器直接跑 `ui` |

🔴 **显式子命令优先于 `--fg`**：`启动X.cmd --fg help` 必须等于 `X.exe help`。判据是「透传串的第一个字符是不是 `-`」。

骨架与 8 个实测坑见 `references/launcher-cmd.md`。

## 5. 后台网页模式

### 5.1 `--background` 只活几百毫秒

1. 抢单实例锁：已被占 → 读 `ui.json`，只开浏览器，返回 0；
2. 没被占 → **立刻释放锁**（真正该持有它的是守护里的 `ui`）；
3. spawn 隐藏 cmd 重跑启动器（`--bg`），等 `ui.json` 被新进程写出，成功返回 0，超时返回非 0。

### 5.2 隐藏守护

Windows 上 `CREATE_NO_WINDOW (0x08000000)` 是「有控制台、没窗口」。整行走 `SysProcAttr.CmdLine`，不要用 `os/exec` 默认的 `\"` 转义（cmd 不认）。

### 5.3 单实例

🔴 **用内核持有的命名互斥体，不用 `tasklist` / pid 文件**：后者会把短命子进程误判成「界面在跑」，或强杀后残留把工具永久锁死。

🔴 **互斥体名必须带配置目录指纹**（配置目录常被环境变量覆盖）：

```go
func uiSingletonKey(dir string) string {
	sum := sha1.Sum([]byte(strings.ToLower(filepath.Clean(dir))))
	return fmt.Sprintf(`Local\<prefix>-ui-%s`, hex.EncodeToString(sum[:6]))
}
```

### 5.4 `ui.json`

落配置目录，权限 `0600`（里面是 token）：`{"port": 7789, "token": "…"}`。

- 每次启动**覆写**，进程退出后留着；不参与单实例判定；
- 读它时校验 `port > 0 && token != ""`，残缺内容不能当成「已有实例」。

### 5.5 日志轮转

后台没有窗口，stdout/stderr 只能落文件。超过上限（512 KB）**整个重写**，不按天/按份切。

### 5.6 就绪等待：把「静默失败」变成「可见失败」

🔴 **`spawn` 成功 ≠ 服务起来了**。端口被占、配置写不了、二进制崩了，都发生在隐藏窗口里。

做法：spawn 前记下 `ui.json` 的修改时间，spawn 后轮询它**被新进程更新且内容完整**，超时（建议 6 秒）返回非 0；启动器见到非 0 自动回退前台 `ui`，错误就出现在可见窗口里。

代码片段见 `references/background.md`。

## 6. 端口策略

🔴 **默认端口只是「起点」，不是必须抢到的端口**：

- 未显式 `--port`：从默认端口起试最多 20 个回环端口，被占就递增；
- 显式 `--port`：严格绑定，被占**直接报错**——静默换端口等于没尊重用户；
- **实际端口**写进 `ui.json`，浏览器地址、Origin 校验、单实例复用全用它。

前端 dev 代理的 target 不要写死，读环境变量，否则后端递增后 dev 会代理到别的工具上。

## 7. 配置不全时的降级页

🔴 **首次运行绝不能静默退出**。

`ui` 把加载错误记在状态里，**照样起服务**；页面回一页能照做的说明（503）：说清「面板已启动但配置没准备好」、放出原始错误（路径、缺哪个键）、给「按顺序补」的步骤 + 「补好了重新加载」按钮，**每次请求都重读配置**。API 侧同样回 503 + 中文原因，不要回 500。

## 8. 关闭与重启

| 能力 | 做法 |
| :--- | :--- |
| 关闭界面 | 页面按钮 → `POST /api/shutdown` → 进程以 **0** 退出。先写响应、`sleep 300ms` 再退出，否则浏览器拿到「连接被重置」 |
| 重启界面 | 独立专题，见 `skills/web-panel-restart/` |

**关闭后前端要切成「已关闭，重新双击启动器可再打开」**。

## 9. 安全边界（本地服务不等于安全）

`127.0.0.1` 不等于安全：浏览器里任何一个页面都能向本机端口发请求。

| 层 | 做法 |
| :--- | :--- |
| 监听 | 只绑 `127.0.0.1`，不绑 `0.0.0.0` |
| token | 每次启动随机生成（≥16 字节）；地址栏 `?token=`，请求头 `X-Ops-Token` |
| Origin | 写操作校验 `Origin` 必须等于本服务源，否则 403 |
| Host | 校验 `Host` 是 `127.0.0.1:<port>` / `localhost:<port>`（挡 DNS rebinding） |
| 静态产物 | `/assets/*`、`/favicon.ico` **不过 token**（代码/图标不含数据，`<script src>` 也带不上自定义头） |
| 写操作 | 必须 `POST`；只接受清单里存在的 id/name，未知值 404 |
| 敏感信息 | 私钥路径、密码、token 不出现在命令行参数、输出、日志里 |

## 10. 桌面快捷方式

🔴 **创建逻辑只能有一份**：命令行（`shortcut` 动词）与页面按钮（`POST /api/shortcut`）都调它。界面自己再拼一遍路径，必然漂移成「命令行建出来能用、界面建出来指向别处」。

用 PowerShell + `WScript.Shell` 建 `.lnk`；`IconLocation` 必须带 `,0`、`WindowStyle = 7`、`Arguments = ''`。Go 编出来的 exe 没嵌图标资源，`IconLocation` **不能指 exe**。

桌面目录问系统 `[Environment]::GetFolderPath('Desktop')`（会把 OneDrive 重定向算进去），不要自己拼。细节见 `references/shortcut.md`。

## 11. 验收

**自动（CI 能跑）**：默认端口被占 → 自动递增；显式端口被占 → 报错；不同配置目录 → 不同单例名；残缺 `ui.json` 视为不可用；就绪等待超时 → 非 0；日志轮转；快捷方式接口无 token 401、配置缺失仍可用。

**真机人工（Windows）**：

- [ ] 双击 → 浏览器自动打开带 token 的页面，桌面**不留**黑窗口；
- [ ] 首次运行（缺 exe / 缺配置）→ 可见窗口里构建/写模板，页面显示「配置还没准备好」；
- [ ] 删掉 exe 再双击 → 自动构建；工具链不在 PATH 时回退能命中；
- [ ] 已有实例时再双击 → 不启第二个进程，只把浏览器指回同一个实例；
- [ ] 默认端口被占 → 自动换端口，页面照常打开；
- [ ] 点「关闭界面」→ 页面显示「已关闭」；再双击能重新打开；
- [ ] 桌面被 OneDrive 重定向时，图标仍出现在真正显示的那个桌面；
- [ ] 🔴 双击后**没有**触发任何写操作。

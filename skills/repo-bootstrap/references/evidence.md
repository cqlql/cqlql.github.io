# 规则成熟度台账

> **这份文件是 repo-bootstrap 的「成长机制」**，不是规范。
>
> 作用：让读到某条规则的 AI 知道 —— **这条被真实项目验证过，还是只是推演**。
> 推演出来的规则不强制执行，可以商量；实测过的规则才有资格写「必须」。
>
> 维护方式见 `SKILL.md` §6 写回协议。

## 一、状态定义

| 状态 | 含义 | 执行方式 |
| :--- | :--- | :--- |
| ✅ **实测** | 至少一个真实仓跑过，有可复核的数据 | 可以写成「必须」 |
| ⚠️ **部分实测** | 跑过，但结论被削弱或有边界条件 | 写成「默认如此」，并注明边界 |
| ❓ **推演** | 没跑过，从原理或单个案例推出来的 | **只作提示，不作强制**；填实例时留空而非编造 |

🔴 **把 ❓ 当 ✅ 写，是这套东西最危险的失败模式**：它会让人以为「已经验证过了」，
从而不再检查。台账里每一条都要能回答「凭什么」。

## 三、怎么用这张表

1. **填实例时**：遇到 ❓ 的条目，**留空并写明「未验证」**，不要照着母本默认值填 —— 那是编造。
2. **写进 AGENTS 时**：❓ 条目不要写成 🔴 红线，写成「默认如此，理由待验证」。
3. **被质疑时**：先查这张表。⚠️ 和 ❓ 的条目，对方有理由说「这条不适用我这仓」。
4. **验证了以后**：改状态 + 补证据 + 写清边界条件（哪个仓、什么改动、什么数字）。

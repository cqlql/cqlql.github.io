## 任务路由（先查这张表，别通读规范）

> 改什么 → 读哪几节 → 验到什么程度 → 交什么证据。
> 表里没列的类型，按 `docs/code-validation.md` §2.1 的三问自己定级，**不要硬套某一行**。

| 改动类型 | 必读（只读这几节） | 验证 | 报告 |
| :--- | :--- | :--- | :--- |
| 文案 / 注释 / 配置值 | 无 | L1 构建或类型检查 | 一行 |
| DTO / 字段映射 / 纯函数 | 无 | L1 | 一行 |
| 一般业务逻辑 / 参数校验 / 新增服务类 | `docs/code-design.md` §二 §七 §八 | L2 相关单测 + 回归 | 一行 |

| 事务 / 幂等 / 消息消费 | `docs/code-design.md` §四 + `docs/sql-orm.md` §5.7 | L3 集成 + 重复请求 + 回滚 | 完整表 |
| SQL / 索引 / 分页 / 批量 | `docs/sql-orm.md` §五 §六 | L2~L3 `EXPLAIN` + 查询次数 | 完整表 |
| 资金 / 权益 / 权限 / 用户数据 | `docs/code-design.md` §四 + `docs/code-validation.md` §四 §六 | L3~L4 真库并发 + 越权用例 | 完整表 |
| 新增目录 / 跨 feature 引用 | 本文件「目录与边界」节 | L1 依赖方向自检 | 一行 |
| 性能优化 / 架构调整 | `docs/code-validation.md` §五（+ §八 运行时） | L4 前后对比 + 回归 | 完整表 |
| 改本文件 / 改 `docs/` | 本文件 §5 文档维护规则 | L1 跑 `check-agents.sh` | 一行 |

**三条使用规则：**

1. **「必读」是下限**：不确定就往上读一档；读完发现用不上就停，不要为了「对齐表格」把整份规范通读一遍。
2. **「报告」决定篇幅**：「一行」就一行 —— 等级 + 命令 + 结果 + 没做什么及原因，不要给 L1 交七行表。
3. **命中两行以上**：等级取最高，必读取并集。

# 12 个实测坑与故障速查

## 1. 十二个坑

| # | 症状 | 根因 | 修法 |
| :--- | :--- | :--- | :--- |
| 1 | 重启后页面一直转圈，最后报「没重启成功」，但服务是新的 | 新进程换了 token，前端轮询 health 一直 401 | `__takeover` 从 `ui.json` 复用 port + token；`GET /api/restart` 先校验凭据可读且与当前一致 |
| 2 | 重启后「服务还在」，其实是旧进程；日志里接手进程只开了个浏览器 | 命名互斥体要等旧进程 `exit` 才由内核释放，而 `WaitPortFree` 只看端口（关监听在 exit 之前），两者差几毫秒 | 接手进程**带重试拿锁**（8s 上界）；拿不到就如实失败，不要走「已有实例 → 只开浏览器」 |
| 3 | 重启成功了，界面却报 `Failed to fetch` | handler 返回前 Flush 退化成 chunked，结束块随进程退出永远发不出去 | 自己序列化 + 显式 `Content-Length` |
| 4 | `'C:\Program' 不是内部或外部命令`，看起来像 go 没装 | 把含空格的 go 路径拼进 `cmd.exe /c` 字符串；加引号也没用（转义规则不同） | `name` 与 `args` 分开传；后端构建直接 exec，只有 `npm.cmd` 走 `cmd.exe /d /c` |
| 5 | 日志写着「新二进制已就位」，正式 exe 却永远是旧的 | `ReplaceBinary(new, target)` 里 `new == target`，`os.Rename` 做了空操作却报成功 | **同路径必须拒绝**；「从哪个文件起来」与「换到哪个文件」分开两个值传 |
| 6 | 第一次「带重建」成功后，第二次不重建的重启报「文件被删了」 | Windows 上 `os.Executable()` 返回**进程映像加载时**的路径：从 `next.exe` 起来、改名成正式 exe 后仍返回 `next.exe` | `TargetExe()` 走按后缀的 `NormalizeExePath`（`.next.exe` → `.exe`）；**按文件名判，不靠探测文件在不在** |
| 7 | 改了脚本 / 前端，重启后跑的还是旧的 | 过期检测只算了 `*.go`，漏掉 embed 输入目录与前端产物 | 白名单含所有 embed 输入 + 前端产物 `index.html` |
| 8 | 「先重建」永远勾着 | 运行态文件（`*.exe~` / `*.log` / `ui.json` / `node_modules`）被算成源码 | 白名单 + prune，运行态文件一律排除 |
| 9 | 交接后服务彻底没了，日志里什么都没有 | detached 进程没有控制台可写，启动失败原因静默丢掉 | `Spawn` 把 stdout/stderr 接日志文件；界面显示路径 |
| 10 | 重启成功两秒后服务又没了 | 新进程共享父进程控制台，关窗口的 `CTRL_CLOSE_EVENT` 把它一起带走 | `DETACHED_PROCESS` + `CREATE_NEW_PROCESS_GROUP` |
| 11 | 影响面文案里出现字面量 `**加粗**` | 文案直接塞进 JSX 当纯文本渲染 | 要强调就换措辞，不写 Markdown |
| 12 | 明明回了 200，浏览器却说响应丢了 | 请求体没读干净就关连接，socket 上残留数据触发 RST | `io.Copy(io.Discard, r.Body)` 再往下走 |

## 2. 故障速查（按症状查）

| 症状 | 最可能的原因 | 先看哪节 |
| :--- | :--- | :--- |
| 页面一直转圈，最后报「没重启成功」，但服务是新的 | 换了 token / `boot_id` 判据写错 | 坑 1、§6 判定函数 |
| 「服务还在」却跑的是旧进程 | 交接失败时旧进程刻意没退；或单例没重试导致接手没起来 | §3 交接链路、坑 2 |
| `Failed to fetch` 但重启其实成了 | chunked 截断报文 | §3、坑 3 |
| `'C:\Program' 不是内部或外部命令` | 把 go 路径拼进 `cmd.exe /c` | §5 命令拼装、坑 4 |
| 日志写「新二进制已就位」，exe 却没换 | `ReplaceBinary` 同路径空操作 | §3、坑 5 |
| 第二次不重建的重启报「文件被删了」 | `os.Executable()` 仍指向 `next.exe` | 坑 6 |
| 「我明明改了，界面怎么没变」 | 漏了 embed 输入 / 忘了勾重建 / 只重编了 Go | §5 过期判据、坑 7 |
| 「先重建」永远勾着 | 运行态文件被算成源码 | §5、坑 8 |
| 重启后服务彻底没了，日志空白 | detached 输出没落盘 | 坑 9 |
| 重启成功两秒后又没了 | 共享控制台，关窗口把新服务带走 | 坑 10 |
| 弹窗里出现字面量 `**加粗**` | 影响面写了 Markdown | §6、坑 11 |
| 按钮点了没反应 | 用了静态 `Modal.confirm` / `message`（拿不到 App 上下文） | §6 |
| 影响面里说「会中断任务」，但任务还是被截断了 | 只在前端提示，服务端没设 409 门 | §4 门 ② |

## 3. 测试矩阵

### 自动（CI 能跑，不真起进程、不碰真配置）

| 测试点 | 断言什么 |
| :--- | :--- |
| `WaitPortFree` | 端口空了立即返回；被占时超时并说清「仍占着」 |
| `ReplaceBinary` | 覆盖目标成功；**同路径拒绝**；产物不存在时给出可记进日志的原因（非致命） |
| `NormalizeExePath` / `TargetExe` | `.next.exe` → `.exe`；正式 exe 原样返回；空路径返回空 |
| `Check`（过期） | 前端源码过期、后端源码过期、embed 输入过期、前端产物比 exe 新；运行态文件**不触发**；产物缺失判为过期 |
| `Rebuild` | 顺序对；前端新鲜时跳过 npm；任一步失败立即停、不继续 go build；源码根缺失时明确拒绝 |
| 确认令牌 | 同实例稳定；换实例 / 换端口后失效 |
| 六道门 | 错 confirm 409、任务在跑 409、凭据读不到 409、重建失败 500 且**不交接/不退出** |
| 交接参数 | 重建过从 `next.exe` 起；不重建从正式 exe 起且 `newExe == "-"`；正式 exe 与「换到哪」是两个值 |
| 响应 | 显式 `Content-Length`；`boot_id` 是重启前的那个 |
| Spawn 失败 | 200 已写出、进程**不退出**、不写第二个响应体 |
| 单例重试 | 前几次拿不到锁最终成功 → 不判失败；一直拿不到 → 如实失败 |
| 前端判定 | `defaultRebuild` / `judgeHandover` 真值表 / 超时文案带日志路径 / 409-500 后刷新视图 |

### 覆盖变量下的真跑（临时配置目录 + 独立端口，不碰真配置、不碰真远端）

1. 起界面：配置目录覆盖变量指到临时目录，显式 `--port` 绑空闲端口，`--no-open`。
2. `GET /api/health` 记下 `before.boot_id`；`GET /api/restart` 核对 `note` 为空、影响面完整、日志路径。
3. **触发过期**：`touch` 一个前端源文件 → 再取视图，应得 `binary_stale=true` 且 `build_command` 列出完整前端构建链。
4. `POST /api/restart` 带 `rebuild=true` → 拿到完整 200（含 `build_output`），不要因为传输层异常就判失败。
5. 轮询 health 直到 `boot_id` 变化；核对正式 exe 的 mtime 变了、`next.exe` 已不在、日志里有「等端口让出来 → 新二进制已就位 → 沿用原令牌」。
6. 再点一次 `rebuild=false`：只换进程、日志里**没有** `ReplaceBinary`，`boot_id` 再次变化。
7. 用错 `confirm` 发一次 → 409，之后 health 仍 200（服务没被动过）。
8. 收尾用项目自己的「关闭界面」停掉验证进程，别留后台进程。

### 真机人工（Windows，逐条打勾）

- [ ] 点「重启」→ 弹窗逐条列出影响面、复选框、构建命令、日志路径。
- [ ] 勾「先重建」→ 页面断连几秒后**自己回来**，不用重新复制地址、不用重新双击启动器。
- [ ] 不勾「先重建」→ 同样能回来，且 exe 的 mtime 不变。
- [ ] 故意让构建失败（临时改坏一个 `.ts`）→ 提示「重建失败、服务照旧在跑」，页面仍在。
- [ ] 长任务在跑时点「重启」→ 被拒绝并说明原因。
- [ ] 无头浏览器截图核对布局，确认按钮不是 disabled。

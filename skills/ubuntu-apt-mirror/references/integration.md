# 接进网页面板

## 1. 接口形状（只读同步、写动作异步）

| 接口 | 语义 | 要点 |
| :--- | :--- | :--- |
| `GET /api/apt/status` | 本机源现状 | 只读，几秒内同步返回 |
| `GET /api/apt/probe` | 目标机测速 | 只读；**必须带「在目标机上测」的说明**，否则用户会当成机器固有属性 |
| `GET /api/apt/plan` | 预演 | 生成文本 + 行级差异 + 服务端预演结论 |
| `POST /api/apt/switch` | 写入 | 要 `confirm=yes`；服务端再预演一遍；正在跑就 409 |
| `GET /api/apt/task` | 写入进度 | 任务脱离请求，前端轮询 / 轮询结束给结论 |

候选源只认白名单 id（如 `aliyun` / `tencent` / `huawei` / `ustc` / `tuna` / `official`），**不接受任意 URL**。

## 2. 六道门（少一道就会写出事故）

1. **confirm**：写入必须显式确认，默认按钮不可用。
2. **服务端预演**：`POST` 里不信任前端传来的文本，服务端自己用同一份生成器再算一次，并用 `plan` 跑一遍远端验证。
3. **白名单**：源 id 与 suite 都校验；suite 只来自目标机 `/etc/os-release`。
4. **单任务互斥**：同时只允许一个写入任务，第二次请求 409。
5. **任务脱离请求**：进度写进任务状态，页面关了也能查；不能挂在 HTTP 连接生命周期上。
6. **密码只给 stdin**：远端 sudo 密码只经 stdin 传递，不进命令行参数、不进日志。

## 3. 单一事实来源

换源文本只能有一份实现（本项目是 Go 的 `BuildSnippet`，skill 是 `scripts/snippet.sh`）：

- 界面展示的那段、CLI 打印的那段、远端写入的那段，必须同源；
- 远端脚本只做「验证 / 写 / 还原」，**不在远端再拼第二份**；
- 校验同一组事实（base / suite / components / keyring）也来自同一处。

两处各拼一份的结果是可预期的：界面给你看 A，实际写进去 B，出事时谁也说不清。

## 4. 前端展示

- 测速表：名次、连接、首字节、吞吐、说明 —— **不可达 / 吞吐没测到要显示原因，不留空**。
- 预演：行级差异（`same/add/del`），加一句「这是计划，还没写」。
- 写入：进度条 + 实时日志；结束后明确给 `applied` / `no_change` / 失败原因与备份路径。
- 备份路径要显示出来：出事时人第一件事是找它。

## 5. Go 落地形态（示例，非唯一）

- `internal/apt`：注册表（候选源）、`BuildSnippet`、分节文本解析、远端脚本调用；
- 脚本用 `go:embed` 打进二进制（`deploy/apt/*.sh`），改了脚本**必须重新 build**，否则拿到的是旧内容；
- CLI 动词与界面共用同一套服务端逻辑，别让面板自己拼脚本。

## 6. 被否掉的方案

| 方案 | 为什么不行 |
| :--- | :--- |
| 在控制台 / 本机测速 | 名次是「从办公室出发的网络」，拿去改机房服务器就是错的 |
| 用并发测吞吐 | 所有源平分带宽，名次失真且看不出错 |
| 只校验 HTTP 200 就写 | 地址对不对不等于 apt 能用；签名 / component 缺一样都会在下次 `apt install` 爆 |
| 写完立刻 `apt-get update` | 几十 MB 下载 + 与 apt-daily 抢锁，属于另一件事，得人自己挑时间 |
| 给 22.04 硬写 deb822 | 格式对不上，等于写坏 apt；如实拒绝更安全 |
| 预览令牌跨进程绑定 | 预演与写入是两次请求，令牌只能存在任务状态里，别搞第二套状态机 |
| 前端自己拼 deb822 | 界面所见与实际所写必然分叉 |

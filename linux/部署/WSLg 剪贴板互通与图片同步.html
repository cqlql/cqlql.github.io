WSLg 剪贴板互通与图片同步

WSLg 剪贴板互通：把 Windows 的图片搬进 Linux 剪贴板

文档定位：这是一篇 Linux 运维笔记，含本次完整落地记录。 目标：让 WSL 里的 Linux 应用（Electron 桌面端、终端 TUI 等）能粘贴 Windows 里复制的图片。 记录 WSLg 剪贴板能力边界（只桥接文本、不桥接图片）、X11 与 Wayland 剪贴板互斥、 常驻同步服务落地，以及 RDP 剪贴板通道卡死的诊断与恢复。

配套文档：

  • 《WSL 安装 Linux 子系统》（同目录）—— 子系统安装，本文假设已装好
  • 《WSLg 中文输入法配置》（同目录）—— 复用其 wslg-wait-x.sh 与 .desktop / systemd 用户服务思路
  • 《OpenCode WSL 安装与踩坑记录》（同目录）—— 本文的首个落地对象，那边只留引用
  • 《systemctl》《journalctl》（进程与服务/）—— systemd 用户服务通用写法

环境：Windows 11 + WSL Ubuntu-24.04（systemd 已启用），WSLg，WSL 用户 cql（uid 1000）。

当前状态（2026-10-18，以本机实测为准）：

能力状态
Windows → Linux 图片剪贴板（X11）✅ 自动同步（winclip-sync.service）
终端 TUI / Electron 应用粘贴图片✅ 已验证（[Image 1]）
Windows → Linux 文本剪贴板⚠️ 会方向性失效，见 §6（需 wsl --shutdown）
Linux → Windows（文本）✅ WSLg 原生支持，无需额外配置

1. 结论先行（速查表）

症状根因解法详见
Windows 复制的图片在 WSL 里粘贴不出来WSLg 根本不桥接图片（只桥接文本），且没有开关起一个同步服务把图片塞进 Linux X11 剪贴板§2、§4
图片塞进 X11 了，某些应用还是粘不上原生剪贴板库优先读 Wayland；WSLg 下 X11 与 Wayland 剪贴板互斥让该应用强制走 X11（unset WAYLAND_DISPLAY 或应用自身的 backend 参数）§3、§5
Windows 复制的文本也粘不进 WSLWSLg RDP 剪贴板通道卡死（有未完成的传输请求）wsl --shutdown 重置 WSLg§6

2. 能力边界：WSLg 只桥接文本，不桥接图片

2.1 先确认你在正确的发行版里

⚠️ 前置检查：如果你在 Docker Desktop 的 docker-desktop 发行版里操作，xclip 一定连不上 X （症状见 §9 第一条）。原因是 WSLg 的 socket 按发行版隔离：/mnt/wslg/.X11-unix/X0 属于 最后启动的发行版，/tmp/.X11-unix/ 才是本发行版的（WSLg 会 bind mount 过来）。 docker-desktop 没有 bind mount，/tmp/.X11-unix 不存在，于是 unable to open display ":0" —— 这不代表 WSLg 坏了。用 cat /etc/os-release 确认是 Ubuntu-24.04（要看到 /home/<你>）， 不是 docker-desktop；换回正确发行版执行 wsl -d Ubuntu-24.04。

2.2 实测

在 Windows 里复制一张图，WSL 侧两个剪贴板都读不到 image/png：

# 正常状态：/tmp/.X11-unix/X0 应存在
ls -l /tmp/.X11-unix/X0

# X11（需先装 xclip）
xclip -selection clipboard -o -t TARGETS     # TIMESTAMP TARGETS UTF8_STRING TEXT
# Wayland（需先装 wl-clipboard）
wl-paste --list-types                        # text/plain;charset=utf-8 STRING

结论：WSLg 只桥接文本，图片不支持，且没有配置开关能打开。 所以要粘图片，只能自己在 Linux 侧造一个剪贴板属主（本文方案），或换个思路（把图存文件再用路径）。

3. 更要命的前提：X11 与 Wayland 剪贴板互斥

WSLg 的 Weston 在 X11（XWayland）与 Wayland 之间不是同步两份，而是「谁最后写谁生效，另一个立刻被清空」：

# 只设 Wayland
wl-copy --type image/png < img ; wl-paste --list-types    # image/png
xclip -selection clipboard -o -t TARGETS                  # TIMESTAMP TARGETS UTF8_STRING TEXT
sleep 1
# 再设 X11
xclip -selection clipboard -t image/png -i img
wl-paste --list-types                                     # ← 变空！

反过来也一样（先 X11 再 Wayland → X11 被清成文本）。

这条是所有麻烦的源头：一套同步不可能同时喂饱「只读 Wayland」和「只读 X11」的应用。 必须先确认目标应用读哪个剪贴板，再决定写哪个 —— 本文的统一选择是全部改用 X11。

查某个应用读哪个：看它有没有 WAYLAND_DISPLAY（Electron 可用 GDK_BACKEND=x11 强制）， 或直接 strings <二进制> 看它链接了 xcb_* 还是 wl_data_*（OpenCode CLI 的做法见 《OpenCode WSL 安装与踩坑记录》§4.4）。

4. 落地方案：图片自动同步 + 应用走 X11

整体思路：统一用 X11（应用侧强制 X11，再让剪贴板属主也是 X11 的 xclip）， 用一个常驻服务把 Windows 剪贴板里的图片搬进 X11。

4.1 Windows 侧：监听剪贴板变化

用 GetClipboardSequenceNumber() 轮询（便宜），只在变化时才读图， 有图就存成 PNG 并输出一行 IMG，无图输出 NONE。也兼容「资源管理器复制图片文件」的情形。

C:\Users\cql13\.wsl-clip\watch-clip-image.ps1：

param(
    [string]$Out = "$env:TEMP\wsl-clip.png",
    [int]$IntervalMs = 700
)
$ErrorActionPreference = 'SilentlyContinue'
Add-Type -AssemblyName System.Windows.Forms
Add-Type -AssemblyName System.Drawing
Add-Type -Namespace Win32 -Name Clip -MemberDefinition '[DllImport("user32.dll")] public static extern uint GetClipboardSequenceNumber();'

$lastSeq = [uint32]::MaxValue
$lastHash = ''
while ($true) {
    $seq = [Win32.Clip]::GetClipboardSequenceNumber()
    if ($seq -ne $lastSeq) {
        $lastSeq = $seq
        $img = $null
        try { $img = [System.Windows.Forms.Clipboard]::GetImage() } catch { $img = $null }
        if ($null -eq $img) {
            $files = $null
            try { $files = [System.Windows.Forms.Clipboard]::GetFileDropList() } catch { $files = $null }
            if ($files) {
                foreach ($f in $files) {
                    $ext = [System.IO.Path]::GetExtension($f).ToLower()
                    if (@('.png','.jpg','.jpeg','.gif','.bmp','.webp','.tif','.tiff') -contains $ext) {
                        try { $img = [System.Drawing.Image]::FromFile($f); break } catch { $img = $null }
                    }
                }
            }
        }
        if ($null -ne $img) {
            $ms = New-Object System.IO.MemoryStream
            $img.Save($ms, [System.Drawing.Imaging.ImageFormat]::Png)
            $bytes = $ms.ToArray()
            $img.Dispose()
            $sha = [System.Security.Cryptography.SHA1]::Create()
            $hash = [BitConverter]::ToString($sha.ComputeHash($bytes))
            if ($hash -ne $lastHash) {
                $lastHash = $hash
                [System.IO.File]::WriteAllBytes($Out, $bytes)
                [Console]::Out.WriteLine('IMG')
                [Console]::Out.Flush()
            }
        } else {
            $lastHash = ''
            [Console]::Out.WriteLine('NONE')
            [Console]::Out.Flush()
        }
    }
    Start-Sleep -Milliseconds $IntervalMs
}

⚠️ .ps1 只用 ASCII 注释：Windows PowerShell 5.1 默认按系统 ANSI（中文机器上是 GBK）读脚本， 中文注释会导致 ParserError。踩过，别写中文。 ⚠️ 必须 -STA 启动（剪贴板 API 要求单线程单元），见 §4.2 的 -STA。

4.2 Linux 侧：把图片写进 X11 剪贴板

/usr/local/bin/winclip-sync：

#!/bin/bash
# winclip-sync — 把 Windows 剪贴板的图片同步到 Linux X11 剪贴板
#   * 目标应用需读 X11（Electron 用 GDK_BACKEND=x11，TUI 用 env -u WAYLAND_DISPLAY）
# Windows 剪贴板变为「非图片」时释放属主，让 WSLg 的文本通道恢复。
set -uo pipefail

PS1='C:\Users\cql13\.wsl-clip\watch-clip-image.ps1'
OUT_WIN='C:\Users\cql13\.wsl-clip\auto.png'
OUT_LIN='/mnt/c/Users/cql13/.wsl-clip/auto.png'

export DISPLAY="${DISPLAY:-:0}"

# systemd 环境 PATH 可能不含 Windows 路径，用绝对路径更稳
PWSH=/mnt/c/WINDOWS/System32/WindowsPowerShell/v1.0/powershell.exe
[ -x "$PWSH" ] || PWSH=powershell.exe

owner=0
"$PWSH" -STA -NoProfile -ExecutionPolicy Bypass -File "$PS1" -Out "$OUT_WIN" 2>/dev/null |
while IFS= read -r line; do
    line="${line%$'\r'}"   # PowerShell 输出 CRLF，去掉行尾 \r
    case "$line" in
        IMG)
            for _ in $(seq 1 30); do
                [ -s "$OUT_LIN" ] && break
                sleep 0.1
            done
            [ -s "$OUT_LIN" ] || continue
            pkill -x xclip 2>/dev/null
            xclip -selection clipboard -t image/png -i "$OUT_LIN" 2>/dev/null &
            owner=1
            ;;
        NONE)
            if [ "$owner" = 1 ]; then
                pkill -x xclip 2>/dev/null
                owner=0
            fi
            ;;
    esac
done

⚠️ line="${line%$'\r'}" 这句不能省：PowerShell 输出是 \r\n， bash 的 read 只去 \n，留下的 \r 会让 case "$line" in IMG) 静默不匹配（踩过）。

4.3 常驻服务

~/.config/systemd/user/winclip-sync.service：

[Unit]
Description=Windows clipboard image to X11 clipboard sync (WSLg)
After=graphical-session.target

[Service]
Type=simple
Environment=DISPLAY=:0
Environment=WAYLAND_DISPLAY=wayland-0
Environment=XDG_RUNTIME_DIR=/run/user/1000
Environment=PATH=/usr/local/bin:/usr/bin:/bin
ExecStartPre=/usr/local/bin/wslg-wait-x.sh
ExecStart=/usr/local/bin/winclip-sync
Restart=always
RestartSec=3

[Install]
WantedBy=default.target
chmod +x /usr/local/bin/winclip-sync
systemctl --user daemon-reload
systemctl --user enable --now winclip-sync.service

wslg-wait-x.sh 来自《WSLg 中文输入法配置》（等 XWayland socket 就绪），没有它服务会在 graphical-session.target 之前抢跑，xclip 连不上 :0。

4.4 手工兜底：winimg

不想等自动同步时，可手动搬一次（同样写 X11）：

#!/bin/bash
# /usr/local/bin/winimg —— 手动把 Windows 剪贴板图片放进 Linux X11 剪贴板
PS1='C:\Users\cql13\.wsl-clip\get-clip-image.ps1'
OUT_WIN='C:\Users\cql13\.wsl-clip\clip.png'
OUT_LIN='/mnt/c/Users/cql13/.wsl-clip/clip.png'
export DISPLAY="${DISPLAY:-:0}"
err=$(/mnt/c/WINDOWS/System32/WindowsPowerShell/v1.0/powershell.exe -STA -NoProfile \
  -ExecutionPolicy Bypass -File "$PS1" -Out "$OUT_WIN" 2>&1 >/dev/null) || {
    echo "❌ 读取失败: $err" >&2; exit 1; }
for _ in $(seq 1 30); do [ -s "$OUT_LIN" ] && break; sleep 0.1; done
xclip -selection clipboard -t image/png -i "$OUT_LIN" && echo "✅ 已放入 Linux 剪贴板，去应用里 Ctrl+V"

配套 get-clip-image.ps1 逻辑与 §4.1 相同，只是单次执行、有图就保存并打印路径、无图 exit 2。

5. 应用侧要配合：强制走 X11

同步服务只保证「X11 里有图」，应用读不读 X11 是应用自己的事。两种典型改法：

应用类型改法
Electron（GTK 后端）启动项 / 启动脚本里加 GDK_BACKEND=x11（配合 --disable-gpu 见《OpenCode WSL 安装与踩坑记录》§3）
终端 TUI（Bun / Node 内嵌原生剪贴板）启动时 env -u WAYLAND_DISPLAY <app>；~/.bashrc 里包一个同名函数最省事

终端 TUI 的包装函数形态：

# ---- <app> CLI 剪贴板（WSLg）----
# WSLg 下 Wayland 与 X11 剪贴板互斥；winclip-sync 把图片放进 X11。
# 该 app 原生优先读 Wayland，这里让它改用 X11。
opencode() {
    local bin="$HOME/.opencode/bin/opencode"
    [ -x "$bin" ] || bin="$(type -P opencode)"
    env -u WAYLAND_DISPLAY "$bin" "$@"
}

用函数而不是往 /usr/local/bin 放 wrapper：~/.bashrc 里 export PATH="$HOME/.opencode/bin:$PATH" 会把真实二进制放在最前，wrapper 会被盖住。函数只影响交互式 shell，脚本 / 非交互场景不会套用。

⚠️ 某些 TUI 提供类似 OPENTUI_CLIPBOARD=x11 的环境变量，实测无效（OpenCode 2.0.32）， 别在这上面空转，unset WAYLAND_DISPLAY 才可靠。

6. 坑：WSLg RDP 剪贴板通道卡死（文本方向失效）

现象：Windows 复制文本到 WSL 也读不到（X11 / Wayland 都空），但 Linux → Windows 正常。 看 WSLg 的 weston 日志：

tail -30 /mnt/wslg/weston.log

关键行：

RDP clipboard_data_source_send new (...:published:fd 131) vs prev (...:cancel pending:fd 129):
outstanding RDP data request (client to server)

根因：RDP 剪贴板有一个未完成的传输请求卡住（cancel pending）， 后续 Windows → Linux 的剪贴板传输全部被挡住。这是 WSLg / msrdc 的已知毛病， 常见诱因是传输进行到一半时剪贴板属主被强杀（比如频繁 pkill xclip）。

解法：重启 WSLg，即

wsl --shutdown

这也顺带让所有 .desktop 覆盖、以及 systemd 用户服务（fcitx5 / winclip-sync）重新生效。 所以「改了 .desktop / 换了服务」和「剪贴板怪了」用的是同一个动作，记住它就好。

9. 排错速查表

症状排查
xclip 报 Error: Can't open display: :0，或 xdpyinfo 同样报错🔴 先看你在哪个发行版（§2.1）：cat /etc/os-release → 若是 docker-desktop，WSLg socket 不属于它，换回 Ubuntu-24.04。其次看 ls -l /tmp/.X11-unix/X0 是否存在（正常是 bind mount 过来的 socket）
图片粘不进应用xclip -o -t TARGETS 是否有 image/png；systemctl --user status winclip-sync
图片在 X11 里，TUI 仍粘不上是否新开终端（函数已加载？type opencode 应显示 is a function）
图片在 X11 里，Electron 仍粘不上启动项是否带了 GDK_BACKEND=x11
文本也粘不进可能就是 §6 的 RDP 通道卡死 → wsl --shutdown
winclip-sync 没反应journalctl --user -u winclip-sync -f；确认 powershell.exe 绝对路径可执行
IMG 收到了但 xclip 没生效检查 OUT_LIN 是否可读（/mnt/c 跨系统写入有毫秒级延迟，脚本里已 sleep 轮询 3s）

10. 踩坑要点（通用经验，与本文主题强相关）

  1. pkill -f <关键字> 会误杀自己：命令里一旦包含同一关键字，pkill -f 连当前 shell 一起杀 （本次多次「Killed by SIGTERM」就是这么来的）。改用 pkill -x <进程名>，或写括号 'winclip[-]sync' 让自身命令行不匹配（注意：括号技巧要求命令里不要再出现该关键字的字面量）。
  2. PowerShell → bash 的行尾是 \r\n：read 只去 \n，\r 会让 case / 比较静默失败， 记得 line="${line%$'\r'}"。
  3. PowerShell 5.1 按 ANSI 读 .ps1：中文注释会 ParserError，脚本保持纯 ASCII。
  4. systemd 用户服务不继承登录 shell 环境，也不保证含 Windows 路径：需要的变量 / 路径显式写在 Environment= 或脚本里用绝对路径。
  5. WSLg 裁剪很多：不转发输入法、不桥接图片剪贴板、Weston 不支持 Wayland 输入法协议、 X11 / Wayland 剪贴板互斥 —— 遇到「WSL 里行为不对」，先怀疑 WSLg 的能力边界，别在应用层空转。
  6. 🔴 WSLg 的 socket 是「按发行版」而不是「按整机」的：/mnt/wslg/.X11-unix/X0 属于最后启动的 那个发行版，自己的发行版通过 bind mount 拿到 /tmp/.X11-unix/X0。所以在别的发行版 （典型是 Docker Desktop 的 docker-desktop）里跑 xclip / GUI 应用，会 Can't open display: :0， 这不是 WSLg 坏了，也不是配置问题 —— 先 cat /etc/os-release 确认自己在哪个发行版， 再去改配置。同理，systemd 用户服务（winclip-sync）必须在承载 cql 用户环境的发行版里跑。

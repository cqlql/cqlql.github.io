title: 浏览器跨域解决

跨域本质是浏览器的同源策略（协议、域名、端口三者相同才同源）限制。常见解决方案如下。

## 1. CORS（服务端白名单，最常用）

服务端通过响应头声明允许的来源。

### PHP 示例

```php
<?php
header("Access-Control-Allow-Origin: *"); // 允许所有来源
// header("Access-Control-Allow-Origin: https://www.google.com"); // 仅单个来源
```

### Node/Express 示例（多个域名白名单）

`Access-Control-Allow-Origin` 不支持多值，需按请求来源动态返回：

```js
app.all('*', function (req, res, next) {
  const allowList = ['https://www.google.com', 'https://www.baidu.com'];
  if (allowList.includes(req.headers.origin)) {
    res.header('Access-Control-Allow-Origin', req.headers.origin);
    res.header('Access-Control-Allow-Methods', 'POST, GET, OPTIONS');
    res.header('Access-Control-Allow-Headers', 'X-Requested-With, Content-Type');
  }
  next();
});
```

### .NET（IIS）

1. 在 IIS 的「HTTP 响应标头」中直接增加 `Access-Control-Allow-Origin: *`；或
2. 在 `web.config` 中配置：

```xml
<system.webServer>
  <httpProtocol>
    <customHeaders>
      <add name="Access-Control-Allow-Origin" value="*" />
    </customHeaders>
  </httpProtocol>
</system.webServer>
```

3. 或在代码中设置：

```csharp
HttpContext.Current.Response.AddHeader("Access-Control-Allow-Origin", "*");
```

> 带自定义头/非简单方法（PUT/DELETE 等）会触发**预检（OPTIONS）**，服务端需同时允许 `Access-Control-Allow-Methods` 与 `Access-Control-Allow-Headers`。

## 2. 反向代理（开发/生产通用，推荐）

让前端和接口走同一域名，从根源消除跨域。

- 开发环境：webpack/vite 的 `devServer.proxy`（见 `webpack 代理 devServer 问题.md`）。
- 生产环境：Nginx 反向代理，将 `/api` 转发到后端。

## 3. document.domain（仅限同主域）

适用于 `one.web.com` 与 `two.web.com` 这种同主域的子域间通信（含 iframe、ajax）：

```js
document.domain = 'web.com';
```

## 4. JSONP（仅 GET，旧方案）

利用 `<script>` 标签不受同源限制的特性加载跨域 JS。只支持 GET，已被 CORS 取代，新项目不推荐。

## 5. postMessage（跨窗口/iframe 通信）

```js
// 监听
window.addEventListener('message', function (event) {
  if (event.data === 'MessageTypeName') {
    // 建议校验 event.origin
  }
});

// 触发（iframe 内向父页面发送）
window.parent.postMessage('MessageTypeName', '*');
```

参考：<https://developer.mozilla.org/zh-CN/docs/Web/API/Window/postMessage>

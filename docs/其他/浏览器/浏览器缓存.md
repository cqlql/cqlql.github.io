浏览器缓存速查（个人速查向）。

## 现象

- `js` / `css` 文件即使改了，浏览器也可能优先用缓存，导致更新不生效。
- `html` 文件一般每次请求都不使用强缓存（多数由服务器 `Cache-Control` 控制为不缓存或短缓存）。

## 强制刷新

- `Ctrl + F5` / `Cmd + Shift + R`：忽略缓存强制重新请求。
- 开发者工具 → Network → 勾选 `Disable cache`：调试时避免缓存干扰。

## 常见缓存头

| 头 | 说明 |
| --- | --- |
| `Cache-Control: max-age=31536000` | 强缓存，单位秒 |
| `Cache-Control: no-cache` | 走协商缓存（每次问服务器） |
| `Cache-Control: no-store` | 完全不缓存 |
| `ETag` / `Last-Modified` | 协商缓存校验，304 表示未变 |

## 前端构建产物缓存策略（推荐）

- 带 hash 的文件（`app.a1b2c3.js`）：设长缓存 `max-age=1y, immutable`。
- `html` / `index.html`：设 `no-cache`，保证每次拉最新，从而带出新 hash 的 js/css。
- 改了代码但没更新：多半是 html 被强缓存了，清缓存或改 html 的 `Cache-Control`。

> 服务端如何配置见 `gzip 服务端压缩.md`、`浏览器跨域解决.md`。

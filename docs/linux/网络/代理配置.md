# Ubuntu 24.04 代理配置指南

## 一、终端环境变量代理（curl / wget / npm / git 等命令）

### 1. 临时生效（仅当前终端）

```bash
# HTTP/HTTPS 代理
export http_proxy=http://127.0.0.1:7897
export https_proxy=http://127.0.0.1:7897
# SOCKS5 全流量（ssh / 部分工具需要）
export all_proxy=socks5://127.0.0.1:7897
# 大写变量兼容部分程序
export HTTP_PROXY=http://127.0.0.1:7897
export HTTPS_PROXY=http://127.0.0.1:7897
export ALL_PROXY=socks5://127.0.0.1:7897

# 本地 / 局域网 / 容器网络跳过代理
export no_proxy="localhost,127.0.0.1,::1,192.168.0.0/16,172.16.0.0/12,10.0.0.0/8,.cluster.local,.svc"
export NO_PROXY="localhost,127.0.0.1,::1,192.168.0.0/16,172.16.0.0/12,10.0.0.0/8,.cluster.local,.svc"
```

验证：`curl -I https://www.google.com`

取消：

```bash
unset http_proxy https_proxy all_proxy HTTP_PROXY HTTPS_PROXY ALL_PROXY no_proxy NO_PROXY
```

### 2. alias 快速开关（推荐长期用）

把下面加到 `~/.bashrc` 或 `~/.zshrc`：

```bash
# proxy aliases
alias proxyon='export http_proxy=http://127.0.0.1:7897 https_proxy=http://127.0.0.1:7897 all_proxy=socks5://127.0.0.1:7897 HTTP_PROXY=http://127.0.0.1:7897 HTTPS_PROXY=http://127.0.0.1:7897 ALL_PROXY=socks5://127.0.0.1:7897 no_proxy="localhost,127.0.0.1,::1,192.168.0.0/16,172.16.0.0/12,10.0.0.0/8,.cluster.local,.svc" NO_PROXY="localhost,127.0.0.1,::1,192.168.0.0/16,172.16.0.0/12,10.0.0.0/8,.cluster.local,.svc"'
alias proxyoff='unset http_proxy https_proxy all_proxy HTTP_PROXY HTTPS_PROXY ALL_PROXY no_proxy NO_PROXY'
```

生效：`source ~/.bashrc`

使用：

```bash
proxyon   # 开启
proxyoff  # 关闭
```

### 3. 一键开关脚本（跨机器共享 / 版本管理）

alias 适合个人终端快速切换，脚本适合多台机器复用或纳入 dotfiles 管理：

```bash
nano ~/proxy-switch.sh
```

内容：

```bash
#!/bin/bash
PROXY_HTTP="http://127.0.0.1:7897"
PROXY_SOCKS="socks5://127.0.0.1:7897"
NO_PROXY_LIST="localhost,127.0.0.1,::1,192.168.0.0/16,172.16.0.0/12,10.0.0.0/8,.cluster.local,.svc"

if [ "$1" = "on" ]; then
    export http_proxy=$PROXY_HTTP
    export https_proxy=$PROXY_HTTP
    export all_proxy=$PROXY_SOCKS
    export no_proxy=$NO_PROXY_LIST
    export HTTP_PROXY=$PROXY_HTTP
    export HTTPS_PROXY=$PROXY_HTTP
    export ALL_PROXY=$PROXY_SOCKS
    export NO_PROXY=$NO_PROXY_LIST
    echo "✅ 代理已开启"
elif [ "$1" = "off" ]; then
    unset http_proxy https_proxy all_proxy HTTP_PROXY HTTPS_PROXY ALL_PROXY no_proxy NO_PROXY
    echo "❌ 代理已关闭"
else
    echo "用法: source ~/proxy-switch.sh on/off"
fi
```

赋予执行权限：

```bash
chmod +x ~/proxy-switch.sh
```

使用（注意必须用 `source`，否则变量只在子 shell 生效）：

```bash
source ~/proxy-switch.sh on   # 开启
source ~/proxy-switch.sh off  # 关闭
```

### 4. `no_proxy` 的网段写法：CIDR vs 通配符

`no_proxy` / `NO_PROXY` 的网段表示有两种常见写法，核心区别在于**工具兼容性**与**网段覆盖范围**，推荐统一使用 **CIDR 网段表示法**。

**兼容性差异**

- **通配符写法（`192.168.*`, `172.16.*`）：兼容性极差** — Linux 下大多数网络库（`curl`、Go `net/http`、Python `urllib` / `requests` 等）在解析 `no_proxy` 时**不支持 `*` 通配符**，该规则会被直接忽略，导致本应直连的局域网 IP 误走代理。
- **CIDR 掩码写法（`192.168.0.0/16`, `172.16.0.0/12`）：标准且通用** — Docker、Go、Python、较新版本 cURL 等主流工具普遍支持。

**覆盖范围差异（以 `172.16` 为例）**

- `172.16.*` 仅覆盖 `172.16.0.0` ～ `172.16.255.255`，会**漏掉** Docker 默认网桥（如 `172.17.0.1`）、K8s Pod IP 等，导致容器连接误走代理超时。
- `172.16.0.0/12` 覆盖 RFC 1918 私有 B 类完整范围 `172.16.0.0` ～ `172.31.255.255`，包含 Docker、K8s 及所有内网场景。
- CIDR 写法应同时补上 `10.0.0.0/8`，覆盖公司内网 / 云 VPC / VPN 常用 `10.x.x.x` 段。

**推荐写法**

```bash
no_proxy="localhost,127.0.0.1,::1,192.168.0.0/16,172.16.0.0/12,10.0.0.0/8,.cluster.local,.svc"
```

| 对比项   | 通配符 (`192.168.*`)                          | CIDR (`192.168.0.0/16`)        |
| -------- | --------------------------------------------- | ------------------------------ |
| 兼容性   | 差（多数工具不识别）                          | 好（主流工具标准支持）         |
| 172 段   | 仅 `172.16.x.x`（漏掉 Docker `172.17.x.x` 等）| 完整覆盖 `172.16 ~ 31.x.x`     |
| 10 段    | 未包含                                        | 包含 (`10.0.0.0/8`)            |

> 部分老版本工具（如旧 cURL）对 CIDR 支持有限，仅支持域名后缀匹配与具体 IP；新版本优先用 CIDR。

## 二、系统全局代理（所有用户、登录界面、systemd 服务）

```bash
sudo nano /etc/environment
```

添加（**不要加 `export`**，直接键值对）：

```
http_proxy="http://127.0.0.1:7897"
https_proxy="http://127.0.0.1:7897"
all_proxy="socks5://127.0.0.1:7897"
no_proxy="localhost,127.0.0.1,::1,192.168.0.0/16,172.16.0.0/12,10.0.0.0/8,.cluster.local,.svc"
HTTP_PROXY="http://127.0.0.1:7897"
HTTPS_PROXY="http://127.0.0.1:7897"
ALL_PROXY="socks5://127.0.0.1:7897"
NO_PROXY="localhost,127.0.0.1,::1,192.168.0.0/16,172.16.0.0/12,10.0.0.0/8,.cluster.local,.svc"
```

重启系统完整生效。

## 三、APT 软件源代理

APT 不读取环境变量，需单独配置文件：

```bash
sudo nano /etc/apt/apt.conf.d/proxy.conf
```

写入：

```ini
# HTTP / HTTPS 代理
Acquire::http::Proxy "http://127.0.0.1:7897";
Acquire::https::Proxy "http://127.0.0.1:7897";
# SOCKS5 代理（可选，需先 apt install apt-transport-socks）
# Acquire::socks::Proxy "socks5://127.0.0.1:7897";
```

有账号密码：`http://user:pass@127.0.0.1:7897`

删除：`sudo rm /etc/apt/apt.conf.d/proxy.conf`

## 四、Git 代理

**临时单次克隆**

```bash
git -c http.proxy=http://127.0.0.1:7897 clone https://github.com/xxx.git
```

**全局永久**

```bash
git config --global http.proxy http://127.0.0.1:7897
git config --global https.proxy http://127.0.0.1:7897
# 或 SOCKS5
git config --global http.proxy socks5://127.0.0.1:7897
```

取消：

```bash
git config --global --unset http.proxy
git config --global --unset https.proxy
```

## 五、Docker 拉镜像代理

dockerd 是 systemd 服务，环境变量不会自动继承，需单独配置：

```bash
sudo mkdir -p /etc/systemd/system/docker.service.d
sudo nano /etc/systemd/system/docker.service.d/http-proxy.conf
```

写入：

```ini
[Service]
Environment="HTTP_PROXY=http://127.0.0.1:7897"
Environment="HTTPS_PROXY=http://127.0.0.1:7897"
Environment="ALL_PROXY=socks5://127.0.0.1:7897"
Environment="NO_PROXY=localhost,127.0.0.1,192.168.0.0/16,.docker.internal"
```

重载并重启：

```bash
sudo systemctl daemon-reload
sudo systemctl restart docker
```

## 六、Snap / Ubuntu Pro 代理

```bash
# 设置
sudo pro config set global_apt_http_proxy http://127.0.0.1:7897
sudo pro config set global_apt_https_proxy http://127.0.0.1:7897
# 取消
sudo pro config unset http_proxy
sudo pro config unset https_proxy
```

## 常见问题

1. 图形界面设置代理后终端不生效：图形代理只给 GUI 程序，终端需单独配环境变量
2. `apt update` 不走代理：必须配置 `/etc/apt/apt.conf.d/proxy.conf`，环境变量无效
3. `docker pull` 失败：dockerd 是 systemd 服务，要配置 `docker.service.d` 章节
4. 局域网 IP 无法访问：检查 `no_proxy` 是否使用 CIDR 写法（见第一节第 3 小节），避免 `192.168.*` 通配符
5. 代理需要账号密码：格式 `http://用户名:密码@ip:端口`

## 查看磁盘空间（整体）

### 总览：`df`

```bash
# 以人类可读单位（G/M）显示各挂载点使用情况
df -h

# 显示文件系统类型
df -hT

# 仅看某个挂载点（如根分区）
df -h /

# 按 inode 使用量查看（排查“磁盘没满但无法写文件”）
df -i
```

`df` 看的是**整个文件系统**的剩余空间，包含已被删除但仍被进程占用的文件。

### 查看块设备与挂载：`lsblk`

```bash
# 树形展示磁盘、分区、挂载点、大小、UUID
lsblk -o NAME,SIZE,FSTYPE,MOUNTPOINT,UUID
```

## 查看文件夹 / 文件大小

### 目录大小：`du`

```bash
# 查看当前目录总大小
du -sh .

# 查看指定目录大小
du -sh /var/log

# 查看目录下各子项大小并排序（找出“大块头”）
du -sh /var/* | sort -rh | head -n 20

# 查看一级子目录大小（不含更深层级）
du -h --max-depth=1 /var | sort -rh

# 仅统计某类文件（如所有日志）
du -ch /var/log/*.log
```

常用参数：

| 参数 | 作用 |
|------|------|
| `-s` | 仅显示总计（summary） |
| `-h` | 人类可读单位 |
| `--max-depth=N` | 限制递归深度 |
| `-c` | 在末尾追加总计 |
| `--exclude=*.cache` | 排除指定文件 |

### 单文件大小：`ls` / `stat`

```bash
# 人类可读显示
ls -lh /var/log/syslog

# 精确字节数
stat -c %s /var/log/syslog
```

### 按大小查找文件

```bash
# 找出大于 100M 的文件
find / -type f -size +100M -exec ls -lh {} \; 2>/dev/null

# 找出大于 1G 的文件并排序
find / -type f -size +1G -printf '%s %p\n' 2>/dev/null | sort -rn | head
```

### 交互式磁盘分析：`ncdu`

比 `du` 更直观，可进入子目录逐级排查（需安装）：

```bash
# 扫描当前目录，进入后可用方向键浏览、d 删除
ncdu /var
```

## 找出空间“去哪了”

常见排查顺序：

1. 先看 `df -h` 确认是哪个挂载点满了。
2. 用 `du -h --max-depth=1 /挂载点` 定位到具体目录。
3. 逐层 `du` 或 `ncdu` 深入，找到大文件/大目录。
4. 检查是否有被删除但被进程占用的文件（见下文）。

## 磁盘清理

### 1. 清理包管理器缓存

```bash
# apt（Debian/Ubuntu）：删除已下载的 .deb 缓存与不再需要的依赖
sudo apt clean
sudo apt autoremove --purge

# 仅删除过期缓存（更保守）
sudo apt autoclean
```

### 2. 清理日志（journald）

```bash
# 查看 journal 占用
journalctl --disk-usage

# 保留最近 7 天的日志
sudo journalctl --vacuum-time=7d

# 限制日志总大小不超过 500M
sudo journalctl --vacuum-size=500M
```

也可在 `/etc/systemd/journald.conf` 中固定上限：

```ini
SystemMaxUse=500M
SystemKeepFree=1G
```

### 3. 清理 Docker 占用

```bash
# 查看 docker 各项目占用
docker system df

# 删除所有未使用的镜像/容器/网络/构建缓存
docker system prune -a

# 仅删除停止的容器
docker container prune
```

### 4. 清理用户缓存与临时文件

```bash
# 当前用户缓存（浏览器、npm、pip 等）
du -sh ~/.cache
rm -rf ~/.cache/*

# 系统临时目录（注意确认无重要文件）
sudo rm -rf /tmp/*

# 旧内核（Debian/Ubuntu，保留当前正在用的一个）
sudo apt autoremove --purge
```

### 5. 清理大日志文件

```bash
# 截断（不删除文件，避免占用 inode/句柄的服务报错）
sudo truncate -s 0 /var/log/syslog

# 或直接删除（删除后需重启对应服务以重新生成）
sudo rm /var/log/syslog.*
```

## 注意：已删除但被进程占用的文件

有时 `df` 显示磁盘满，但 `du` 找不到对应大文件——通常是**进程仍持有已删除文件的描述符**。

```bash
# 找出这类文件（deleted 状态）
lsof +L1 | grep deleted
# 或聚焦大小
lsof +L1 | awk '$5=="REG" {print $7, $1, $2, $9}' | sort -rn

# 释放方法：重启对应进程，或向其发送清空指令
# 例如清空 nginx 已删除的日志文件句柄
sudo truncate -s 0 /proc/<PID>/fd/<FD>
```

> 直接 `rm` 删除这类文件并不会立即释放磁盘空间，必须让持有它的进程释放或重启。

## 快速定位“谁占了空间”一条龙

```bash
# 1. 哪个挂载点满了
df -h

# 2. 该挂载点下谁最大（以 / 为例）
sudo du -h --max-depth=1 / 2>/dev/null | sort -rh | head

# 3. 是否有被删除但占用空间的文件
sudo lsof +L1 2>/dev/null | grep -i deleted
```

## 磁盘测速

写速度（用 `dd` 写临时文件测顺序写吞吐）：

```bash
dd if=/dev/zero of=test.img bs=1M count=1024 conv=fdatasync status=progress
```

读速度（先写再用已存在文件测顺序读）：

```bash
dd if=test.img of=/dev/null bs=1M count=1024 status=progress
```

测完清理临时文件：

```bash
rm -f test.img
```

> 更专业的随机读写 / IOPS 测试推荐用 `fio`，`dd` 仅反映顺序大块吞吐。

# 微信小程序支付（JSAPI 下单）

基于**微信支付 APIv3 + JSAPI 下单**实现小程序内支付（充值场景）。后端用商户私钥签名下单、接收支付结果通知（验签 + AES-256-GCM 解密），小程序端拿到支付参数后调 `wx.requestPayment` 拉起收银台。

> 项目背景：PassUp 面试助手（Java Spring Boot 后端 + Taro/React 小程序端）。后端代码位于 `infrastructure/integration/wechat/`（支付集成）与 `modules/recharge/`（订单 + 资产发放业务）；小程序端代码位于 `frontend-mp/src/features/recharge/`（service/store/api）与 `pages/recharge/`（礼包购买页）。

------

## 一、整体流程

```
① 小程序端选择礼包 → POST /api/recharge-orders 创建订单
   ↓
② 后端：校验礼包 → 取 openid → 生成订单号/快照 → 调微信 JSAPI 下单
   ↓
③ 微信返回 prepay_id
   ↓
④ 后端用商户私钥二次签名，返回前端调起参数（appId/timeStamp/nonceStr/package/paySign）
   ↓
⑤ 小程序端 wx.requestPayment(payParams) 拉起收银台
   ↓
⑥ 用户完成支付 → 微信异步回调 POST /api/callback/wechat-pay
   ↓
⑦ 后端：验签 → AES-256-GCM 解密 → 更新订单状态 → 发放资产
   ↓
⑧ 返回 {"code":"SUCCESS"} 给微信（否则微信会重复回调）
```

关键点：**下单与回调是两条独立通道**，下单由后端主动调用，回调由微信异步推送，二者通过 `out_trade_no`（商户订单号）关联。

------

## 二、下单流程（后端主动调用）

### 1. 创建订单 + 下单

`RechargeController#createOrder` → `RechargeOrderService#createOrder`：

```java
@Transactional
public CreateOrderResponse createOrder(Long userId, Long packageId) {
    // 1. 校验礼包存在且已上架
    // 2. 取微信 openid（未绑定微信则无法支付）
    String openId = userAuthRepository.findByUserIdAndAuthType(userId, WECHAT_MINIAPP)
            .map(UserAuth::getIdentifier)
            .orElseThrow(() -> new BusinessException("未绑定微信，无法支付"));

    // 3. 生成订单号 + 礼包快照（记录下单时礼包内容，防止后续改价/改内容）
    RechargeOrder order = new RechargeOrder();
    order.setOrderNo(generateOrderNo());           // R + 时间戳 + 4 位随机
    order.setPackageSnapshot(buildSnapshot(pkg));  // JSON 快照
    order.setAmount(pkg.getSalePrice());
    order.setPayStatus("PENDING");
    order.setExpireTime(Instant.now().plus(2, HOURS)); // 2 小时过期
    order = rechargeOrderRepository.save(order);

    // 4. 调微信 JSAPI 下单
    WechatPayParams payParams = wechatPayService.createJsapiOrder(order, openId);
    return CreateOrderResponse.builder()
            .orderNo(orderNo).amount(order.getAmount().toString())
            .payment(payParams).build();
}
```

设计要点：

- **礼包快照**：下单时把礼包内容/价格序列化成 JSON 存进订单，发放资产时按快照发放，避免礼包后续改价/改内容影响历史订单。
- **金额单位**：微信支付金额单位是「分」，`amount.multiply(100).intValue()` 把元转分。

### 2. 调用微信 JSAPI 下单

### 3. 构造前端调起参数（二次签名）

`WechatPayService#buildPaymentParams`：

```java
String appId = miniAppProperties.getAppId();
String timeStamp = String.valueOf(Instant.now().getEpochSecond());
String nonceStr = WXPayUtility.createNonce(32);
String packageValue = "prepay_id=" + prepayId;

// 签名串：appId + 时间戳 + 随机串 + 包信息，用商户私钥 SHA256withRSA 签名
String signMessage = appId + "\n" + timeStamp + "\n" + nonceStr + "\n" + packageValue + "\n";
String paySign = WXPayUtility.sign(signMessage, "SHA256withRSA", getPrivateKey());

return WechatPayParams.builder()
        .appId(appId).timeStamp(timeStamp).nonceStr(nonceStr)
        .packageValue(packageValue).signType("RSA").paySign(paySign).build();
```

> 注意「**两次签名**」：第一次是给微信接口的 `Authorization` 请求头签名（下单用）；第二次是给小程序端 `wx.requestPayment` 的 `paySign`（调起支付用）。二者签名串格式不同，不能混用。

### 4. 小程序端调起

后端返回 `WechatPayParams`（字段与微信小程序 `wx.requestPayment` 参数一一对应），小程序端（Taro）用 `Taro.requestPayment` 调起：

```ts
// features/recharge/service.ts
function requestPayment(orderResult: CreateOrderResult): Promise<any> {
  const p = orderResult.payment;
  return Taro.requestPayment({
    appId: p.appId,
    timeStamp: p.timeStamp,
    nonceStr: p.nonceStr,
    package: p.packageValue,   // 注意：小程序端字段名是 package
    signType: p.signType,      // 'RSA'
    paySign: p.paySign,
  });
}
```

字段对应关系（易错点）：

| 后端 `WechatPayParams` | 小程序 `wx.requestPayment` | 说明 |
| ---------------------- | -------------------------- | ---- |
| `packageValue` | `package` | 字段名不同，值为 `prepay_id=xxx` |
| `timeStamp` | `timeStamp` | 字符串时间戳 |
| `nonceStr` | `nonceStr` | 随机串 |
| `paySign` | `paySign` | 二次签名 |
| `signType` | `signType` | `RSA` |

> **安全提醒**：`appId` 前端无需传入（小程序运行时自带），后端签名时不把 `appId` 算进 `paySign`，但返回它仅供参考。**签名密钥（商户私钥）只存在于后端**，前端只负责透传参数，绝不能接触私钥。

## 三、支付回调（微信异步通知）

### 1. 回调处理流程

`WechatPayCallbackController#handleNotify`：

```java
@PostMapping("/wechat-pay")
public Map<String, String> handleNotify(
        @RequestHeader("Wechatpay-Signature") String signature,
        @RequestHeader("Wechatpay-Nonce") String nonce,
        @RequestHeader("Wechatpay-Timestamp") String timestamp,
        @RequestHeader("Wechatpay-Serial") String serial,
        @RequestBody String body) {

    // 1. 验签 + 解密
    WechatPayNotifyResult result = wechatPayService.decryptNotify(
            signature, nonce, timestamp, serial, body);

    // 2. 支付成功才处理
    if ("SUCCESS".equals(result.getTradeState())) {
        rechargeOrderService.handlePaymentSuccess(
                result.getOutTradeNo(), "WECHAT", result.getTransactionId());

        // 3. 发放资产（失败也不阻塞，补偿任务兜底）
        try {
            RechargeOrder order = rechargeOrderService.getOrderByOrderNo(result.getOutTradeNo());
            rechargeAssetGrantService.grantAssets(order.getId());
        } catch (Exception e) {
            log.error("发放资产失败", e);
        }
    }

    // 必须返回此格式，否则微信会重复通知
    return Map.of("code", "SUCCESS", "message", "成功");
}
```

### 2. 验签 + 解密（核心安全）

`WechatPayService#decryptNotify` 三步走：

```java
// 1. 验签：用微信支付平台公钥验签（SHA256withRSA）
String signMessage = timestamp + "\n" + nonce + "\n" + body + "\n";
boolean verified = WXPayUtility.verify(signMessage, signature, "SHA256withRSA", getPublicKey());

// 2. 解析通知外层（含 resource.ciphertext 密文）
WechatPayNotifyRequest notifyReq = WXPayUtility.fromJson(body, ...);

// 3. AES-256-GCM 解密 resource.ciphertext（key = APIv3 密钥）
String decrypted = WXPayUtility.aesAeadDecrypt(
        apiV3Key.getBytes(),                      // APIv3 密钥
        resource.getAssociatedData().getBytes(),  // 附加数据（AAD）
        resource.getNonce().getBytes(),           // 随机串（nonce）
        Base64.getDecoder().decode(resource.getCiphertext())); // 密文

// 4. 解析解密后的交易数据
WechatPayNotifyResult result = WXPayUtility.fromJson(decrypted, ...);
```

**APIv3 回调安全机制**（区别于旧版 MD5 签名）：

| 机制 | 说明 |
| ---- | ---- |
| 验签 | 用**微信支付平台公钥**（`Wechatpay-Public-Key`）验 `Wechatpay-Signature` 头，防伪造回调 |
| 解密 | `resource.ciphertext` 用 **APIv3 密钥** 做 AES-256-GCM 解密，回调数据不透明、防窃听 |
| 防重放 | 校验 `Wechatpay-Timestamp` 与本地时间差（微信建议 5 分钟内） |

> 关键点：验签用「平台公钥」，解密用「APIv3 密钥」，两者用途不同，不能混淆。商户私钥用于下单签名，平台公钥用于回调验签，APIv3 密钥用于回调解密——三把钥匙各司其职。

### 3. 资产发放 + 幂等

`RechargeAssetGrantService#grantAssets`：

```java
// 1. 校验订单已支付成功
// 2. 解析订单快照
// 3. 原子抢占：markAssetGranted（CAS 更新 assetGranted 标记）
int marked = rechargeOrderRepository.markAssetGranted(orderId);
if (marked == 0) {
    // 已被其他线程发放，跳过（幂等）
    return;
}
// 4. 逐项发放资产
for (item : items) {
    billingService.grantAsset(userId, assetType, amount, RECHARGE, orderNo);
}
```

通过 `markAssetGranted` 的原子更新实现**幂等发放**——即使微信重复回调或补偿任务并发执行，也只会发放一次。

### 4. 补偿机制

发放资产失败时不阻塞回调返回，由**补偿任务**兜底：

```java
public void grantPendingAssets() {
    List<RechargeOrder> orders = rechargeOrderRepository.findUngrantedSuccessOrders();
    for (RechargeOrder order : orders) {
        if (order.getGrantRetryCount() >= maxRetry) { /* 超限人工介入 */ }
        try {
            rechargeAssetGrantService.grantAssets(order.getId());
            rechargeOrderRepository.resetGrantRetryInfo(order.getId());
        } catch (Exception e) {
            recordGrantFailure(order, errorMsg, maxRetry); // 独立事务记录失败
        }
    }
}
```

- 定时扫描「已支付但未发放资产」的订单，补发资产。
- 内置重试上限（`max-retry`），超限升级为 ERROR 日志，需人工处理。
- 失败记录用 `REQUIRES_NEW` 独立事务写入，避免被外层回滚吞掉。

## 四、密钥与配置

### 配置项

`application.yml` 中 `wechat.pay`：

```yaml
wechat:
  pay:
    mch-id: your-mch-id              # 商户号
    api-v3-key: your-api-v3-key      # APIv3 密钥（回调解密用）
    serial-number: your-serial-number # 商户证书序列号（签名用）
    private-key-path:                # 商户私钥 PEM 文件路径（挂载）
    public-key-path:                 # 微信支付平台公钥 PEM 文件路径（验签用）
    notify-url: https://your-domain.com/api/callback/wechat-pay
```

对应 `WechatPayProperties`。

### 三把钥匙的用途总结

| 钥匙 | 来源 | 用途 |
| ---- | ---- | ---- |
| 商户私钥（`private-key-path`） | 商户 API 证书 | ① 下单请求 `Authorization` 签名 ② 调起支付 `paySign` 二次签名 |
| 平台公钥（`public-key-path`） | 微信支付平台 | 回调通知验签 |
| APIv3 密钥（`api-v3-key`） | 商户平台设置的 32 位密钥 | 回调 `resource` 数据 AES-256-GCM 解密 |

> 密钥通过 PEM 文件挂载读取（见 `WXPayUtility#loadPrivateKeyFromPath` / `loadPublicKeyFromPath`），`WechatPayService` 内部用双重检查锁缓存 `PrivateKey` / `PublicKey` 对象，避免每次请求重复解析。

## 五、关键设计点

1. **两次签名**：下单用 `Authorization` 头签名，调起支付用 `paySign` 二次签名，签名串格式不同。
2. **金额用「分」**：微信支付金额单位为分，后端用 `BigDecimal` 计算后 `×100` 转 int，避免浮点误差。
3. **礼包快照**：下单时快照礼包内容与价格，发放资产按快照，防止礼包改价/改内容影响历史订单。
4. **验签 + 解密双保险**：平台公钥验签防伪造回调，APIv3 密钥 AES-256-GCM 解密防窃听。
5. **幂等发放**：`markAssetGranted` 原子更新防重复发放，配合补偿任务保证「支付成功必发资产」。
6. **回调必须返回 SUCCESS**：否则微信会重复推送通知，需靠幂等兜底。
7. **密钥后端持有**：商户私钥/APIv3 密钥绝不下发前端，前端只透传参数。

## 七、小程序端实现（Taro）

小程序端（Taro + React + Zustand）在 `frontend-mp/src/features/recharge/` 下分层：

| 文件 | 职责 |
| ---- | ---- |
| `api.ts` | 封装 HTTP 请求（下单、查单、礼包列表、余额） |
| `service.ts` | 支付业务编排：下单 → 调起 → 轮询查单 |

### 1. 完整支付流程

`service.ts#createRechargeOrder` 是「立即购买」的完整编排，分三步：

```ts
export async function createRechargeOrder(packageId: number) {
  // 1️⃣ 创建订单，获取微信支付参数
  Taro.showLoading({ title: '下单中…', mask: true });
  const body = await createOrder(packageId);          // POST /api/recharge-orders
  const orderResult = body.data;
  useRechargeStore.getState().setOrderNo(orderResult.orderNo);

  // 2️⃣ 调起微信支付
  try {
    await requestPayment(orderResult);                // Taro.requestPayment
  } catch (payErr) {
    if (payErr?.errMsg?.includes('cancel')) {         // 用户取消支付
      return { success: false, message: '已取消支付' };
    }
    return { success: false, message: '支付失败，请重试' };
  }

  // 3️⃣ 轮询查询支付结果
  const payResult = await pollPaymentStatus(orderResult.orderNo);
  if (payResult.success && payResult.data?.assetGranted) {
    Taro.showToast({ title: '充值成功！', icon: 'success' });
    fetchAssetBalance();                              // 刷新资产余额
  }
  return payResult;
}
```

### 2. 轮询查单（以服务端结果为准）

```ts
async function pollPaymentStatus(orderNo: string) {
  const maxRetry = 10;                 // 最多轮询 10 次
  for (let i = 0; i < maxRetry; i++) {
    await sleep(1000);                 // 间隔 1 秒
    try {
      const body = await getOrderStatus(orderNo);     // GET /api/recharge-orders/{orderNo}
      const status = body.data;
      if (status.payStatus === 'SUCCESS' && status.assetGranted) {
        return { success: true, data: status };
      }
      if (status.payStatus === 'EXPIRED') {
        return { success: false, message: '订单已过期' };
      }
    } catch {
      // 网络错误忽略，继续重试
    }
  }
  // 超时兜底提示，避免用户一直等
  Taro.showToast({ title: '支付结果确认中，请稍后查看', icon: 'none' });
  return { success: false, message: '支付结果确认超时' };
}
```

设计要点：

- **`success` 回调 ≠ 支付成功**：`Taro.requestPayment` 的 `success` 仅表示「收银台流程结束、用户点了确定」，真正的支付结果由微信异步回调 + 后端更新订单后，前端**主动查单**确认。所以支付成功后必须轮询查单，以 `payStatus === 'SUCCESS' && assetGranted` 为最终成功标志。
- **`assetGranted` 二次确认**：轮询不仅看支付状态，还要求 `assetGranted === true`（资产已发放），避免「已支付但资产未发放」就提示充值成功。
- **区分取消与失败**：通过 `errMsg.includes('cancel')` 区分「用户主动取消」和「支付失败」，给不同提示。
- **超时兜底**：轮询 10 次仍无结果时，提示「稍后查看」而非卡死或误报成功，配合「我的购买记录」页可随时核对。

### 3. 用户取消与失败处理

```ts
catch (payErr) {
  // 用户取消支付：errMsg 形如 "requestPayment:fail cancel"
  if (payErr?.errMsg?.includes('cancel')) { ... }
  // 其他错误（余额不足、网络异常等）
  else { ... }
}
```

用户取消支付是高频正常场景，不能当作错误弹「失败」；其他异常才提示「支付失败，请重试」。

### 4. 状态管理

`store.ts` 用 Zustand 维护 `orderNo` / `payStatus` / `assetBalance` / `packages` 等状态，供页面与「我的购买记录」复用。支付成功后调用 `fetchAssetBalance()` 刷新余额，触发界面即时更新。

### 5. 注意事项

- **回调接口需放行**：`/api/callback/wechat-pay` 在 `SecurityConfig` 中需放行（无需登录态），微信服务器无法携带业务 token。
- **金额单位换算**：`INTERVIEW_SECONDS` 资产后端返回秒，前端展示时 `Math.round(amount / 60)` 转分钟（见 `pages/recharge/index.tsx#formatBenefitText`）。
- **package 字段名**：后端 `packageValue` 映射到 `Taro.requestPayment` 的 `package`，是唯一一个字段名不一致的项。

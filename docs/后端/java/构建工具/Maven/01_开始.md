## Maven 常用命令

### 1. 基础构建常用命令

这些命令是日常开发中频率最高的，通常遵循 Maven 的标准生命周期。

| **命令**      | **说明**                                 | **适用场景**                                     |
| ------------- | ---------------------------------------- | ------------------------------------------------ |
| `mvn clean`   | 清理项目，删除 `target` 目录。           | 在重新构建前确保环境干净，避免旧类文件干扰。     |
| `mvn compile` | 编译主源代码（`src/main/java`）。        | 仅检查代码是否有语法错误或编译问题。             |
| `mvn test`    | 运行单元测试。                           | 在提交代码前验证功能是否正常。                   |
| `mvn package` | 打包（如生成 `.jar` 或 `.war` 文件）。   | 准备将项目输出为可执行文件。                     |
| `mvn install` | 将打包后的文件安装到**本地仓库**。       | 多个项目协作时，让 A 项目能引用 B 项目的最新版。 |
| `mvn deploy`  | 将最终包上传到**远程私服**（如 Nexus）。 | 发布版本供团队内其他成员或生产环境使用。         |

---

### 2. 组合拳：高效常用指令

在实际操作中，我们很少只运行一个指令，通常会组合使用：

- **`mvn clean install -DskipTests`**

  这是最常用的组合。清理旧文件、重新编译、打包并安装到本地，同时**跳过测试环节**以节省时间。

- **`mvn clean package`**

  纯粹的重新打包。

---

### 3. 依赖管理与排查

当遇到“Jar 包冲突”或“找不到类”时，这些命令是你的救星。

- **`mvn dependency:tree`**

  **神器。** 以树状结构列出所有依赖。帮助你快速定位某个冲突的 Jar 包是从哪个父依赖引入的。

- **`mvn dependency:analyze`**

  分析依赖使用情况。它会告诉你哪些依赖被引用了但没显式声明，哪些声明了但根本没用到。

- **`mvn help:effective-pom`**

  查看最终生效的 POM 文件。当你的项目有复杂的继承关系（Parent POM）时，这个命令可以显示合并后的完整配置。

---

### 4. 项目初始化与常用参数

#### 快速创建项目

- **`mvn archetype:generate`**

  通过骨架（模版）生成项目。执行后会有一系列交互操作让你选择项目类型（Web、Quickstart 等）。

#### 常用可选参数

- **`-U`**：强制更新。例如 `mvn clean install -U`，强制从远程仓库下载最新的 Snapshot 依赖。
- **`-P <profile_id>`**：指定配置环境。例如 `mvn clean package -Pprod` 使用生产环境配置。
- **`-D<name>=<value>`**：设置系统属性。最常见的是 `-Dmaven.test.skip=true`（完全跳过测试编译与运行）。

## mvn package 的执行链条

Maven 实际上会按顺序走完以下这串“流水线”：

1. **validate**：验证项目结构是否正确。
2. **generate-sources**：生成源代码（如果有插件定义）。
3. **process-sources**：处理资源文件。
4. **compile**：将源代码编译为 `.class` 文件。
5. **process-classes**：处理编译后的文件。
6. **generate-test-sources**：生成测试源码。
7. **test-compile**：编译测试代码。
8. **test**：运行单元测试。
9. **package**：最后一步，将编译好的 `.class` 文件和资源打包成 `jar` 或 `war`。

## mvn compile

```
.\mvnw.cmd -q -DskipTests compile
```

- **`.\mvnw.cmd`**：使用项目自带的 Maven 包装器（Wrapper），确保版本一致。
- **`-q`** (--quiet) ：保持清爽，不看琐碎的日志。
- **`-DskipTests`**：不运行测试用例。
- **`compile`**：只执行编译动作。

### `-P` 来控制 Spring 的 Profile

**第一棒 (Maven)**：你运行 `mvn package -Pprod`。

**第二棒 (pom.xml)**：Maven 看到 `-Pprod`，就把配置文件里的占位符 `active: @profile.active@` 替换成 `active: prod`。

**第三棒 (Spring Boot)**：程序启动时，看到配置是 `prod`，于是自动加载了 `application-prod.yml`。

```xml
<profiles>
    <profile>
        <id>dev</id>
        <properties>
            <activatedProperties>dev</activatedProperties>
            <dbName>test_db</dbName>
            <logLevel>DEBUG</logLevel>
        </properties>
    </profile>
    <profile>
        <id>prod</id>
        <properties>
            <profile.active>prod</profile.active>
        </properties>
    </profile>
</profiles>
```

## -D定义环境变量

```
java -Denv=prod -jar app.jar
```

`-Denv=prod` 本质是 **JVM System Property**

等价于：

```
System.getProperty("env")
```
如果你只是想切换环境，Spring 官方推荐用： spring.profiles.active

```
java -jar app.jar --spring.profiles.active=prod
```

### ✅ 方式 1：直接在 application.yml 里用

```
my:
  env: ${env:dev}
```

解释：

- `${env}` → 读取 JVM 参数 `-Denv`
- `:dev` → 如果没传默认 dev

------

### ✅ 方式 2：@Value 读取

```
@Value("${env}")
private String env;
```

------

### ✅ 方式 3：Environment 读取（推荐）

```
@Autowired
private Environment environment;

String env = environment.getProperty("env");
```

# 一个文件中，多个同级类限制条件

## 1. 规则：可以同级，但只能有一个 "Public"

在一个 `.java` 文件中，你可以编写多个类（这些类在代码层面是并列的、同级的），但必须遵守以下核心规则：

- **唯一公开性：** 一个源文件中最多只能有一个 `public` 类。
- **命名一致性：** 如果文件中有一个 `public` 类，那么文件名必须与该类名完全一致。
- **默认访问权限：** 其他同级类不能用 `public` 修饰，它们只能拥有 `package-private`（默认，即不写修饰符）权限。

### 代码示例

```
// 文件名必须叫 Main.java
public class Main { 
    // 公开类
}

class Tool { 
    // 同级类，正确：它是包私有的
}

class Helper { 
    // 又一个同级类，正确
}
```

------

## 2. 为什么要这样设计？（底层逻辑）

Java 编译器（javac）和类加载器（ClassLoader）之所以做出这种限制，主要是为了**提高编译效率**和**代码可维护性**。

### A. 快速定位源码

当编译器在处理大型项目时，如果看到一个类型叫 `com.app.UserManager`，它不需要扫描整个项目的所有文件，直接去对应的包路径下找 `UserManager.java` 即可。这种“一对一”的映射极大提高了查找和链接的速度。

### B. 避免类名冲突

如果允许一个文件里有多个 `public` 类，且文件名随意，那么开发者很难直观地通过文件系统管理代码。限制一个文件一个 `public` 类，强制了物理结构与逻辑结构的高度统一。

### C. 编译产物依然是独立的

这是一个关键点：即便你在一个 `.java` 文件里写了 3 个同级类，编译后依然会生成 3 个独立的 `.class` 文件。

- `Main.java` → `Main.class`
- `Tool.class`
- `Helper.class`

既然最终都是独立的字节码文件，Java 官方更鼓励将复杂的类拆分到独立的文件中。

------

## 3. 常见误区：内部类 vs 同级类

有时候大家会把“同级类”和“内部类”搞混：

| **类型**   | **定义位置**             | **访问权限**                            |
| ---------- | ------------------------ | --------------------------------------- |
| **同级类** | 在类外面定义             | 只能是包私有（非 public）               |
| **内部类** | 在类大括号 `{}` 里面定义 | 可以是 `public`, `private`, `static` 等 |

> **温馨提示：** 在实际开发中，除非是写一些非常简单的辅助类（Helper），否则**不建议**在同一个文件中写多个同级类。这会增加维护成本，让其他同事找代码时感到困惑。

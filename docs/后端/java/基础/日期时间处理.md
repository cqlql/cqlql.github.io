
# 日期时间处理
## 铁律
- **存/传**：一律 `Instant`（UTC）
- **展示**：前端自己转，或后端最后一步转 `ZonedDateTime`

## 常用代码

```java
// 获取当前 UTC
Instant now = Instant.now();

// 比较大小（秒懂）
boolean expired = expireTime.isBefore(Instant.now());

// 加减时间（返回新 Instant）
Instant later = now.plus(2, ChronoUnit.HOURS);

// UTC 字符串解析
Instant.parse("2026-07-06T10:00:00Z");

// 转给前端（毫秒时间戳或标准字符串）
return Instant.now().toEpochMilli();  // 推荐
return Instant.now().toString();      // 带 Z

// UTC → 上海本地时间（展示用）
ZoneId SH = ZoneId.of("Asia/Shanghai");
LocalDateTime local = LocalDateTime.ofInstant(now, SH);

// 本地时间 → UTC（前端传参入库必转）
LocalDateTime input = LocalDateTime.of(2026,7,6,10,0);
Instant instant = ZonedDateTime.of(input, SH).toInstant();
```

## 禁区
- ❌ `new Date()` → 用 `Instant.now()`
- ❌ `SimpleDateFormat` → 线程不安全
- ❌ `LocalDateTime.now()` 存 DB → 不带时区，会乱

## 一句话避坑
> 只要涉及存储、传输、计算，就用 `Instant`；只有给人看的瞬间，才转时区。

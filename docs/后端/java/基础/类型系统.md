# java 类型系统

### 核心特性对比表

| **类型**       | **核心定位** | **主要用途**          | **关键特性**                                       |
| -------------- | ------------ | --------------------- | -------------------------------------------------- |
| **Class**      | 基础模板     | 定义对象的行为和状态  | 支持继承、封装、多态，是最通用的类型。             |
| **Interface**  | 行为契约     | 定义“能做什么”        | 默认方法全公开，支持多继承，解耦调用者与实现者。   |
| **Enum**       | 枚举常量     | 定义一组固定的常量值  | 线程安全，自带单例属性，适合表示状态、类型。       |
| **Annotation** | 元数据       | 为代码提供配置信息    | 不改变逻辑，但能被编译器或框架（如 Spring）读取。  |
| **Record**     | 数据载体     | 纯粹的数据传输（DTO） | **Java 14+**。自动生成 Getter、equals、hashcode。  |
| **Sealed**     | 层次控制     | 限制哪些类可以继承它  | **Java 15+**。精确控制继承树，增强模式匹配安全性。 |

------

### 详细解析

#### 1. Class vs Interface (传统双雄)

- **Class**: 是实体的“本体”。它不仅规定了数据（Field），还实现了逻辑（Method）。
- **Interface**: 是“接口标准”。它让不同的类可以拥有相同的行为外观。现代 Java 中，接口也可以通过 `default` 关键字写逻辑，但它依然不能存储“状态”（实例变量）。

#### 2. Enum (常量集合)

当你需要表示“星期几”、“订单状态”或“用户角色”时，`Enum` 是唯一选择。它比普通的 `static final int` 更安全，因为它是强类型的。

#### 3. Record (简洁的数据模型)

如果你写过很多只有字段、构造函数、Getter 和 `toString()` 的类（比如 POJO），`Record` 就是你的救星。

- **传统写法**：可能需要 50 行代码。
- **Record 写法**：`public record User(String name, int age) {}` 一行搞定。
- **注意**：Record 是**不可变（Immutable）**的，字段默认是 `final`。

#### 4. Annotation (代码的“贴纸”)

它们本身不执行任何操作。它们的威力在于**被读取**。例如 `@Override` 告诉编译器检查检查重写，`@Test` 告诉 JUnit 运行这个方法。

#### 5. Sealed (被封印的继承)

在 `Sealed` 出现之前，类要么是 `final`（不准继承），要么是公开的（谁都能继承）。

`Sealed` 允许你开启“VIP 继承制”：

> ```
> public sealed class Shape permits Circle, Square { ... }
> ```
>
> 这意味着除了圆和方块，没人能自称是“形状”。这在复杂的业务逻辑建模中非常有用，能防止逻辑外溢。

------

### 总结建议

- **存数据且不需要改？** 用 `Record`。
- **定义一组固定选项？** 用 `Enum`。
- **描述一个物体的本质？** 用 `Class`。
- **定义跨多个类的行为？** 用 `Interface`。
- **想限制继承范围？** 给你的 Class 或 Interface 加上 `Sealed`。

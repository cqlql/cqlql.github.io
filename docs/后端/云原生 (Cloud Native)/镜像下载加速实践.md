## 方案概述

在内网环境中，通过自建 Registry 代理（Pull-Through Cache）来解决 Docker Hub / ghcr.io 等公共镜像仓库的下载速度问题。

整体思路：

- **私有 Registry**（`5000` 端口）：用于推送自定义镜像。
- **Registry Proxy**（`5001` 端口）：代理 `docker.io`，缓存 Docker Hub 镜像。
- **Registry Proxy**（`5002` 端口）：代理 `ghcr.io`，缓存 GitHub Container Registry 镜像。

## docker-compose 部署 Registry

```yaml
services:
  # 私有镜像仓库，用于自己 push 镜像
  registry:
    image: registry:3.1
    container_name: registry
    restart: unless-stopped
    ports:
      - "5000:5000"
    volumes:
      - registry_data:/var/lib/registry
    environment:
      REGISTRY_STORAGE_DELETE_ENABLED: "true"
      REGISTRY_HTTP_HEADERS_Access-Control-Allow-Origin: '[http://localhost:5080]'
      REGISTRY_HTTP_HEADERS_Access-Control-Allow-Methods: '[HEAD,GET,OPTIONS,DELETE]'
      REGISTRY_HTTP_HEADERS_Access-Control-Allow-Credentials: '[true]'
      REGISTRY_HTTP_HEADERS_Access-Control-Allow-Headers: '[Authorization,Accept,Cache-Control]'
      REGISTRY_HTTP_HEADERS_Access-Control-Expose-Headers: '[Docker-Content-Digest]'

  # Docker Hub 代理缓存，加速 docker.io 镜像拉取
  registry-cache:
    image: registry:3.1
    container_name: registry-cache
    restart: unless-stopped
    ports:
      - "5001:5000"
    volumes:
      - registry_cache_data:/var/lib/registry
    environment:
      REGISTRY_PROXY_REMOTEURL: "https://registry-1.docker.io"
      REGISTRY_PROXY_USERNAME: ${REGISTRY_PROXY_USERNAME:-}
      REGISTRY_PROXY_PASSWORD: ${REGISTRY_PROXY_PASSWORD:-}
      REGISTRY_STORAGE_DELETE_ENABLED: "true"

  # GitHub Container Registry 代理缓存，加速 ghcr.io 镜像拉取
  registry-cache-ghcr:
    image: registry:3.1
    container_name: registry-cache-ghcr
    restart: unless-stopped
    ports:
      - "5002:5000"
    volumes:
      - registry_cache_ghcr:/var/lib/registry
    environment:
      REGISTRY_PROXY_REMOTEURL: "https://ghcr.io"
      REGISTRY_STORAGE_DELETE_ENABLED: "true"

volumes:
  registry_data:
  registry_cache_data:
  registry_cache_ghcr:
```

### 关键环境变量说明

| 变量 | 说明 |
| --- | --- |
| `REGISTRY_PROXY_REMOTEURL` | 上游仓库地址，Registry 会自动代理并缓存拉取的镜像 |
| `REGISTRY_PROXY_USERNAME` / `REGISTRY_PROXY_PASSWORD` | Docker Hub 登录凭据（可选，用于突破匿名拉取限流） |
| `REGISTRY_STORAGE_DELETE_ENABLED` | 允许通过 API 删除镜像 |

> 通过 `.env` 文件或环境变量传入 `REGISTRY_PROXY_USERNAME` / `REGISTRY_PROXY_PASSWORD`，可避免 Docker Hub 匿名拉取速率限制（6h/100 次）。

## K3s 配置镜像加速

K3s 使用 containerd 作为容器运行时，镜像加速通过 `/etc/rancher/k3s/registries.yaml` 配置。

### 编辑配置文件

```bash
sudo nano /etc/rancher/k3s/registries.yaml
```

### 完整配置示例

```yaml
mirrors:
  # ================= 场景 A：公共镜像加速 =================
  "docker.io":
    endpoint:
      - "http://192.168.1.221:5001"  # Docker Hub 代理缓存
  "ghcr.io":
    endpoint:
      - "http://192.168.1.221:5002"  # GitHub Container Registry 代理缓存
  # ================= 场景 B：拉取自己的私有镜像 =================
  "192.168.1.221:5000":
    endpoint:
      - "http://192.168.1.221:5000"  # 私有镜像仓库（非代理模式）

# 如果私有镜像库需要跳过 TLS 检查或配置 Auth 账号密码，在 configs 下补充配置：
configs:
  "192.168.1.221:5000":
    tls:
      insecure_skip_verify: true
    # auth:
    #   username: "your_username"
    #   password: "your_password"
```

### 重启 K3s 使配置生效

```bash
sudo systemctl restart k3s
```

### 验证配置

```bash
# 拉取镜像测试（会通过 registry-cache 代理）
sudo k3s ctr image pull docker.io/library/nginx:alpine

# 查看 K3s containerd 中的镜像列表
sudo k3s ctr image ls
```

## 拉取流程

配置完成后，镜像拉取流程如下：

```text
K3s (containerd)
    │
    ▼
registries.yaml → mirrors."docker.io" → http://192.168.1.221:5001
    │
    ▼
registry-cache 容器
    │
    ├─ 本地有缓存 → 直接返回
    └─ 本地无缓存 → 代理拉取 https://registry-1.docker.io → 缓存并返回
```

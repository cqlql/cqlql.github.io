> 打污点后如果其他服务器挂了，业务 Pod 会到打污点的服务器这里来吗？
> **默认不会自动跑过去；只有 Pod 配置了对应的 toleration（容忍），才允许调度到带污点节点。** 污点不会因为其他节点宕机就自动放宽规则。

## 一、两个概念

1. **Taint（节点污点）**：打在节点上，相当于节点声明「除非 Pod 能容忍我这个污点，否则不要把 Pod 调度到我这」。
2. **Toleration（Pod 容忍）**：写在 Pod / Deployment 里，告诉调度器「我可以接受这个污点，允许调度上去」。

> 污点**不会自动失效**，别的节点挂了也不会临时取消污点。

## 二、三种 effect

| effect | 行为 | 适用 |
| --- | --- | --- |
| `NoSchedule` | 新 Pod 不能调度上来，**已在节点上运行的 Pod 不受影响** | 最常用（硬隔离） |
| `PreferNoSchedule` | 软限制：尽量不调度，**实在没地方放就允许调度** | 「尽量不去弱机，迫不得已才去」的兜底场景 |
| `NoExecute` | 不仅不调度，还会**驱逐已经跑在该节点上的 Pod** | 慎用 |

## 三、场景分析：强节点全挂，业务 Pod 会去弱节点吗？

假设：node-low（弱节点）打污点 `node-type=low:NoSchedule`；node1/node2（高性能节点）正常；业务 Deployment **没有写 toleration**。

### 场景 1：强节点全部挂掉，业务 Pod 没有 toleration
调度器尝试新建 Pod，发现所有正常节点不可用、弱节点有污点、Pod 无容忍 → **Pod 会 Pending，不会调度到弱节点**（事件：`Untolerated taint`）。业务无法自动扩容重建。

### 场景 2：业务 Pod 加了 toleration，但没有 nodeAffinity 限制
```yaml
tolerations:
- key: node-type
  operator: Exists
  effect: NoSchedule
```
- 正常时：优先调度到无污点高性能节点；
- 高性能节点全部故障：调度器会把 Pod 调度到弱污点节点，作为兜底。

⚠️ **坑**：有容忍只是「允许」，不等于「优先去强节点、只有强节点全挂才用弱节点」。只配 toleration 不配亲和，集群正常时也可能把 Pod 调度到弱节点。

> 要实现「正常跑高性能节点，强节点全挂才降级到弱节点」，需要**两个配合**：
> 1. 弱节点：`taint: node-type=low:NoSchedule`
> 2. Pod：toleration（允许兜底调度）+ nodeAffinity 强制优先选择高性能标签节点

### 场景 3（更简单）：用 PreferNoSchedule 实现自动兜底
给弱节点打 `PreferNoSchedule` 污点，**不需要 Pod 写 toleration**（偏好是软约束，不是硬阻挡）：
- 有正常高性能节点：调度器尽量避开弱节点；
- 高性能节点全部不可用：调度器接受偏好失效，把 Pod 调度上来。

## 四、方案对比

| | 方案 A：硬隔离（NoSchedule） | 方案 B：故障兜底（PreferNoSchedule） |
| --- | --- | --- |
| 正常情况 | 业务 Pod 绝对不会跑到弱机 | 调度器优先避开弱节点 |
| 强节点全挂 | Pod Pending，不自动降级，需人工干预（去污点/加容忍） | 自动调度到弱节点兜底 |
| 风险 | 故障时业务不可用，需人工介入 | 不是 100% 保证永远不去弱节点，资源紧张时正常集群也可能调度上去 |
| 推荐 | 绝大多数生产 | 需要自动降级兜底的场景（可搭配 nodeAffinity 压低概率） |

## 五、命令示例

```bash
# 打污点（硬隔离）
kubectl taint nodes node-low node-type=low:NoSchedule

# 打污点（软限制，优先不调度、无节点可用才调度）
kubectl taint nodes node-low node-type=low:PreferNoSchedule

# 删除污点
kubectl taint nodes node-low node-type:PreferNoSchedule-
```

## 六、额外提醒（异构集群大坑）

1. 就算 Pod 兜底跑到弱节点，**流量分发依旧是轮询**——弱节点上拉起的业务 Pod 会和强节点 Pod 均分流量，弱节点容易被打崩。
2. 兜底是**灾难降级**，不是常规容灾；弱节点只适合扛极小流量，不要指望性能持平。

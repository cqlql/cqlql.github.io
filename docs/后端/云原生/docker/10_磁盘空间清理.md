`docker system df` 用于快速诊断 Docker 磁盘占用。下面是一个典型的分析案例。

## 解读 `docker system df`

```plain
TYPE            TOTAL     ACTIVE    SIZE       RECLAIMABLE
Images          46        11        32.3GB     25.46GB (78%)
Containers      11        11        17.18MB    0B
Local Volumes   29        8         193.2GB    191.9GB (99%)
Build Cache     150       0         32.49GB    32.49GB
```

| 字段 | 含义 |
|------|------|
| `TYPE` | 资源类型 |
| `TOTAL` | 总数 |
| `ACTIVE` | 正在被使用的数量 |
| `SIZE` | 磁盘占用 |
| `RECLAIMABLE` | 可回收空间 |

## Volumes（数据卷）—— 最大元凶

```plain
Local Volumes   29        8         193.2GB    191.9GB (99%)
```

- 29 个 volume，只有 8 个被容器使用
- **21 个孤儿 volume**，可回收约 **191GB**

### 孤儿 Volume 的常见来源

**1. Docker Compose 反复部署**

项目名改变后，旧 volume 不会被自动删除：

```bash
# 之前创建了 project_postgres_data
docker compose up -d

# 后来改了项目名，Docker 会创建新 volume，旧的遗留
```

**2. 删除容器时未删除 volume**

```bash
docker rm container  # 不会删除 /var/lib/docker/volumes/xxx
```

只有带 `-v` 才会同步删除：

```bash
docker rm -v container
```

### 查看 Volume 详情

```bash
# 列出每个 volume 的大小和引用数
docker system df -v
```

输出示例：

```plain
Local Volumes space usage:
VOLUME NAME            LINKS     SIZE
postgres_data          1         120GB
minio_data             1         50GB
old_project_data       0         20GB   ← LINKS=0，无容器使用
```

> **`LINKS = 0` 表示没有容器挂载该 volume，可安全清理。**

### 安全清理无用 Volume

```bash
docker volume prune
```

会提示确认：

```plain
WARNING! This will remove all local volumes not used by at least one container.
Are you sure you want to continue? [y/N]
```

输入 `y` 确认。

### 清理前确认重要 Volume

执行清理前，先列出当前 volume 确保不误删：

```bash
docker volume ls
```

检查某个 volume 是否被容器使用：

```bash
docker volume inspect postgres_data
docker ps --filter volume=postgres_data
```

> **PostgreSQL、MinIO、Redis 等有状态服务的 volume 不要删除。**

## Build Cache（构建缓存）

```plain
Build Cache     150       0         32.49GB    32.49GB
```

全部可回收。

### 清理命令

```bash
# 删除未使用的构建缓存
docker builder prune

# 删除所有构建缓存（更彻底）
docker builder prune -a
```

| 命令 | 效果 |
|------|------|
| `docker builder prune` | 删除未被任何构建引用的缓存 |
| `docker builder prune -a` | 删除所有未使用的构建缓存 |

## Images（镜像）

```plain
Images          46        11        32.3GB     25.46GB (78%)
```

- 46 个镜像，只有 11 个被容器使用
- 可回收约 25GB

### 查看与清理

```bash
# 查看所有镜像
docker images

# 清理悬空镜像（<none>:<none>）
docker image prune

# 清理所有未被容器使用的镜像
docker image prune -a
```

> `-a` 会删除没有被任何容器（包括已停止的）使用的镜像，请确认后再执行。

## 推荐的清理顺序

以下按安全程度从高到低排列：

### 第一步：清理孤儿 Volume

```bash
docker volume prune
```

预计释放空间最大，风险较低（只删未被使用的 volume）。

### 第二步：清理构建缓存

```bash
docker builder prune
```

### 第三步：评估是否需要进一步清理

```bash
docker system df
```

如果还不够：

```bash
docker image prune -a
```

## 一键清理（谨慎使用）

```bash
# 清理所有未使用的镜像、容器、网络、构建缓存
docker system prune -a

# 再加上 volume
docker system prune -a --volumes
```

> 这会删除所有未被运行中容器使用的资源。**有状态服务的 volume 也会被删**，生产环境慎用。

## 常见大 Volume 来源

以下服务通常产生大量 volume 数据：

| 服务 | 数据类型 | 预估大小 |
|------|----------|----------|
| Loki | 日志 | 几十 GB |
| Prometheus | TSDB 时序数据 | 几十 GB |
| PostgreSQL | 数据库 | 几 GB ~ 上百 GB |
| MinIO | 对象存储 | 视使用情况 |
| Elasticsearch | 索引数据 | 几十 GB |

## 预防措施

- 删除容器时加 `-v` 参数：`docker rm -v container`
- Docker Compose 停止时加 `-v`：`docker compose down -v`
- 定期执行 `docker system df` 检查磁盘占用

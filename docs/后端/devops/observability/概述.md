# 可观测性概述

可观测性（Observability）是运维体系的核心能力，通过三大支柱实现系统状态的全面感知：

## 三大支柱

| 支柱 | 核心组件 | 用途 |
|---|---|---|
| **指标（Metrics）** | Prometheus + node-exporter + Grafana | 量化系统健康状态，CPU、内存、磁盘、QPS 等 |
| **日志（Logs）** | Loki + Promtail | 聚合与检索应用日志、系统日志 |
| **链路追踪（Traces）** | Tempo / Jaeger | 追踪请求在微服务间的调用链路 |

## 技术选型

本系列笔记采用 **Grafana 全家桶**方案：

- **指标采集**：Prometheus（时序数据库 + 拉取式采集）
- **主机指标暴露**：node-exporter
- **日志采集**：Promtail（轻量级日志采集代理）
- **日志存储与查询**：Loki（类 PromQL 的 LogQL 语法）
- **可视化与告警**：Grafana（统一面板，支持 Prometheus / Loki 多数据源）
- **链路追踪**：Tempo（可选，与 Grafana 深度集成）

## 与传统方案对比

| 维度 | Grafana 全家桶 | ELK（传统方案） |
|---|---|---|
| 日志存储 | Loki（轻量、仅索引标签） | Elasticsearch（全量索引） |
| 资源消耗 | 低，适合中小规模 | 高，内存/磁盘需求大 |
| 运维复杂度 | 简单，Docker Compose 即可 | 复杂，集群调优成本高 |
| 统一体验 | Grafana 统一面板 | Kibana 仅日志，指标需另配 |

## 部署架构概览

```
应用 stdout / 系统指标
        ↓
  Promtail（日志）          node-exporter（主机指标）
        ↓                         ↓
      Loki                    Prometheus
        ↓                         ↓
        └──────→  Grafana  ←──────┘
                    ↑
                  Tempo（链路追踪，可选）
```

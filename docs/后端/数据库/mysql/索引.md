# MySQL 表结构设计：索引设计

#### 1️⃣ 索引的几种定义方式

```
- PRIMARY KEY → 主键索引（聚簇）
- UNIQUE KEY → 唯一索引
- KEY / INDEX → 普通索引
```

------

#### 2️⃣ 索引 ≠ 约束（必记）

```
- PRIMARY / UNIQUE：索引 + 约束
- INDEX：只有索引
- FOREIGN KEY：只有约束（不自动建索引）
```

📌 **这是面试 & 生产踩坑点**

------

#### 3️⃣ 什么时候该建索引（判断规则）

```
- WHERE / JOIN / ORDER BY / GROUP BY 出现的字段
- 区分度高的字段
- 经常作为查询入口的字段
```

------

#### 4️⃣ 不要乱建索引

```
- 低基数字段（sex / status）
- 经常更新的字段
- 索引 ≠ 越多越好
```

------

#### 5️⃣ 组合索引核心规则（重点）

```
- 最左前缀原则
- 等值在前，范围在后
- ORDER BY 顺序要和索引一致
```

------

#### 6️⃣ 常见业务模板（你风格非常适合记这个）

```
【用户表】
- uk_user_username (username)
- idx_user_status (user_id, status)

【树结构】
- idx_parent_id (parent_id)

【时间查询】
- idx_created_at (created_at)
```

## 几种场景

### 1️⃣ 建表时直接定义

```
CREATE TABLE user (
  id BIGINT PRIMARY KEY,
  user_name VARCHAR(50),
  parent_id BIGINT,
  UNIQUE KEY uk_user_username (user_name),
  KEY idx_parent (parent_id)
);
```

------

### 2️⃣ `CREATE INDEX`（事后补索引）

```
CREATE INDEX idx_parent ON user(parent_id);
CREATE UNIQUE INDEX uk_user_username ON user(user_name);
```

📌 **不能用来创建主键**

------

### 3️⃣ `ALTER TABLE`（最常用在生产）

```
ALTER TABLE user ADD INDEX idx_parent (parent_id);
ALTER TABLE user ADD UNIQUE uk_user_username (user_name);
ALTER TABLE user ADD PRIMARY KEY (id);
```

------

### 4️⃣ 组合索引（非常重要）

```
KEY idx_user_status (user_id, status)
```

特点：

- 遵循 **最左前缀原则**
- `(a, b, c)` 可用：
  - `a`
  - `a, b`
  - `a, b, c`
- ❌ 不能直接用 `b`、`c`

------

### 5️⃣ 前缀索引（字符串省空间）

```
KEY idx_email (email(20))
```

- 只对 `VARCHAR / TEXT` 有效
- 减少索引体积
- 唯一索引也可以用（但要保证前缀足够区分）

------

### 6️⃣ 全文索引（`FULLTEXT`）

```
FULLTEXT KEY idx_content (content)
```

- 用于 `MATCH ... AGAINST`
- 适合：
  - 文章
  - 搜索
- InnoDB 5.6+ 支持

------

### 7️⃣ 空间索引（`SPATIAL`）

```
SPATIAL KEY idx_location (point)
```

- GIS / 地理位置
- 一般业务很少用

## 二、服务连续性：高可用方案（HA）

### 核心方案：Patroni（生产级推荐 ⭐）

全自动高可用——实现数据库节点自动故障检测、自动主从切换、自动恢复，无需人工干预，保障业务服务持续可用，有效避免单点故障导致的服务中断。

- 基于分布式一致性（etcd / Consul / ZooKeeper）选主，避免脑裂
- 配合流复制（Streaming Replication）实现一主多从
- 主节点故障时自动提升候选从节点为新主，并引导其余节点重新指向

### k3s / Kubernetes 下的高可用

- 推荐使用 **CloudNativePG Operator**：原生支持 PG 集群的 HA、自动 failover、备份与 PITR，与 k3s 集成度高
- 也可在 k8s 上自建 Patroni + etcd 集群，但运维复杂度高于 Operator 方案

## 三、方案选型总结

| 需求场景 | 推荐方案 | 核心优势 |
| --- | --- | --- |
| 小型项目、数据量小、无需精准恢复 | `pg_dump` 全量备份 | 简单易用、低成本、零复杂度 |
| 生产 / 大库、需时间点恢复 | `pg_basebackup` + WAL 归档（PITR） | 高效备份、精准恢复、数据安全性高 |
| 需杜绝单点故障、保障服务持续可用 | Patroni / CloudNativePG（HA） | 全自动故障转移、服务稳定性强 |

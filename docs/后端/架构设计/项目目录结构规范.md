# 项目目录结构规范

结合 **Docker、PostgreSQL 备份脚本、Makefile** 以及 **Spring Boot 后端**，建议采用**标准 Maven 架构 + 运维部署解耦**的目录组织方式。

这样既能保证 Spring Boot 代码结构清晰（符合领域/分层规范），又能将 Makefile 和运维脚本完美融入版本控制。

## 推荐的项目整体目录结构

```text
my-springboot-project/               # 项目根目录
├── .github/                         # (可选) CI/CD 流程文件 (如 GitHub Actions)
├── deploy/                          # 运维与部署目录 (关键：与业务代码隔离)
│   ├── docker/
│   │   ├── Dockerfile               # Spring Boot 镜像构建文件
│   │   └── docker-compose.yml       # 单机本地/生产容器编排 (包含 App + PG)
│   ├── backup/                      # 备份恢复统一目录（按服务细分，未来可扩 redis 备份）
│   │   ├── postgres/
│   │   │   ├── pg_backup.sh         # PostgreSQL 逻辑备份脚本（落盘 /data/backups/postgres/{daily,weekly,monthly}）
│   │   │   └── pg_restore.sh        # PostgreSQL 恢复脚本（含二次确认）
│   │   ├── minio/
│   │   │   └── minio_backup.sh      # MinIO 对象同步备份脚本（目标 /data/backups/minio/data）
│   │   └── init.sql                 # 数据库初始化 SQL
│   ├── monitoring/                   # 监控体系 (Prometheus + Grafana + Alertmanager)
│   │   ├── prometheus/
│   │   │   ├── prometheus.yml       # Prometheus 主配置 (抓取目标、全局规则)
│   │   │   └── rules/               # 告警/记录规则
│   │   │       ├── infrastructure.yml  # 基础设施类规则 (主机、容器)
│   │   │       ├── database.yml        # 数据库类规则 (PostgreSQL 等)
│   │   │       ├── storage.yml         # 存储类规则 (MinIO 等)
│   │   │       └── application.yml     # 应用类规则 (Spring Boot 指标)
│   │   ├── grafana/
│   │   │   ├── provisioning/        # Grafana 数据源/仪表盘自动预置
│   │   │   └── dashboards/          # 导出的 JSON 仪表盘模板
│   │   ├── alertmanager/
│   │   │   └── alertmanager.yml     # 告警路由、收敛与通知渠道配置
│   │   └── exporters/               # 各类 Exporter 部署清单 (node/mysqld/postgres 等)
│   └── env/
│       ├── .env.example             # 环境变量配置模板
│       └── postgres.env.example     # 数据库环境变量模板
│
├── src/                             # Spring Boot 源码目录
│   ├── main/
│   │   ├── java/com/example/project/
│   │   │   ├── common/              # 通用工具类、全局异常拦截、常量、枚举
│   │   │   │   ├── exception/
│   │   │   │   └── result/
│   │   │   ├── config/              # Spring 配置类 (Security, Redis, Swagger 等)
│   │   │   └── modules/             # 按业务模块划分 (比纯按层划分更易维护)
│   │   │       ├── user/            # 用户模块
│   │   │       │   ├── controller/
│   │   │       │   ├── service/
│   │   │       │   │   └── impl/
│   │   │       │   ├── mapper/      # 或 repository
│   │   │       │   └── model/       # DTO / VO / Entity
│   │   │       └── order/           # 订单模块
│   │   │           └── ...
│   │   └── resources/               # 资源配置文件
│   │       ├── mapper/              # MyBatis Mapper XML 文件 (如有)
│   │       ├── application.yml      # 主配置文件
│   │       ├── application-dev.yml  # 开发环境配置
│   │       └── application-prod.yml # 生产环境配置
│   └── test/                        # 单元测试与集成测试
│
├── .gitignore                       # Git 忽略文件 (注意要忽略 *.dump, *.log, .env)
├── Makefile                         # 运维/开发自动化入口 (整合 Docker、Crontab 等)
├── pom.xml                          # Maven 依赖配置文件
└── README.md                        # 项目说明文档
```

## 核心设计要点

### 1. 运维与工程解耦 (`deploy/` 与 `Makefile`)

- **统一收纳**：把所有 Dockerfile、Compose 文件、`pg_backup.sh` 脚本和初始化 SQL 统统放在 `deploy/` 下，不要杂乱地堆在项目根目录。
- **安全隔离**：在 `.gitignore` 中配置忽略实际的环境变量文件（如 `.env`），只提交模板文件（如 `.env.example`）。

> **注意区分「项目仓库目录」与「宿主机数据目录」两个维度**：`deploy/` 下存放的是**脚本与配置（纳入 Git 版本控制）**，而备份脚本**运行时落盘的数据目录**在宿主机上，统一以 `/data/backups` 为根：
>
> ```text
> /data/backups/
> ├── postgres/                  # pg_backup.sh 落盘：pg_dump 产物按 daily/weekly/monthly 分级
> └── minio/
>     └── data/                  # MinIO 实际对象数据目录（docker-compose 卷挂载）
> ```
>
> 脚本里通过 `BACKUP_ROOT="/data/backups/postgres"` 之类的变量指向上述宿主机路径，脚本本体仍留在 `deploy/` 里随仓库版本管理。

> **Git 仓库目录与服务器目录一一对应**：为方便整体迁移，服务器上的部署目录建议与仓库 `deploy/` 保持一致，统一放 `/opt/deploy/`：
>
> ```text
> Git                          Server
> ────────────────────────────────────────────
> deploy/backup/        →      /opt/deploy/backup/
> deploy/backup/minio/  →      /opt/deploy/backup/minio/
> deploy/backup/postgres/ →    /opt/deploy/backup/postgres/
> deploy/docker/        →      /opt/deploy/docker/
> ```
>
> 迁移服务器时直接 `rsync -av /opt/deploy/ new-server:/opt/deploy/`，整个部署文件目录一键迁移。最终三个维度边界清晰：
>
> ```text
> /opt/deploy/backup/     # 程序、脚本（随 Git 版本管理）
> /data/backups/          # 真正的备份数据（独立挂盘）
> /var/log/...            # 日志
> ```

### 2. Spring Boot 业务分层包结构

推荐采用 **按业务模块划分 (Package by Feature)**，而不是单纯的 **按架构层级划分 (Package by Layer)**：

- **不推荐（传统小项目）**：所有 Controller 放一起，所有 Service 放一起。项目一旦变大，查找一个功能的文件需要频繁上下翻滚。
- **推荐（模块化分包）**：按 `modules/user`、`modules/order` 划分子包，每个模块内部自包含 Controller、Service、DTO 等。后续如果需要微服务拆分，直接剥离模块即可。

### 3. `.gitignore` 的配套设置

为了配合数据库备份和运维脚本，请确保你的 `.gitignore` 中包含了以下规则：

```
# 编译与打包
/target/
*.class
.idea/
*.iml

# 运维与日志临时文件
*.log
*.dump
*.sql
!deploy/backup/init.sql

# 环境变量敏感文件
/deploy/env/.env
/deploy/env/*.env
!/deploy/env/*.example
```

## 配合 Makefile 的体验

有了上述结构后，根目录下的 `Makefile` 就可以作为**项目的统一命令行指挥中心**：

```makefile
# 常用指令示例
.PHONY: dev build docker-up backup-cron-install

# 1. 本地启动开发
dev:
	./mvnw spring-boot:run -Dspring-boot.run.profiles=dev

# 2. 打包项目
build:
	./mvnw clean package -DskipTests

# 3. 容器化一键部署
docker-up:
	docker-compose -f deploy/docker/docker-compose.yml --env-file deploy/env/.env up -d --build

# 4. 挂载 PostgreSQL Crontab 备份任务
backup-cron-install:
	@chmod +x deploy/backup/postgres/pg_backup.sh
	@(crontab -l 2>/dev/null | grep -v "pg_backup.sh"; echo "0 2 * * * /bin/bash $(shell pwd)/deploy/backup/postgres/pg_backup.sh >> /var/log/pg_backup.log 2>&1") | crontab -
	@echo "✅ PostgreSQL 备份定时任务已成功安装！"
```

# 备份架构设计

## 备份架构总览

```text
                Git
                 │
          保存所有 YAML/配置
                 │
────────────────────────────────

每天凌晨

CronJob
    │
    ├──────────────┐
    │              │
pg_dump         Redis RDB
    │              │
    └──────┬───────┘
           │
      压缩（可选）
           │
      上传 MinIO
           │
           ▼
     Backup Bucket
           │
           ▼
  再同步到另一台服务器/NAS（异地更佳）
```

## 核心设计原则

### 1. 数据库备份与 K3s 解耦

即使未来迁移到 Docker Compose、虚拟机或云数据库，备份方案也无需改变。备份脚本不依赖 K3s 特有功能，使用标准的 `pg_dump` 工具。

### 2. PostgreSQL 使用原生备份工具

使用 `pg_dump` 保证一致性和可恢复性，不依赖容器快照或文件系统级备份。

### 3. Redis 根据用途决定是否备份

- **缓存数据**：不备份（丢了重新加载即可）
- **会话/Session 数据**：可选择性备份
- **持久化数据**（如计数器、队列状态）：使用 RDB 备份

避免做无意义的数据备份，减少存储成本。

### 4. K3s 职责清晰

K3s 只负责：
- 调度备份任务（CronJob）
- 备份集群自身的 etcd

### 5. 备份至少保留两份

- 一份在对象存储（如 MinIO）
- 另一份同步到独立服务器或 NAS，避免单点故障

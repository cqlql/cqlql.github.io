# ID 设计规范

## 1. 设计目标

- 唯一性
- 可扩展性（分布式）
- 数据库友好
- 对外安全（防枚举）

---

## 2. 常见方案对比

### 自增ID
优点：
- 简单
- 数据库友好

缺点：
- 不适合分布式
- 可被枚举

---

### 雪花ID
优点：
- 分布式
- 高性能
- 适合数据库主键

缺点：
- 需要 workerId 管理

---

### ULID
优点：
- 无中心
- 可排序
- 适合对外ID

缺点：
- 字符串，不适合主键

---

## 3. 最终方案

```text
id   → BIGINT（内部主键）
uid  → ULID（对外标识）
```

双 ID 设计之所以能无痛升级，是因为把“可变的内部实现（id）”和“稳定的外部契约（uid）”分离了。

# 文件存储方案

## 一、方案对比

| 方案                         | 推荐程度 | 适用场景             | 说明                         |
| ---------------------------- | -------- | -------------------- | ---------------------------- |
| 本地磁盘                     | ❌        | 单机开发/测试        | 不适合分布式，扩容困难       |
| NFS                          | ⚠️        | 传统机房共享存储     | 有单点瓶颈，高并发性能差     |
| 数据库 (BLOB)                | ❌        | -                    | 严重拖慢数据库，备份恢复慢   |
| 对象存储（OSS / S3 / MinIO） | ✅        | 生产环境标准方案     | 分布式、高可用、自动扩容     |

> 对象存储具备天然的分布式能力，支持海量文件存储和高并发访问，同时具备高可用和自动扩容能力。在扩展性、可靠性和成本上都优于其他方案，是文件存储的行业标准。

## 二、对象存储核心优势

- **前端直传**：支持 Presigned URL 直传，显著降低后端带宽压力。
- **安全可控**：通过签名 URL 控制访问权限和有效期。
- **无限扩展**：无需关心容量上限，按量付费。
- **多副本**：数据自动冗余，无需额外运维。

## 三、上传方案

### 方案 A：前端直传（推荐）

```
前端 → 后端（获取上传凭证/Presigned URL）→ 直接上传到对象存储
```

后端只做：
- 生成 Presigned PUT URL
- 校验文件类型和大小
- 记录文件元信息到数据库

优点：带宽成本低、上传速度快、后端压力小。

### 方案 B：后端中转（适合需要额外处理的场景）

```
前端 → 后端（接收文件流）→ 对象存储
```

适用场景：
- 需要对文件进行转码/压缩/水印
- 需要严格审计上传内容
- 前端无法直接使用 SDK

## 四、常见对象存储选型

| 产品 | 类型 | 说明 |
|------|------|------|
| **MinIO** | 自建 | 开源，兼容 S3 API，适合私有化部署 |

| **腾讯云 COS** | 云服务 | 国内腾讯生态集成方便 |

# 数据模型与分层规范

## 数据流示意

正向数据流（查询 / 读）

Entity → Repository → Projection → BO → DTO → VO → 前端

反向数据流（提交 / 写）

前端 → VO / Form → DTO → BO → Entity → Repository → DB

> **Entity 不进 Controller** **Projection 不进 save** **业务逻辑只存在于 BO**
>
> 如果是 BFF / 前后端分离项目，`vo` 也可以只存在于前端

## 分层职责说明

| 对象           | 层             | 作用             | 特点                         | 示例                       |
| -------------- | -------------- | ---------------- | ---------------------------- | -------------------------- |
| **Form**       | 接口层（输入） | 接收前端请求参数 | 可校验、可缺省、与前端强绑定 | `CreateUserForm`           |
| **Entity**     | 持久层         | 表映射           | 全字段、JPA 注解             | `User`                     |
| **Projection** | Repository 层  | 精简查询结果     | 只读、字段子集、SQL 强绑定   | `UserPermissionProjection` |
| **BO**         | 业务层         | 业务语义封装     | 聚合、规则、状态机           | `UserPermissionBO`         |
| **DTO**        | 接口层（输出） | 接口返回         | 控制暴露字段、序列化友好     | `UserPermissionDTO`        |
| **VO**         | 展示层         | 前端展示         | 格式化、组合、可计算         | `UserPermissionVO`         |

## Form vs DTO（最容易混淆）

| 维度             | Form         | DTO                |
| ---------------- | ------------ | ------------------ |
| 方向             | 输入         | 输出               |
| 面向对象         | 前端请求     | 前端响应           |
| 是否校验         | ✅           | ❌（通常不校验）   |
| 是否可缺字段     | ✅           | ❌（尽量完整）     |
| 是否包含业务语义 | ❌           | ❌                 |
| 是否可复用       | ❌（接口级） | ✅（接口间可复用） |

> ❗**结论**
> **不要用 DTO 接请求**
> **不要用 Form 做返回**

## 数据流说明（文字版）

1. **Form → DTO / BO**
   - Controller 接收 Form
   - 做参数校验、基础转换
2. **DTO / BO → Service**
   - Service 不关心 HTTP / JSON
3. **Service → Repository**
   - 查询返回 Projection
4. **Projection → BO**
   - 执行业务规则（如 DENY 覆盖 ALLOW）
5. **BO → DTO**
   - 转为接口返回模型
6. **DTO → VO**
   - 前端展示专用结构

## Projection 的典型使用场景

- 原生 SQL（`nativeQuery = true`）
- 多表 JOIN
- `SELECT` 字段 ≠ Entity 字段
- 临时拼装的数据视图

## Projection vs BO 对照表

| 维度        | Projection   | BO         |
| ----------- | ------------ | ---------- |
| 所在层      | Repository   | Service    |
| 角色        | 查询结果映射 | 业务模型   |
| 是否可变    | 否（只读）   | 视设计而定 |
| 是否含逻辑  | ❌           | ✅         |
| 与 SQL 绑定 | 强           | 弱         |
| 生命周期    | 短           | 长         |

## 推荐结构

```
permission
├─ controller
│   ├─ PermissionController.java
│   └─ form
│       ├─ AssignPermissionForm.java
│       └─ RevokePermissionForm.java
├─ service
│   └─ PermissionService.java
├─ entity （表结构）
│   └─ Permission.java
├─ repository（查询结果）
│   └─ PermissionRepository.java
├─ projection
│   └─ UserPermissionProjection.java
├─ bo（业务模型）
│   └─ UserPermissionBO.java
├─ dto
│   └─ UserPermissionDTO.java
└─ vo
    └─ UserPermissionVO.java
```

## 一句话总总结

> **Form 负责“接收世界的不可信输入”
> BO 负责“业务真实规则”
> DTO 负责“对外安全输出”
> Projection 负责“SQL 世界的真实形态”**

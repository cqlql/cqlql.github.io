# 简介

## Redis 是什么？

Redis = **内存型 Key-Value 数据库**

特点：

- 🚀 **非常快**（内存）
- 🧠 支持多种数据结构（不只是 String）
- 🔥 常用于 **缓存 / 会话 / 分布式锁 / 计数 / 排行榜**

一句话：

> Redis 不是用来替代数据库，而是 **减轻数据库压力、提升响应速度** 的。

## Redis 能用来做什么（最常见 6 种）

### 1️⃣ 缓存（最常见）

```txt
数据库慢 → Redis 快
```

例子：

- 用户信息缓存
- 权限列表缓存
- 配置项缓存

```txt
key: user:info:1001
value: {id:1001,name:"Tom"}
```

---

### 2️⃣ 登录会话 / Token

```txt
token → userId
login:token:abc123 → 1001（30分钟过期）
```

优点：

- 无状态服务
- 支持多实例部署

---

### 3️⃣ 分布式锁

```txt
防止重复提交 / 并发写
SET lock:order:1001 1 NX EX 10
```

---

### 4️⃣ 计数器 / 限流

```txt
验证码次数
接口调用次数
INCR api:limit:user:1001
```

---

### 5️⃣ 排行榜 / TopN

```txt
点赞排行 / 积分排行
```

使用 `ZSET`

---

### 6️⃣ 临时数据

```txt
短信验证码
邮箱验证码
```

## 登录风控适合用redis

> 即使单体应用也极力推荐

### 为什么 Redis 非常适合

1. **高并发原子操作**
   - `INCR`、`SET NX` 都是原子操作
   - 多线程 / 多实例下保证计数准确
2. **短时存储**
   - 登录失败记录只需要 5~30 分钟
   - Redis TTL 自然过期
3. **跨实例共享**
   - 单机可以用本地缓存
   - 多实例必须 Redis
4. **支持复杂数据结构**
   - String、Hash、SortedSet 都可以做统计

## Redis 不适合做什么 ❌

- ❌ 强一致事务
- ❌ 大数据长期存储
- ❌ 复杂 SQL 查询

# AI 框架与协议

## mcp 与 a2ui

MCP 拿数据，A2UI 决定怎么“给人看”

### MCP 的世界里（能力层）

- AI 调用：
  - DB
  - API
  - 文件系统
  - 内部服务
- 返回的是：
  - 数据
  - 执行结果
  - 状态

👉 **不关心 UI 怎么显示**

### A2UI 的世界里（UI 层）

- AI 操作：
  - 页面跳转
  - 打开弹窗
  - 表单填充
  - 高亮组件
- 不直接碰业务数据
- 不执行副作用（或极少）

### 它们在系统架构中的位置

```
用户
 ↓
UI（Vue / React）
 ↓  ↑  A2UI
Agent / LLM
 ↓  ↑  MCP
工具 / 服务 / DB
```

### 类比一下（帮助记忆）

| 类比     | MCP         | A2UI        |
| -------- | ----------- | ----------- |
| 人       | 手          | 表情 / 动作 |
| 操作系统 | syscall     | GUI 事件    |
| 后端     | Service API | View Model  |
| 自动驾驶 | 控制引擎    | 仪表盘      |

## MCP 与 Skill

从性质上看，它们不是同一层级的概念：

1. **MCP 是平台级别**，强调**管理、组合、调度**能力。MCP 可以管理多个 Skill，负责调度、调用、组合。
2. **Skill 是单元级别**，强调**具体功能的实现**。

> 类比现实世界：MCP 就像是“工具箱”，Skill 就是“里面的工具”。你可以说工具箱里有多少工具，但不能直接把工具和工具箱比较优劣。

| 概念                                            | 含义                                                         | 使用场景                         | 特点                                                   |
| ----------------------------------------------- | ------------------------------------------------------------ | -------------------------------- | ------------------------------------------------------ |
| **MCP (Modular Capability/Component Platform)** | 一种能力/模块化组件的平台或者框架，专门用于组合、管理、调度不同能力。 | LLM 智能体、RPA 或多能力 AI 系统 | 更像“系统级能力管理”，可做能力调度、权限控制、资源管理 |
| **Skill**                                       | 单个具体能力或技能模块，比如“翻译文本”、“查询数据库”、“生成图表”。 | LLM 或智能体的具体操作           | 颗粒度小，是 MCP 管理的单元，通常是可复用的功能模块    |

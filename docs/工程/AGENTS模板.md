# AGENTS.md 模板（新仓第一天写它）

> 状态：**母本 · 现行**（2026-10-30 从 `pass-up.frontend-mp` 的实战版提炼；
> 2026-11-18 骨架新增「任务路由」表 + §3.1 —— 解决「专项规范按需读」缺正向入口，
> 让 AI 不必在「全读」与「全不读」之间二选一）
>
> **AI 执行版**：`skills/repo-bootstrap/`（本模板是其 `assets/AGENTS-template.md`）；
> 本文件仍是母本。
>
> `AGENTS.md` 是**给 AI 编码助手读的项目指引**，不是给人看的 README。
> 它只有一个考核指标：**AI 读完这一份，动代码时不会踩你已经踩过的坑。**

---

## 一、先记住那条实测数据

某仓的 AGENTS.md 曾写到 **1117 行 / 106KB**，结果 **只有前 17% 进得了上下文** ——
后面 83% 的红线写得再好，AI 也读不到，等于没写。

所以硬指标：

| 指标 | 上限 | 超了怎么办 |
| :--- | :--- | :--- |
| 行数 | **≤ 220 行** | 拆到 `docs/`，AGENTS 只留一句结论 + 指针 |
| 体积 | **≤ 16.5KB** | 同上 |

> 220 行不是审美标准，是「能整份进上下文」的经验上限。

---

## 二、每条内容先过三问

写之前问自己，**三条缺一条就别写进 AGENTS**：

1. **每次动代码都要遵守吗？** —— 只对某个功能成立 → 进 `docs/`。
2. **不知道会不会写错 / 搞坏？** —— 显然不会踩的常识 → 删掉，AI 本来就知道。
3. **能一句话说清吗？** —— 要三段话解释的判据、实测数据、决策历史 → 进 `docs/`。

留下来的形态统一是：**一句结论 + 一个指针**。

```md
- 🔴 **构建前先看有没有 `--watch` 在跑**：一次性构建与它写同一个产物目录，会产出混合包。
- 详细判据与踩坑见 `docs/build-and-verify.md`。
```

**唯一例外**是 §三 骨架里那张**任务路由表**：它的判据本身就是四维映射（改动类型 → 章节 → 等级 → 篇幅），
压成「一句结论 + 一个指针」会直接失真。例外受两条约束：**进 AGENTS 不新开文件**、**≤12 行**（见 §3.1）。

### 3.1 骨架里那张「任务路由」表，为什么必须进 AGENTS

**它解决的是检索成本，不是规则数量。** 六份规范每份都写了「本文不管什么 → 指针」，
但没有一张正向的「改 X 读哪节」。缺了它，AI 只有两个选择：**全读**（上下文膨胀）或**全不读**（红线失效）。
这张表给的是第三条路。

**它不是「第二份索引」。** `文档约定` §四 禁止的是「另建 README 当索引」——两份索引必然漂移。
这张表按**改动类型**索引，与 AGENTS 里「功能 / 模块 → 文档」那张表**正交**，且**同在 AGENTS 内**，
不新增入口、不新增文件。

三条填法（照抄骨架最容易错的地方）：

1. **只填章节号，不填章节标题**。标题会改名，章节号相对稳定；真要重排章节，就是一次有意的改动，顺手回来核对本表。
2. **本仓没实例化的规范，删掉对应行**。没有 `docs/sql-orm.md` 就删掉 SQL 两行；没有 `docs/code-validation.md` 就删掉验证等级列。
   删掉 = 明确「不存在」；留一行指向空文件比删掉更坏。（目录那行指向本文件自己的「目录与边界」节，不依赖 `docs/`。）
3. **上限 8 行 / 约 1.5KB**。每行约 180B —— 10 行就要吃掉 AGENTS 体积预算的 11%（实测：10 行版 1.8KB，太重）。
   超了说明分类太细，合并相邻行；AGENTS 已接近 16.5KB 时压到 **5 行**（pass-up.backend 实测够用）。
   这是「四档决策表」，不是「改动类型词典」。

🔴 **表里的等级是下限**，与 `代码验证规范` §2.2 一致：命中「资金 / 权益 / 并发 / 状态机」任一项时，
不许以「表里写的是 L2」为由降级。反过来，L1 的改动也不许照着 L3 那行做。

## 四、几条实战写法规矩

**1. 索引只有一张表，就在 AGENTS 里。**
不额外建 `docs/README.md` 当第二索引 —— 两个索引必然漂移，最后谁都不准。详见 `文档约定.md` 第四节。

**2. 红线和指针必须成对出现。**
只写「见 `docs/xxx.md`」等于没写（AI 不一定会去点）；只写结论不写指针，以后判据变了没人知道去哪改。

**3. 用 🔴 标「不知道就会搞坏」的条目。**
一个仓里 🔴 控制在 10~20 条。满屏都是红点 = 没有红点。

**4. 不写「项目简介」「如何安装」这类 README 内容。**
AI 需要的是判据，不是产品介绍。人看的那份放 `README.md`。

**5. 改完代码先改 AGENTS，再改 docs。**
顺序反了就会出现「文档说 A、红线说 B」—— 而 AI 只信 AGENTS。

**6. 一份 AGENTS 只服务一个仓。**
多仓项目各写各的；跨仓契约放生产方那一仓，消费方只放指针（见 `文档约定.md` 第一节第 3 问）。

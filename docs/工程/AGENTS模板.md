# AGENTS.md 模板（新仓第一天写它）

> 状态：**母本 · 现行**（2026-10-30 从 `pass-up.frontend-mp` 的实战版提炼）
>
> `AGENTS.md` 是**给 AI 编码助手读的项目指引**，不是给人看的 README。
> 它只有一个考核指标：**AI 读完这一份，动代码时不会踩你已经踩过的坑。**

---

## 一、先记住那条实测数据

某仓的 AGENTS.md 曾写到 **1117 行 / 106KB**，结果 **只有前 17% 进得了上下文** ——
后面 83% 的红线写得再好，AI 也读不到，等于没写。

所以硬指标：

| 指标 | 上限 | 超了怎么办 |
| :--- | :--- | :--- |
| 行数 | **≤ 220 行** | 拆到 `docs/`，AGENTS 只留一句结论 + 指针 |
| 体积 | **≤ 16.5KB** | 同上 |

> 220 行不是审美标准，是「能整份进上下文」的经验上限。

---

## 二、每条内容先过三问

写之前问自己，**三条缺一条就别写进 AGENTS**：

1. **每次动代码都要遵守吗？** —— 只对某个功能成立 → 进 `docs/`。
2. **不知道会不会写错 / 搞坏？** —— 显然不会踩的常识 → 删掉，AI 本来就知道。
3. **能一句话说清吗？** —— 要三段话解释的判据、实测数据、决策历史 → 进 `docs/`。

留下来的形态统一是：**一句结论 + 一个指针**。

```md
- 🔴 **构建前先看有没有 `--watch` 在跑**：一次性构建与它写同一个产物目录，会产出混合包。
- 详细判据与踩坑见 `docs/build-and-verify.md`。
```

## 四、几条实战写法规矩

**1. 索引只有一张表，就在 AGENTS 里。**
不额外建 `docs/README.md` 当第二索引 —— 两个索引必然漂移，最后谁都不准。详见 `文档约定.md` 第四节。

**2. 红线和指针必须成对出现。**
只写「见 `docs/xxx.md`」等于没写（AI 不一定会去点）；只写结论不写指针，以后判据变了没人知道去哪改。

**3. 用 🔴 标「不知道就会搞坏」的条目。**
一个仓里 🔴 控制在 10~20 条。满屏都是红点 = 没有红点。

**4. 不写「项目简介」「如何安装」这类 README 内容。**
AI 需要的是判据，不是产品介绍。人看的那份放 `README.md`。

**5. 改完代码先改 AGENTS，再改 docs。**
顺序反了就会出现「文档说 A、红线说 B」—— 而 AI 只信 AGENTS。

**6. 一份 AGENTS 只服务一个仓。**
多仓项目各写各的；跨仓契约放生产方那一仓，消费方只放指针（见 `文档约定.md` 第一节第 3 问）。

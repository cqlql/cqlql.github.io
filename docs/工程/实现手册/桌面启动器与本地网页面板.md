## 0. 一页速用

目标形态，三段结构，**形状固定**：

```text
桌面 .lnk  →  仓库根「启动<工具名>.cmd」  →  <exe> <动词>
（只存路径）   （构建 / 配置 / 单实例 / 前后台）   （真正干活）
```

无参双击时，动词是 **`ui --background`**：启动器前台进程几百毫秒内退出，
一条**隐藏的** cmd 托管 `ui`，浏览器自动打开带 token 的地址，桌面不留黑窗口。

三句红线，先记住：

1. 🔴 **`.lnk` 只指启动器，不指 exe**。指 exe 会绕过构建、配置模板、单实例判断，
   换台机器必然「双击没反应」，而且错误现场没有任何提示。
2. 🔴 **双击不执行写操作**。落地页必须只读；唯一的写要人显式点击（还要二次确认/输密码）。
3. 🔴 **后台失败必须可见**。隐藏窗口里的失败 = 用户眼里的「双击没反应」，
   这是本类工具最高频的投诉，必须在架构上堵死（见 skill 第 5.6 节）。

## 1. 适用与不适用

**适用**：本地单二进制工具（Go / Rust / Node 打包均可），已经有或想要一个本地 Web 面板，
用户不想记命令、不想开终端。

**不适用**（别硬套）：

- 服务端程序。本文全部动作发生在**本机**，不碰远端。
- 需要开机自启 / 托盘常驻 / 安装器的产品。本文明确不做这些（桌面只放一个 `.lnk`）。
- macOS / Linux 的等价物。`.lnk` 与 `WScript.Shell` 是 Windows 专属；
  其它平台应明确报「请自己建一个指向启动器的入口」，不要假装成功。

## 2. 三段结构：每层只干一件事

| 层 | 文件 | 职责 | 不能做 |
| :--- | :--- | :--- | :--- |
| 快捷方式 | 桌面 `<名字>.lnk` | `TargetPath` / `WorkingDirectory` / `IconLocation` / `Description` / `WindowStyle` | 不带业务参数、不直接指 exe、不写配置 |
| 启动器 | 仓库根 `启动<工具名>.cmd` | 定位或构建 exe、首次写配置模板、单实例、前后台、日志、参数透传 | 不实现业务逻辑、不判断该跑哪个远端动作 |
| 程序 | `<exe> <动词>` | 真正的命令（`init` / `ui` / `backup deploy` …） | 不关心自己是被双击还是被手敲启动的 |

**为什么启动器放仓库根**：`%~dp0` 天然是仓库根，配置目录、兄弟仓库的相对路径都从这里算；
放深一层就得靠 `..` 拼，容易和「向上找启动器」的层级判断打架。

---

## 3. 代码分层与依赖方向

以 Go 为例（其它语言照搬职责划分）：

```text
main.go                       只做命令分发 + 注入
internal/shared/              跨能力共用：配置目录、单实例、共享模型
internal/<能力>/              各能力的实现与 CLI 分发
internal/ui/                  网页面板服务端 + 后台调度
internal/launcher/            桌面快捷方式 + 交互菜单
```

🔴 **依赖方向只许单向**：`main → {能力包, ui, launcher} → shared`。
`ui` 与 `launcher` 之间**不能互相 import**。两条实操结论：

| 需求 | 错的做法 | 对的做法 |
| :--- | :--- | :--- |
| 界面要调「建快捷方式」 | `ui` import `launcher`（而 `launcher` 已 import `ui` → 成环） | `main` 把函数注给 `ui`：`ui.CmdUI(args, static, createShortcut)` |
| 界面与菜单都要「单实例」 | 各写一份 Windows API 胶水 | 下沉 `shared.AcquireSingleton(name)`，两边各传不同名字 |
| 界面要回传快捷方式结果 | 在 `ui` 里再定义一份结构体 | 模型下沉 `shared.ShortcutInfo`，两边共用 |

**注入的签名要窄**：只传函数，不传整个包。菜单同理：`launcher.CmdMenu(args, exec, probe)`
由 `main` 注入 `run` 与「这个动词注册了吗」。

## 4. 关闭与重启：只做一半也是对的

| 能力 | 做法 | 是否建议做 |
| :--- | :--- | :--- |
| 关闭界面 | 页面按钮 → `POST /api/shutdown` → 进程以 **0** 退出，守护随之结束 | ✅ 必做。后台窗口是隐藏的，没有它只能去任务管理器杀进程 |
| 重启界面（自重建） | 进程重建自己 → 退出 **75** → 启动器把 `exe.new` 换成正身 → 带 `--takeover` 重跑（同端口同 token，页面自己重连） | ◐ 可选。链路长，出错时同样无人看见 |

**做关闭的注意点**：先写响应、`sleep 300ms` 再 `os.Exit`，否则浏览器拿到的是
「连接被重置」，而它本来该显示「界面已关闭」。前端收到成功响应后要把页面切成
「已关闭，重新双击启动器可再打开」。

**不做自重建的理由**（如果前端是独立工程，更该这么选）：重建要跑 npm/打包，
链路长、失败面大，而失败发生在隐藏进程里；源码改动让开发者手动 `build` 一次更诚实。
**决定了不做，就写进文档**，别让后来的人以为「点了重启会生效」。

## 5. 决策与备选

| 决策 | 备选 | 为什么选这个 |
| :--- | :--- | :--- |
| `.lnk` 指启动器 | 直接指 exe | 指 exe 绕过构建/配置/单实例，换机器就「双击没反应」 |
| 后台交给隐藏 cmd | Go 自己当守护 | Windows 上双击 `.cmd` 必开控制台；cmd 不持有 exe 句柄，将来换身也不会锁死自己 |
| 命名互斥体 | `tasklist` / pid 文件 | 内核持有、进程被杀自动释放；另两种会误判或残留 |
| 互斥体名带目录指纹 | 全局固定名 | 配置目录可被覆盖，固定名会让多环境互相挡 |
| 默认端口自动递增 | 绑死端口 / 一律递增 | 绑死会静默失败；一律递增会让显式 `--port` 形同虚设 |
| 就绪等待 + 回退前台 | spawn 成功即返回 0 | 隐藏窗口里的失败必须变成可见错误 |
| 配置不全也起页面 | 直接退出 | 首次运行/隐藏窗口下退出 = 双击没反应 |
| 关闭按钮退出 0 | 只给 `--fg` / 让用户杀进程 | 后台窗口隐藏，页面必须有停止入口 |
| 不做自重建 | 照搬「退出码 75 + `.new` 换身」 | 链路长、失败面大且无人看见；源码改动手动 build 更诚实 |
| 快捷方式实现注入 | `ui` 直接 import `launcher` | 已有 `launcher → ui`，反过来成环 |
| 静态产物不过 token | 每个请求都校验 | `<script src>` 带不上自定义头，也拿不到地址栏参数；边界在 API |

> ⚠️ 表中「不做自重建」一行**已被修订**：满足 [网页面板重启自己（通用实现手册）](网页面板重启自己（通用实现手册）.md) §1.3 四个前提时改为「做」，详见该文 §5；前提不满足仍按本表。

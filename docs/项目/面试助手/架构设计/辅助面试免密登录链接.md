## 背景与问题

辅助面试页面只能在 PC 端打开，移动端需要提供一个 URL 链接，复制后粘贴到 PC 浏览器打开。

场景本质是：

> 手机端已经登录 → 点击"辅助面试" → 生成一个临时链接 → 复制到 PC 浏览器 → PC 直接进入辅助面试页面

这类场景**不建议做传统账号登录**，而应设计成**一次性访问凭证（One-Time Access Token）**。

不要直接暴露：

```
https://passup.com/interview/helper?interviewId=123&userId=456
```

因为没有安全性，任何人拿到链接即可访问。

------

## 推荐方案：短期免密登录链接（Magic Link）

```
手机端
  |
  | 点击辅助面试
  ↓
后端生成 ticket
  |
  ↓
https://passup.com/helper/login?t=abc123xyz
  |
  | 复制
  ↓
PC浏览器打开
  |
  ↓
后端校验 ticket
  |
  ↓
创建 PC 会话
  |
  ↓
进入辅助面试
```

------

## 是否免密？

是，但**不是永久免密**，而是：

> 短期 + 单次 + 限定资源

这是很多产品使用的方式（飞书文档分享、腾讯会议入会链接、Notion share link、Stripe checkout）。

## 生成链接

手机端请求：

```
POST /api/interview/{id}/helper-link
```

后端：

```java
String token = SecureRandomUtil.randomString(48);

ticketRepository.save(
    new InterviewAccessTicket(
        userId,
        interviewId,
        token,
        now.plusMinutes(10)
    )
);

return "https://passup.ai/helper/login?t=" + token;
```

生成：

```
https://passup.ai/helper/login?t=8fK39s9aKdj29...
```

------

## PC 打开

请求：

```
GET /helper/login?t=xxxx
```

后端步骤：

1. 查 token

```sql
select *
from interview_access_ticket
where token = ?
```

2. 检查：是否存在、是否过期、是否使用过
3. 创建登录态

```
Set-Cookie:
PASSUP_SESSION=xxxx;
HttpOnly;
Secure;
SameSite=Lax
```

4. 302 重定向到 `/helper/interview/123`

## 安全增强建议

### 1. token 不要可预测

不要用 `uuid`。虽然 UUID 看似随机，但建议用 **256bit random**（如 `SecureRandom`）生成 48~64 字符的随机串。

### 2. 设置过期时间

辅助面试场景建议 **10 分钟**。用户流程：手机打开 → 复制 → 切电脑 → 打开，10 分钟足够。

### 3. 单次使用

打开后将状态置为 `USED`，之后再次访问同一链接返回"链接已失效"。

### 4. 绑定浏览器（初期可不做）

第一次打开可记录 `user-agent` 与 `ip`，后续请求检查。PassUp 初期不建议做，增加复杂度。

## Redis 方案（更推荐，无需建表）

项目已使用 Redis，可以直接用，不必建表。

```
key:   interview:helper:ticket:{token}
value: { userId:1001, interviewId:2001 }
TTL:   600s
```

生成：

```java
String token = SecureRandomUtil.randomString(48);

redis.set(
    "interview:helper:ticket:" + token,
    json,
    Duration.ofMinutes(10)
);
```

打开：

```java
redis.get("interview:helper:ticket:" + token);
```

成功后：

```java
redis.delete("interview:helper:ticket:" + token);
```

## 与 PassUp 现有架构的衔接

推荐方案：

```
手机端
  |
  | POST /interviews/{id}/helper-ticket
  ↓
Redis（TTL 10 分钟）
  |
  | 返回 URL
  ↓
PC 打开
  |
  | GET /helper/login?t=
  ↓
TokenAuthenticationFilter
  |
  | 创建临时 Session / JWT
  ↓
辅助面试页面
```

可复用已有能力：

- Redis Key 管理
- JWT
- Cookie refresh token

Redis Key 设计：

```java
public interface InterviewRedisKey {

    String HELPER_TICKET = "interview:helper:ticket:";

    Duration HELPER_TICKET_TTL = Duration.ofMinutes(10);
}
```

------

## 关键细节：PC 不应获得完整用户权限

这一点很重要。链接登录后**不要生成普通登录 JWT**，应生成专用角色：

```
ROLE_INTERVIEW_HELPER
```

权限：

- 允许：`GET /api/interview/current`、`POST /api/answer/analyze`、`GET /api/resume/context`
- 禁止：修改账号、充值、删除简历

否则链接泄露风险很大。

------

## 最终建议

**Redis + 一次性 ticket + 10 分钟过期 + 打开即消费 + 专用辅助面试权限。**

该方案与 PassUp 现有的 Spring Security + Redis 架构衔接最好。

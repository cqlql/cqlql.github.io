## 解析流程

上传简历
   ↓
文件解析（PDF / Word / 图片 OCR）
   ↓
文本预处理（清洗、分段）
   ↓
结构化解析（核心）
   ├── 规则解析（正则/模板）
   ├── NLP解析（实体识别）
   └── LLM补全（兜底）
   ↓
标准化（字段统一）
   ↓
存储（JSON + 结构化表）

## 业务端（java）+解析端（python）架构

### 调用链

```
前端上传文件
   ↓
Java（接收文件）
   ↓
存储文件（OSS / MinIO）
   ↓
调用 Python（传 URL 或 file_id）
   ↓
Python 下载文件 + 解析 + AI处理
   ↓
返回结构化结果
   ↓
Java 入库
```

### 架构

```
[Frontend]
   ↓
[Java Backend]
   - 上传
   - 鉴权
   - 存储
   - 任务调度
   ↓
[Python AI Service]
   - parser
   - pydantic_ai
```

### **解析失败情况处理方案：**

####  方案 1：允许失败（最常见）

- 展示“解析失败”
- 用户手动重试

👉 最简单、最稳

------

#### 方案 2：自动重试（推荐）

```
FAILED → retry_count < 3 → 再试
```

👉 注意：

- 避免死循环
- 指数退避（1s / 5s / 30s）

------

#### 方案 3：人工兜底（进阶）

- 解析失败 → 标记“需要人工处理”
- 后台修复（运营工具）

#### 状态机

状态设计

```
resume_parse_status:

- UPLOADED        已上传
- PARSING         解析中
- SUCCESS         成功
- FAILED          失败
```

数据库示例

```
resume_record
------------------------
id
user_id
file_url
status
error_message
retry_count
created_at
updated_at
```

#### 完整流程

```
1. Java 上传文件
   → status = UPLOADED

2. 投递解析任务（MQ / 异步）
   → status = PARSING

3. Python 处理
   → 成功：status = SUCCESS
   → 失败：status = FAILED + error_message

4. Java 根据状态做后续处理
```

```
user 1 —— N resume 1 —— N attachment
```

👉 一个用户可以有多份简历
 👉 一份简历可以有多个附件（PDF / Word / 多版本）



file → attachment → resume



简单架构

一个文件 → 一个 attachment → 一个 resume



```
① 请求 presign
↓
② 前端直传 MinIO
↓
③ 调 complete → 返回 fileId
↓
④ 创建 resume → 绑定 fileId
```



正确姿势：File 状态机（核心）

你需要把 `file` 表变成一个“生命周期实体”👇

```
INIT (已创建, 未上传)
   ↓
UPLOADED (已上传, 待确认)
   ↓
CONFIRMED (已确认, 可使用)
   ↓
DELETED (已删除)
```

推荐的架构

file（资源层） ✅ 提前创建
attachment（业务层） ✅ 后绑定
MinIO（存储层） ✅ 独立

✔ 最终流程

```
1. 创建 file（INIT）
2. 上传
3. confirm → 校验 + 更新 file（CONFIRMED）
4. 绑定 attachment
5.（可选）copy 到 official
```

# 模拟面试 V2：联调与冒烟清单（Step 1 / 2 / 3 / 4）

> **用途**：交付与回归时照着做一遍，就能确认 V2 的四条链路没坏 ——
> ① 文字作答（Step 1）、② 独立识别通道 `/ws/asr`（Step 2）、③ 治理：配额 / 指标 / 埋点 / 日志（Step 3）、
> ④ **识别通道的使用资格与回收**（Step 4：必须有一场进行中的面试；面试结束即回收）。
>
> **与实现文档的分工**：方案文档讲「为什么这么设计」，本清单讲「怎么验、看到什么才算对、坏了怎么定位」。
> 相关：后端方案 §4.1 / §4.2 / §12.3–12.5 / **§12.8**；前端方案 §6；`AGENTS.md` §3.7 / §3.8 / §6.8。
>
> **一句话结论**：自动化脚本覆盖协议层（0 依赖，两分钟），
> 识别准确率 / 回答质量 / 交互手感必须人来做（第 2 节）。

## 0. 前置准备（5 分钟）

### 0.1 环境

| 项 | 默认值（线上口径） | 说明 |
| :--- | :--- | :--- |
| 后端 HTTP | `http://localhost:8080` | 控制器统一挂在 `/api/**`（`WebConfig` 加前缀） |
| 后端 WebSocket | `ws://localhost:8080` | `/ws/audio`、`/ws/asr` **不在** `/api` 下 |
| 指标端点 | `http://localhost:8009/actuator/prometheus` | `management.server.port: 8009` |
| Node | ≥ 22（推荐 24） | 冒烟脚本用全局 `fetch` + `WebSocket`，**零依赖** |
| 小程序 | 开发者工具打开 V2 页面 | `src/pages/mock-interview-v2`（文字作答版） |

> **本机联调实例（2026-09-22 实测，和默认值不一样）**：profile `dev`，API 在 **7005**、
> 管理端口在 **7009**（`application-local.yml` / `docker/.env` 的 `SERVER_PORT`），日志落在
> `logs/app-dev.log`（profile 是 `dev`，`logging.level.root: debug`）。
> 所以本地跑脚本要显式指定：
>
> ```bash
> BASE_URL=http://localhost:7005 WS_URL=ws://localhost:7005 \
> ACTUATOR_URL=http://localhost:7009 SMOKE_LOG_FILE=logs/app-dev.log \
> TOKEN=<accessToken> node scripts/smoke-v2.mjs
> ```
>
> 端口对不上时的定位方式：`Get-NetTCPConnection -State Listen | ? { $_.LocalPort -in 7005,7009,8080,8009 }`
> 配合 `Get-CimInstance Win32_Process -Filter "Name='java.exe'"` 看哪个是 `PassUpApplication`。

### 0.2 拿 accessToken（脚本与手工联调都要）

**最快路径（推荐）**：小程序开发者工具打开 V2 页面 → `Network` 面板 → 点任一请求 →
复制请求头 `Authorization: Bearer <xxx>` 里的 `xxx`，它就是 accessToken。

脚本用法：`TOKEN=<xxx> node scripts/smoke-v2.mjs`

> 为什么不做"脚本自动登录"：小程序登录依赖 `wx.login` 的 code，脱离运行时拿不到；
> PC 端的 `/api/web/auth/login` 需要用户名 + 密码（微信注册的用户没有密码）。
> 硬造 token 只会让脚本看起来能跑、实际验了个假身份。

### 0.3 账号要求（最容易踩的一条）

| 要求 | 不满足会怎样 |
| :--- | :--- |
| **账号有面试时长余额**（`INTERVIEW_SECONDS` > 0 或无限资格） | `/ws/audio` 建连被拒：`INSUFFICIENT_BALANCE`（关闭码 4001） |
| 余额别太少 | `MOCK` 文字会话**同样按时长计费**，联调一轮会走掉几十秒；**冒烟脚本为了让识别通道可用还会开一条"资格载体"会话并保活**，同样计时 |
| **识别通道只能在面试进行中使用**（Step 4） | 没有进行中的面试时点话筒 → `ASR_NO_ACTIVE_SESSION`（关闭码 **4007**）：先开始一场面试再用语音 |
| 建议：用专门的联调账号 | 人工用例里会反复建连 / 暂停 / 重连 |

> 注意：**面试会话与识别通道的准入是两套闸门** ——
> 面试会话看"余额 > 0"（`INSUFFICIENT_BALANCE`），识别通道看"**当前有没有进行中的面试**"（4007）；
> 每日识别配额只作用于 `/ws/asr`，不影响面试会话。
> 也别把 4007 当故障：它正是 Step 4 设的成本护栏（豆包识别按音频时长计费，
> 不能让"只要登录"就能白刷）。

**（强烈建议）本机独享一个 Redis**（2026-09-24 加，原因见 §5 第一条）：
如果同机 / 同网还有别的后端实例（VirtualBox VM、devcontainer、另一台机器）也在跑这套服务，
它们会连**同一个** Redis，各自的计费调度器会把"不在自己内存注册表里"的会话判成孤儿删掉 ——
表现为**面试进行中点话筒被 4007 拒**，而且计费静默停止。隔离只需一步（服务已在 `docker-compose.dev.yml` 里备好）：

```bash
cd docker
docker compose --env-file .env -f docker-compose.base.yml -f docker-compose.dev.yml up -d redis-local
# 只绑 127.0.0.1:6380 —— 别的机器探不到（可自测：Test-NetConnection 172.16.0.222 -Port 6380 → False）
```

启动本机后端时加两个环境变量（**不要改 `docker/.env`**：那份 env 会被 devcontainer / 其他实例一起读，改了等于把所有人一起搬过来，隔离就白做了）：

```text
SPRING_DATA_REDIS_HOST=127.0.0.1
SPRING_DATA_REDIS_PORT=6380
```

> **Postgres 仍是共用的**（`jdbc:postgresql://172.16.0.222:5432/pass_up_dev`）：多实例在数据层仍会互相干扰
> （扣同一份 `user_asset`、回收同一批 `interview` 行、共享 `minio` 的文件）。
> 要彻底隔离就再单独建一个库（如 `pass_up_local`）并把 `SPRING_DATASOURCE_URL` 指过去 ——
> 代价是本地数据从零开始（Flyway 会自动建表，admin 账号会自动创建，体验模板会自动灌）。

### 0.4 两分钟自检（先跑这个）

```bash
cd pass-up.backend
TOKEN=<accessToken> node scripts/smoke-v2.mjs
```

| 退出码 | 含义 |
| :--- | :--- |
| `0` | 协议层全通过（SKIP / WARN 不算失败） |
| `1` | 有 FAIL，脚本末尾列出失败项 |
| `2` | 前置缺失（没给 TOKEN / Node 版本过低） |
| `3` | 脚本自身异常（把它当成一个 bug 报出来） |

可选环境变量：

| 变量 | 默认 | 用途 |
| :--- | :--- | :--- |
| `TEMPLATE_UID` | 空 | 指定体验模板（如 `exp-java-backend-3y`），避免依赖账号的默认简历 / 岗位 |
| `SMOKE_LOG_FILE` | 空 | 后端日志文件路径 → 自动校验「日志里没有作答原文」（Step 3） |
| `SMOKE_QUOTA_TOTAL` | `0` | 把 `realtime.asr.daily-sessions-per-user` 临时调小后，验证 4006 配额拒绝 |
| `SMOKE_LLM_TIMEOUT_MS` | `240000` | LLM 慢时放宽。**首问整轮可能要数十秒到数分钟**（实测 9 秒 ~ 2 分钟），脚本总时长基本由它决定 |

**看到 `SKIP` 不一定是坏事**，但要读懂它在说什么：

| SKIP 文案 | 含义 |
| :--- | :--- |
| `本机未配豆包 ASR Key` | 建连与推帧链路已走通，但识别文本验不了（要有 Key + 真人 / 真实音频） |
| `先收到 ASR_UNAVAILABLE` | audio 模式的「拒绝文字作答」分支没覆盖到，因为会话先因 ASR 不可用结束了 |
| `未复现 TURN_BUSY` | 见 WARN：那一轮回复瞬间结束，没造出并发窗口 |

## 1. 自动化冒烟覆盖了什么（脚本用例对照）

| 用例 | 验的是 | 判定依据（脚本断言） |
| :--- | :--- | :--- |
| `S0-1` | 凭证链路 | `GET /api/ws/ticket` 返回非空 `data`（顺带证明 token 有效） |
| `S1-1` | **会话就绪点迁移**（Step 1 的关键回归） | `mode=MOCK&input=text` 建连后收到 `THINKING` —— 说明不靠 ASR 就绪也能起算计费 + 发首问 |
| `S1-2` | **回合串行化** | 首问还在生成时发 `ANSWER` → `ERROR{TURN_BUSY}`（未被接受、不并发跑两轮） |
| `S1-3` | **「回答结束」信号**（哨兵用例） | 收到 `LLM_REPLY{final:true}`，`replyId` 与首问 `THINKING` 一致；打印 final 分片条数与是否带正文（正常：**1 条且带正文**） |
| `S1-4` | 文字作答 → 回合 | 发 `ANSWER` 后新增一条 `THINKING`，且随后的 `LLM_REPLY.replyId` 与之**一致** |
| `S1-5` | 空作答 | `ERROR{INVALID_ANSWER}`，且 `THINKING` 数量不变（不消耗回合） |
| `S1-6` | 超长作答 | 2001 字 → `ERROR{ANSWER_TOO_LONG}`（**拒绝而非截断**） |
| `S1-7` | 协议严格 | 多传未知字段（`source`）→ **整条丢弃**：无 `THINKING`、无 `ERROR`、静默窗口内 0 条新消息 |
| `S1-8` | 正常收尾 | 客户端关闭 → 连接正常收敛（触发结束事件与计费收尾） |
| `S1-9` | 非法参数组合 | `ASSIST + input=text` → `ERROR{INTERVIEW_PREPARE_FAILED}` + 关闭码 **4002**（非法组合当场暴露，不静默降级成 audio） |
| `S1-10` | 模式与能力对应 | audio 模式发 `ANSWER` → `ERROR{INVALID_INPUT_MODE}`，且不产生回合 |
| `S2-1` | 识别通道推帧（含资格放行） | 先确保**有进行中的面试**（`ensureCarrier`），再 `/ws/asr` 建连 + 推 PCM 帧后**无 ERROR**（有 Key 时另看 `ASR_RESULT`） |
| `S2-2` | 识别并发闸门 | 第二条 → `ERROR{ASR_LIMIT_EXCEEDED}` + 关闭码 **4004** |
| `S2-3` | 识别鉴权 | 不带 ticket → `ERROR{AUTH_FAILED}` + 关闭码 **4001** |
| `S3-1` | 指标暴露 | `/actuator/prometheus` 里有 4 个 `asr_stream_*` 指标，并打印 accepted / rejected_limit / **rejected_no_session** 计数 |
| `S3-2` | 每日配额（可选） | 建连到超限 → `ERROR{ASR_QUOTA_EXCEEDED}` + 关闭码 **4006** |
| `S3-3` | 日志脱敏（可选） | ①正向：日志里能看到 `收到文本作答 … text=len=N` 的摘要；②反向：带随机标记的作答原文**不出现在 INFO+ 级别**（DEBUG 与 AI 复述行不算泄漏，见下） |
| `S4-1` | **识别资格闸门**（Step 4） | **没有进行中的面试**时建连 → `ERROR{ASR_NO_ACTIVE_SESSION}` + 关闭码 **4007**（脚本先开一条会话再关掉，确定性制造"没有面试"；带小重试窗口，避免服务端收尾慢导致的假失败） |
| `S4-2` | 资格不误杀 | 面试进行中建连 → **放行**（无 ERROR）；本机没配豆包 Key 时是 `ASR_UNAVAILABLE`，那同样证明资格已放行（否则会是 4007） |
| `S4-3` | **面试结束即回收**（Step 4） | 识别连接已建好 → 关闭面试会话 → 该识别连接被服务端**静默关闭**：`code=1000`、`reason=INTERVIEW_ENDED`，且**全程没有 ERROR** |
| `S5-1` | **上游输入空闲释放**（2026-09-24，可选、默认跳过） | 建连后**不推任何帧** → 约 <阈值> 后被静默释放：`code=1000`、**`reason=ASR_INPUT_IDLE`**、无 ERROR，且耗时在「阈值 ~ 阈值+检查周期」内。需把后端 `realtime.asr.input-idle-timeout-ms` 临时调小（如 3000）并重启，再带上 `SMOKE_ASR_IDLE_TIMEOUT_MS=<同一个值>` |

## 2. 手工联调清单（脚本替代不了的部分）

### A. 文字作答链路（Step 1）

| # | 操作 | 期望 | 不满足时先看 |
| :--- | :--- | :--- | :--- |
| A-1 | 从设置页以 `?mode=text` 进入 V2 页面，建连 | 建连成功；AI 面试官**主动发首问**（不需要用户先说话） | 前端建连 URL 是否真带 `input=text`；后端是否 `MOCK`（`ASSIST` 无首问） |
| A-2 | 在输入框打字 → 发送 | 出现"思考中"→ 逐字流式输出；**输入框在回复期间禁用** | 前端是否消费 `TURN_BUSY`（回到 S1-4） |
| A-3 | 回复中再点发送 | 提示"AI 正在回复中，请稍候"，且**没有**第二条回答 | 前端本地没拦 → 允许发，但后端必须回 `TURN_BUSY` |
| A-4 | 发送空白 / 纯空格 / 纯换行 | 提示内容不能为空，不产生回答 | `INVALID_ANSWER` |
| A-5 | 粘贴一段超长文本（>2000 字）发送 | 明确提示超长；**不要**发出去被截断 | `ANSWER_TOO_LONG` |
| A-6 | **点话筒说话**（语音输入辅助） | 识别文本进入输入框（草稿可被后续分片覆盖，`final` 后落定），**不触发回答** | 识别通道不触发回合是设计如此（Step 2 的核心解耦） |
| A-7 | 暂停 → 继续面试（重连） | 会话恢复；**输入框仍可文字作答**，且**不会凭空开始走语音会话**。V2 入口：头部「暂停」（带确认）→ 底部暂停条「继续面试」 | `interview.input_mode` 是否落库 / `LogicalSessionRebuilder` 是否还原（见 A-9） |
| A-8 | 提示词一致性：问一个只有简历里才有的细节 | 回答里用到了简历/岗位内容 | 快照裁剪与 `system_prompt` 落库 |
| A-9 | **数据层铁证**（三层判据） | ①现象：发 `ANSWER` 有回答（audio 模式会被拒）；②`select mode, input_mode from interview order by id desc limit 1` → `text`；③重连后仍能文字作答 | `input_mode` 没落库 → 重连后会退化成 audio（重连即启动 ASR，且 `ANSWER` 被判模式不符） |
| A-10 | **V1 / PC 正式面试回归**（最重要的一条） | PC 端（`mode=ASSIST`，不带 `input`）一切照旧：识别 → 自动回答 → 计费 / 暂停 / 结束 | `audio` 路径必须与改动前**行为等价**（后端方案 §5.2 的 5 条回归） |
| A-11 | 结束面试 → 收尾跳转（对齐 V1） | 点底部「结束面试」→ 提示「面试已结束」→ 用**通用模板**的面试进「体验完成」引导页，没用模板则返回上一页；模板分支用 `redirectTo`，**返回键不该再回到面试页**。暂停态点结束同样可退出（此时后端由暂停保留时长兜底收尾，`end_reason` 是超时口径） | 「是否用模板」在**建连成功时定格**（`usedTemplateRef`）—— 别改成收尾时再读 storage，那时选中态可能已被清掉 |

### B. 独立识别通道（Step 2）

| # | 操作 | 期望 |
| :--- | :--- | :--- |
| B-1 | 面试会话进行中，点话筒 → 说一句话 → 停止 | 识别文本进入输入框；**面试会话不受任何影响**（没有额外回答、没有计费异常） |
| B-2 | 说话后什么都不做 | ⚠️ 2026-09-24 后**这条已经验不到绝对上限了**：前端 8 秒空闲释放 / 后端 25 秒上游空闲会先把它收掉（见 B-9）。真要验绝对上限：把后端 `input-idle-timeout-ms` 设为 0、临时把前端 `IDLE_RELEASE_DELAY_MS` 调大，再等满 `session-max-duration-ms`（300 秒）→ 应收 `ASR_TIMEOUT` / 4005，面试继续 |
| B-3 | 在已有识别连接时再点一次话筒 | 旧连接先关 / 或收到 `ASR_LIMIT_EXCEEDED`(4004)；**不要静默重连** |
| B-4 | 断网 → 恢复网络 | 识别连接失败只提示"改用打字"，面试会话按既有心跳规则处理（两者互不牵连） |
| B-5 | 移动网络下同时维持会话 + 识别两条连接 | 双连接稳定（这是 Step 2 的主要风险项，必须在真机 + 移动网络验一次） |
| B-6 | 当天识别次数用完后点话筒 | 提示"今日语音识别次数已用完"（4006），**不自动重连**；文字作答仍然可用 |
| B-7 | **没有面试时点话筒**（Step 4） | 在"未开始面试 / 面试已结束 / 面试已暂停"的页面上点话筒 → 提示「请先开始面试后再使用语音输入」（4007）；**不打开麦克风、不自动重连** |
| B-8 | **说话中直接结束面试**（Step 4） | 识别连接被服务端**静默**收掉（1000，页面不弹任何错误），麦克风随之释放、"正在聆听"提示消失 |
| B-9 | **停止说话后不再操作**（2026-09-24） | 点话筒说一段 → 点话筒停止 → 什么都不做：约 **8 秒后**识别连接自动关闭（开发者工具 Network 里 WS 关闭）；期间最后一句识别结果仍会落进输入框；再点话筒能正常开始（**不能**出现"点了没反应"） |
| B-10 | **单次上限 180 秒**（2026-09-24） | 说满 **180 秒** → 微信自动停录音 + 提示「已到单次语音上限，可再点话筒继续说」，**已识别文字仍在输入框里**；随后再点话筒能正常开始（新连接、新窗口）。界面**不显示**已用时长（2026-09-24 决定） |

### C. 治理（Step 3）

| # | 操作 | 期望 |
| :--- | :--- | :--- |
| C-1 | 跑一轮 B-1 后看指标 | `asr_stream_sessions_active` 回到 0；`asr_stream_connections_total{result="accepted"}` +1；`asr_stream_session_duration_seconds{end="client_close"}` 有一次样本；`asr_stream_audio_bytes_total` 按说话时长增长（≈32000 字节/秒） |
| C-2 | Prometheus 查询 | `rate(asr_stream_audio_bytes_total[5m]) / 32000` ≈ 每秒识别音频时长 → 识别成本；`asr_stream_session_duration_seconds_count{end!="client_close"}` / `..._count` = 失败率 |
| C-3 | 日志抽查（Step 3 的核心验收） | **INFO 及以上**搜不到作答原文与识别转写；能看到 `len=42` 这类摘要。命令：搜你自己的作答内容，再看它命中行的级别 |
| C-4 | 埋点核对 | 分析平台查 `interview_session_started` / `interview_session_ended`，看到 `props.input_mode=AUDIO|TEXT`；时长 / 结束原因与联调过程对得上 |
| C-5 | 配额验证 | 临时把 `realtime.asr.daily-sessions-per-user` 改成 1 → 重启 → 第二次点话筒必回 4006（并在 Redis 里看到 `interview:asr:quota:<userId>:<北京日期>`） |
| C-6 | 资格与回收的指标（Step 4） | `asr_stream_connections_total{result="rejected_no_session"}` 只在"没在面试里点话筒"时增长；被回收的连接记在 `asr_stream_session_duration_seconds{end="server_close"}`（**正常收尾，不是故障**）；**客户端该关没关**的兜底记在 `end="input_idle"`（同样不是故障，但它持续增长说明有客户端没走"停止后 ~8 秒自己释放"那条正路，值得看一眼） |

> C-1 / C-2 的读法：**失败率只看 `end="asr_unavailable"` 的占比**（豆包挂了 / 没配 Key）。
> 另外三类都**不是**故障，别混进去：`client_close`（用户说完就关）、
> `server_close`（**面试结束回收**，Step 4）是正常收尾，`timeout`（点了话筒忘记说话）是用户误触 ——
> 混在一起会把"用户误触 / 正常回收"误判成"服务不稳定"。

## 4. 常见故障对照表（现象 → 根因 → 去哪里看）

| 现象 | 最可能的原因 | 排查入口 |
| :--- | :--- | :--- |
| 建连立刻断开，收到 `INSUFFICIENT_BALANCE` | 账号没有面试时长余额 | `TicketHandshakeInterceptor`（余额准入）；给账号充值 / 用无限资格账号 |
| 建连立刻断开，收到 `MISSING_TICKET` / `INVALID_TICKET` | 没带 ticket / ticket 已过期（30 秒）/ 被复用（GETDEL 一次性） | 前端是否"先取 ticket 再立即建连"；`WebSocketTicketService` |
| 点话筒没反应，无任何提示 | 识别通道建连失败且前端未处理 | 开发者工具 Network 里的 WS 帧；`AsrWebSocketHandler` 是否发了 `ERROR` |
| 点话筒提示「请先开始面试」（`ASR_NO_ACTIVE_SESSION` / 4007） | 该用户当前**没有进行中的面试**（未开始 / 已结束 / 已暂停）—— 这是 Step 4 刻意设的成本护栏，不是故障 | 是否真在面试中：Redis `interview:session:user:<userId>` 是否存在且未 `paused`；`AsrUsageGuard#decide` |
| 面试结束后识别连接还活着（豆包还在计费） | 回收没生效：`InterviewEndedEvent` 没人监听 | `AsrSessionReclaimer` 是否装配；事件是否真的发布（`AudioStreamSession#publishEnded` / `evictExpiredPausedSessions`） |
| **停止说话后识别连接还挂着**（豆包还在喂静音、按时长计费） | 前端空闲释放没跑（定时器被清 / 小程序切后台）**且**后端兜底没生效 | 前端 `WsAsrTransport#stop` 的 `IDLE_RELEASE_DELAY_MS`（8 秒）；后端 `realtime.asr.input-idle-timeout-ms`（25 秒，0 = 关掉了）；日志搜 `上游输入空闲已达上限`，指标看 `end="input_idle"` |
| **面试进行中点话筒却提示「请先开始面试」（4007）** | ① **最常见：同一个 Redis 上还有别的后端实例**（VM / devcontainer / 另一台机器），它的计费调度器把本机这条会话当孤儿会话删掉了（见 §5）；② 本机自身也可能有"迟到起算 / 起算竞态"（已修，见 §5） | 先确认本机后端连的是**独占的** Redis（§0.3：`redis-local:6380`）；再搜日志 `忽略迟到的「会话就绪」` 与 `计费会话归属不是本次会话`；对照 `InterviewBillingService#startBilling`、`AudioStreamSession#markSessionReady` |
| 频繁 `TURN_BUSY` | 前端没有在等回复时禁用输入框；或用户连点 | 前端消费 `THINKING` / `LLM_REPLY{isFinal}` 的状态机 |
| text 会话重连后开始走语音 | `input_mode` 没落库 / 重建时没还原 | `Interview.input_mode`（V26）/ `LogicalSessionRebuilder` |
| 识别通了但文字进不了输入框 | 前端 `base + draft` 规则没按 `final` 落定 | 前端方案 §6.1；`ASR_RESULT.final` |
| `ANSWER` 发了却什么都没发生 | 多传了字段（如 `source`）→ 整条丢弃 | 上行报文与 `ControlMessage` 字段一一对应；见 S1-7 |
| 指标一条都不涨 | 该分支没被走到 / 抓的是另一个实例 / actuator 端口不对 | `curl localhost:8009/actuator/prometheus \| grep asr_stream` |
| 埋点里没有 `input_mode` | `analytics.enabled=false`（默认关闭）；或事件未上报 | `AnalyticsTracker` 日志；AGENTS.md §6.8 |
| 指标里 `rejected_quota` 持续增长 | 配额上限对真实使用偏低，或账号被刷 | `interview:asr:quota:*`；调 `daily-sessions-per-user` |
| 前端收不到「回答结束」，输入框一直禁用 | `final` 分片没到（上游末分片不再带 `finish_reason`），或消费方把字段判成了 `isFinal` | 回归看 `S1-3`；字段名以实际 JSON 为准（§12.6.1） |
| 日志里出现作答原文或识别转写 | 仍有 INFO 级在用 `truncate`（保留前 512 字**内容**）的行；已修 `[回合] 触发LLM回答` 一处 | 回归看 `S3-3`；`LogTextUtils#describe` |
| dev 下日志里能看到完整 LLM 上下文 / 简历内容 | **预期行为**：dev profile 是 `root: debug`，这些是 DEBUG 行；生产 `root=INFO` 不输出 | 看命中行的级别再判断，别按"全文件搜不到"验收 |

> **日志脱敏的验收标准（别搞错）**：按**级别**判定 —— `INFO` 及以上不得出现用户输入原文（作答、识别转写），
> `DEBUG` 允许（dev 排查用）。另外两类"命中"不是泄漏：AI 回答里的复述（`[回合] LLM回答完成`，回答本就落库）、
> 以及 dev 的调试日志。冒烟 `S3-3` 已按这套语义实现。
>
> **「回答结束」的验收标准**：`LLM_REPLY{final:true}` 一轮**恰好一条**、`replyId` 与触发它的 `THINKING`
> 一致；它**带最后一段正文**，前端按**追加**处理（不要整段替换）。它是 V2 输入框恢复的唯一依据 ——
> 这条信号没了，输入框会一直禁用。

| 项 | 说明 |
| :--- | :--- |

| 文本模式「失联 = 结束」还是「失联 = 暂停」 | ✅ **已定稿**：失联 = 结束（≠ 暂停），文字作答阈值 180 秒（后端方案 §4.1.6 / §8.1） |
| 「无操作自动暂停」 | ✅ **已定稿**：V2 不引入，保持显式 `PAUSE`（后端方案 §8 P0-1）；文本模式下用户静默思考照样按时长计费 |
| 前端埋点 `source`(voice/text) | 后端拿不到（打字与语音转写在协议上无法区分），由前端埋点承担 |
| 多端登录顶号 × V2 会话 | 沿用既有顶号语义，V2 未改动，也不在本次冒烟范围 |
| **多实例共享 Redis 顶掉活会话的计费会话**（2026-09-24 冒烟实跑定位；**不是代码缺陷，是本地环境**） | **现象**：`/ws/asr` 在"确实进行中的面试"里被判无资格（4007），并且计费静默停止（用户白嫖）。<br>**根因**：同机还有别的实例（当时是 3 台 VirtualBox VM）跑同一套后端，且**连的是同一个 Redis**（`172.16.0.222:6379`）—— 它们各自的 `InterviewBillingScheduler` 会 `SCAN interview:session:user:*`，把"不在自己内存注册表里"的会话当孤儿会话 `stopBilling` 删键。<br>**定位证据**：① Redis `MONITOR` 抓到一条 `DEL`，但应用日志里**没有任何对应记录**（同步 appender，不存在丢行）；② 给两处删键点（`stopBilling` / `forceTerminateActiveSession`）加带调用栈的临时日志后，**删键那一刻两者都没被调用** ⇒ 不是本进程；③ `CLIENT LIST` 里有一条 age≈6.6 小时的 `Lettuce` 客户端在跑 `SCAN`（本机实例只有几分钟大）。<br>**解决**：本机独享一个 Redis（`docker-compose.dev.yml` 已加 `redis-local`，**只绑 `127.0.0.1:6380`**），后端用 `SPRING_DATA_REDIS_HOST/PORT` 指过去，做法见 §0.3。隔离后冒烟连续两轮 `PASS=19 / FAIL=0`。<br>**注意**：Postgres（`pass_up_dev`）**仍是共用的** —— 多实例之间的数据级干扰（扣同一份 `user_asset`、回收同一批 `interview` 行）不会因此消失 |
| **迟到起算 / 起算竞态**（2026-09-24 排障过程中证实并**已修**；与上一条环境问题独立） | ① `AudioStreamSession#markSessionReady()` **不校验会话是否已结束** ⇒ 被顶号 / 已关闭的 audio 会话，其**迟到的 `AsrEvent.Ready`** 仍会走完"起算"（实测：连接 35.479 已收尾，36.144 还在为它起算）；② `InterviewBillingService#startBilling()` 的"已存在就跳过"是 **check-then-act**（同一 JVM 内实测**同一毫秒两条** `开始计费`），两个会话都可能写同一个键，键最终可能归属**已死会话**。<br>**已修**：前者加"已结束 / 已暂停即返回"守卫（日志会打 `忽略迟到的「会话就绪」`）；后者改为**只在同一 `logicalSessionId`** 时跳过、属于别的会话则**覆盖并打 ERROR**。两者都有单测（`AudioStreamSessionAsrBaselineTest` / `InterviewBillingServiceTest`）。 |

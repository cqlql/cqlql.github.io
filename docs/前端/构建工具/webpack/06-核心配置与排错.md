# 核心配置项与排错经验

## output 关键字段

### publicPath

`output.path` 决定产物输出目录，`publicPath` 只影响全局资源引用路径（否则相对 `output.path`）。

```js
module.exports = {
  output: {
    path: path.resolve(__dirname, 'dist'),
    publicPath: '/assets/', // 资源以 /assets/ 开头引用
  },
}
```

部分 loader（如 `file-loader`）的 `publicPath` 是在全局基础上追加。

### filename / chunkFilename

- `[hash]`：每次构建都重新生成唯一 hash，所有文件共用 → 任意改动全量失效缓存，**不推荐**。
- `[chunkhash]`：按 chunk 生成，仅当 chunk 变动才变 → 推荐用于长效缓存。
- `[contenthash]`：按文件内容生成（CSS 抽离常用）。

```js
output: {
  filename: 'js/[name].[chunkhash:8].js',
  chunkFilename: 'js/[name].bundle.[chunkhash:8].js',
}
```

> devServer 下不可用 `[chunkhash]`，否则热更新报错，开发期用 `[name].js` 即可。

### entry 也能指定文件夹

```js
entry: {
  'v3/index': ['./src/v3/index.pcss', './src/v3/index.js'],
}
```

但自动生成的引用路径可能多一层，不如直接用 `output` 指定更可控：

```js
output: { path: path.resolve(__dirname, 'dist/v3'), filename: '[name].js' }
```

## resolve 模块解析

- `alias`：简化模块路径，可指向目录或具体模块。
- `modules`：指定模块查找目录，支持文件夹名（向上查找）、相对/绝对路径。

```js
module.exports = {
  resolve: {
    alias: {
      j: './src/js',
      ChunkedShow: 'E:/_work/modules/chunked-show/src/v1/chunked-show.js',
    },
    modules: [
      path.resolve(__dirname, 'node_modules'), // 绝对路径，避免多项目打包出多份同库
      'E:/github/cqlql.github.io/libr',
    ],
  },
}
```

> 使用相对/文件夹名称作为模块路径，可能导致一个 chunk 打包出多个相同模块（各项目自带 `node_modules`）。统一用绝对路径 `node_modules` 可避免。

## Node.js API 编译

避免 CLI 与 config 不同级导致的报错（如 `chunk.sortModules is not a function`）：

```js
const webpack = require('webpack')

webpack(require('./webpack.config')(), (err, stats) => {
  if (err) {
    console.error(err.stack || err)
    return
  }
  const info = stats.toString({ colors: true })
  if (stats.hasErrors()) console.error(info.errors)
  if (stats.hasWarnings()) console.warn(info.warnings)
  console.log(info)
})
```

## 常见排错

### babel 不编译

先检查是否存在 `.babelrc` / `babel.config.js` 配置；有一次为此找了很久原因却**不报错**，坑点在于配置缺失而非语法错误。

### 大批量客户端 node_modules 模块找不到

检查 `resolve.modules` 是否错误地指定了绝对路径导致查找范围被限：

```js
resolve: {
  modules: [
    // 一般不要写死绝对路径，否则其它目录的模块找不到
    path.resolve('../../node_modules'),
  ],
}
```

### css 提取时报错 `chunk.sortModules is not a function`

CLI 且 `node_modules` 与 `webpack.config` 不同级时易触发。改用上面的 Node.js API 编译即可。

### css 模块依赖顺序 / @import 路径

- 在 entry 直接指定 css，依赖顺序不稳定，基础 css 可能被排到后面。
- 在 css 中用 `@import` 更稳定；但 `@import` 的模块不会在 `resolve.modules` 路径中查找。
- 解决：用 `postcss-smart-import` 并指定 `path`：

```js
module.exports = {
  plugins: [
    require('postcss-smart-import')({
      path: ['E:/_work/modules/base-libs/css'],
    }),
  ],
}
```

### CommonsChunkPlugin 打出的公共包被莫名引入

`names` 数组头/尾生成的模块不可控，某个未指定的模块可能被生成进头部公共包。解决：查看源码把多余模块固定打入某公共包，或把公共包同时放在 `names` 头尾。

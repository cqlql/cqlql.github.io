# 小程序真机自动化：怎么在真机上跑脚本

> **一句话结论**：Windows 上可以用官方 `miniprogram-automator` 驱动**真机**，不需要 Appium、不需要 root。
> 前提只有两条：① 工具里把真机连上（「编译并自动调试」或扫码）；② 用 `automator.connect` 连，**不要**用 `automator.launch`。
>
> 所以「AI 没法测真机」这个说法是错的。真话是：**AI 点不了工具里的按钮**（见 §7.1），其余全部可以脚本化。

## 0. 什么时候必须上真机

不是所有问题都值得走真机（每轮要占一台手机、要手动点一次编译）。判据是「模拟器里这个组件的实现和真机不一样」：

| 对象 | 模拟器 | 真机 | 差异后果 |
| :--- | :--- | :--- | :--- |
| `textarea` / `input` | DOM 节点，CSS 全生效，`auto-height` 同步 | **原生组件**，不吃 CSS 行高、默认盒高不同、测量异步 | 高度/边距/首帧闪动只在真机出现 |
| 安全区 `env(safe-area-inset-*)` | 恒为 0 | 真实值 | 底栏压住最后一行 |
| 录音 / 授权 / 蓝牙 / 罗盘 | 假的或没有 | 真实 | 授权态、并发录音互斥 |
| 性能 / 首屏 | 无参考价值 | 参考价值高 | 卡顿、掉帧 |

判断顺序：**先确认问题是不是"只有真机才有"**（模拟器复现不了 ≠ 你的代码没问题），再上真机。反之亦然：模拟器能复现的问题不要拿去真机绕。

## 1. 三条启动方式，哪条能用

官方文档：[真机自动化](https://developers.weixin.qq.com/miniprogram/dev/devtools/auto/remote.html)、[MiniProgram API](https://developers.weixin.qq.com/miniprogram/dev/devtools/auto/miniprogram.html)。

| 方式 | 写法 | 实测结论（工具 2.02.2608080 / Windows 11） |
| :--- | :--- | :--- |
| SDK 启动 | `automator.launch({ cliPath, projectPath })` → `mp.remote()` | ❌ `launch` 直接失败：`Failed to launch wechat web devTools`（内部 spawn `cli.bat` 报 ENOENT，显式给 `cliPath` 也一样） |
| 已连接上调 remote | `mp.remote(true\|false)` | ❌ 一律 `timeout waiting for automator response`（它走 `Tool.enableRemoteDebug`，这条工具版本不应答） |
| **工具里手工 / 自动真机调试** | 工具 UI 连上真机，然后 `automator.connect({ wsEndpoint })` | ✅ 唯一可行；`connect` 之后所有 API 都跑在手机上 |
| 启动工具本身 | `cli.bat auto --project <dir> --auto-port 9431` | ✅ 必需，否则没有自动化端口可连 |

结论：**别在 `launch` / `remote()` 上耗时间**，直接走第三条。

## 2. 最短可行路径（自动模式，不用扫码）

1. 工具**安全设置**里打开「CLI/HTTP 调用」与 CLI token（不开的话 CLI 完全无法启动）。
2. 用 CLI 打开项目并开自动化端口（端口随便挑，别和已有进程撞）：

   ```bash
   "C:/Program Files (x86)/Tencent/微信web开发者工具/cli.bat" auto \
     --project "D:/_work/<repo>" --auto-port 9431
   ```

   日志出现 `√ auto` 且 `netstat` 能看到 `:9431 LISTENING` 即成功。

3. 工具里：**真机调试 → 自动真机调试 → 勾 iOS 端 / 安卓端 → 点「编译并自动调试」**（快捷键 `Ctrl+Shift+R`）。
   - 手机需要：微信在前台、登录的是该小程序的开发者/体验者账号、与电脑同网段。
   - 「局域网模式」出问题时可关掉再试（社区报过 2.0 + 局域网模式连接时好时坏）。
   - 自动模式要微信 7.0.6+（安卓）/ 6.6.7+（iOS）；老客户端退回扫码。

4. 脚本连上并**先判端**：

   ```js
   const automator = require('miniprogram-automator');
   const mp = await automator.connect({ wsEndpoint: 'ws://127.0.0.1:9431' });
   const platform = await mp.evaluate(new Function('return wx.getSystemInfoSync().platform;'));
   // 'devtools' = 还在模拟器（真机没连上）；'ios' / 'android' = 已在真机
   ```

   判端这一步**不能省**：真机没连上时 `connect` 照样成功，后面所有操作都会静默打在模拟器上，跑一遍全绿、结论全错。

## 3. 两个必须知道的互斥关系（最费时间的部分）

### 3.1 `cli auto` 与「真机调试」会互相踢

| 操作 | 结果 |
| :--- | :--- |
| 工具里**编译 / 开真机调试 / 切真机调试版本** | `cli auto` 的自动化 target 被带走 → `connect` 报 `Failed connecting to ws://127.0.0.1:9431` |
| 重跑 `cli.bat auto` | 端口恢复；**真机连接通常还在**，`connect` 又能拿到 `platform=ios` |
| 工具重启 | 两个都得重来（`cli auto` + 真机调试） |

⇒ 固定成这个顺序：**用户点「编译并自动调试」→ 脚本补 `cli auto` → 立刻 `connect` 量数**。

### 3.2 改完代码必须「在工具里编译」才会推到手机

`taro --watch` / `vite build` 之类的监听只写 `dist/`，**工具不重编译，手机上跑的还是旧包**。
最坑的是它不会报错：你怎么改都"没效果"。

判据（别靠感觉）：读一下某个**随本次改动变化**的元素属性，例如

```js
const ta = await (await mp.currentPage()).$('textarea');
console.log(await ta.attribute('style'));   // 旧包/新包会在这里不同
```

## 4. 需要"首帧到稳态"的时间线时：页内采样

### 4.1 别用 automator 逐帧 RPC

真机上一次 `page.$() + size()` 往返要**几百毫秒**（实测 300~600ms）。想量 300ms~1s 的闪动（先高后回落、布局跳一下），
逐帧采样必然漏掉：第一个有效样本往往已经是稳态。

### 4.2 做法：把采样器装进页面里

`mp.evaluate` 在页面上下文里跑一个 30ms 的 `wx.createSelectorQuery` 循环，写进 `globalThis.__probe`，
跑满窗口后一次性取回 —— 分辨率不再受调试桥拖累。

```js
const INSTALL = `
  (function () {
    var t0 = Date.now(), rec = [];
    globalThis.__probe = { rec: rec };
    function tick() {
      var q = wx.createSelectorQuery();
      q.select('.my-box').boundingClientRect();      // 换成你的选择器，最多 4~5 个
      q.select('.my-inner').boundingClientRect();
      q.exec(function (r) {
        rec.push({ t: Date.now() - t0, box: r[0] ? Math.round(r[0].height) : -1,
                                       inner: r[1] ? Math.round(r[1].height) : -1 });
        if (Date.now() - t0 < 12000) setTimeout(tick, 30); else globalThis.__probe.done = true;
      });
    }
    tick();
    return true;
  })();
`;

await mp.evaluate(new Function(INSTALL));   // ⚠️ 在"触发业务动作"之前装好
await (await page.$('.start-btn')).tap();
await sleep(12800);
const data = await mp.evaluate(new Function('return globalThis.__probe || null;'));
```

输出时**只打印发生变化的帧**（差分），一眼就能看出"是哪一层的数字在变"：

```
+  19ms  box=-1  inner=-1
+ 447ms  box=42  inner=33
+1315ms  box=42  inner=33      ← 已稳定
```

### 4.3 判读方法：找"两个量之差"

上面这个例子里结论落在 `box - inner`：如果它在每一帧都相等，说明**外层留白没变**，是内层元素自己的高度在变；
如果它变了，才去看自己写的 padding / margin / flex。

## 5. 已知限制（别在这些点上白耗）

- **`mp.screenshot()` 在真机不可用**：官方文档写明"目前只有开发者工具模拟器支持，客户端无法使用"。要留证只能屏幕录制。
- **原生组件可能查不到**：页内 `createSelectorQuery().select('textarea')` 在真机上可能返回 `null`（实测），
  但 automator 的 `page.$('textarea')` 能拿到 `size()` / `attribute('style')` —— 两种通道互补，别只信一种。
- **播过音频后调试桥容易掉**：收到 WS 二进制帧（TTS 的 PCM）后，工具控制台刷 `incorrect header check`，
  随后任何 RPC 超时、`Remote debug connection lost`。**概率性**，掉了只能重新连真机再来一轮；
  所以脚本的**断言部分要跑在收尾动作之前**，截图/点按钮/disconnect 全部包 `try`，否则掉线会把"全过"判成失败。
- **`page.data()` 读不到业务状态**：断言用元素查询（`$$('view')` 读 class / text），不要读 data。
- **`mockWxMethod` 需要基础库 ≥ 2.9.5**；真机自动化需要基础库 ≥ 2.7.3。
- **`showModal` 之类原生弹窗点不到**：用 `mp.mockWxMethod('showModal', { confirm: true })` 提前改掉返回值。

## 6. 可直接复制的两个脚本

### 6.1 `wait-attach.js`：等真机接入，判端后转交

```js
// 用法：node wait-attach.js [最长等待分钟数]
const { spawnSync } = require('child_process');
const automator = require('miniprogram-automator');

const WS = process.env.MP_WS || 'ws://127.0.0.1:9431';
const MINUTES = Number(process.argv[2] || 10);
const deadline = Date.now() + MINUTES * 60 * 1000;
const sleep = (ms) => new Promise((r) => setTimeout(r, ms));

(async () => {
  while (Date.now() < deadline) {
    let mp = null;
    try {
      mp = await automator.connect({ wsEndpoint: WS });
      const platform = await mp.evaluate(new Function('return wx.getSystemInfoSync().platform;'));
      if (platform && platform !== 'devtools') {
        console.log('真机已接入 platform =', platform);
        await mp.disconnect();
        // 转交给真正的测量脚本
        spawnSync(process.execPath, ['probe.js'], { stdio: 'inherit' });
        return;
      }
      console.log('还是模拟器，继续等…（去工具里点「编译并自动调试」）');
    } catch (e) {
      console.log('连接失败：', e.message, '（需要 cli auto 起端口）');
    } finally {
      try { if (mp) await mp.disconnect(); } catch {}
    }
    await sleep(4000);
  }
  console.log('等待超时');
})();
```

### 6.2 `connect-or-recover.js`：端口没了就自己补

```js
// 端口不通时自己拉 cli auto，然后判端；是模拟器就退出码 4 提示"去点按钮"
const { spawn } = require('child_process');
const automator = require('miniprogram-automator');

const WS = 'ws://127.0.0.1:9431';
const PROJECT = 'D:/_work/<repo>';
const CLI = 'C:/Program Files (x86)/Tencent/微信web开发者工具/cli.bat';
const sleep = (ms) => new Promise((r) => setTimeout(r, ms));

async function connect() {
  try { return await automator.connect({ wsEndpoint: WS }); } catch { return null; }
}

(async () => {
  let mp = await connect();
  if (!mp) {
    spawn('cmd.exe', ['/c', `"${CLI}" auto --project "${PROJECT}" --auto-port 9431`], {
      detached: true, stdio: 'ignore',
    }).unref();
    for (let i = 0; i < 45 && !mp; i++) { await sleep(2000); mp = await connect(); }
    if (!mp) process.exit(1);
  }
  const platform = await mp.evaluate(new Function('return wx.getSystemInfoSync().platform;'));
  await mp.disconnect();
  if (platform === 'devtools') {
    console.error('连上的还是模拟器 ⇒ 先在工具里点「编译并自动调试」');
    process.exit(4);
  }
  console.log('真机在线：', platform);
})();
```

## 7. 排错清单

| 现象 | 原因 | 处理 |
| :--- | :--- | :--- |
| `Failed connecting to ws://127.0.0.1:9431` | 自动化端口没了（工具重启 / 编译 / 切真机调试） | 重跑 `cli.bat auto`；端口通了多半真机还在 |
| `connect` 成功但 `platform=devtools` | 真机没连上，操作全打在模拟器 | 工具里点「编译并自动调试」或扫码 |
| `timeout waiting for automator response` | `remote()` 接口本机不应答 | 别用 `remote()`，走工具 UI |
| `Failed to launch wechat web devTools` | `automator.launch` 在 Windows 上不可用 | 用 `cli auto` + `connect` |
| 改了代码但真机没变化 | 工具没重编译，手机跑旧包 | 工具里 `Ctrl+Shift+R`；比对元素 `style` 属性确认版本 |
| 一轮全绿但结论离谱 | 采样/断言其实跑在模拟器上 | 每个脚本开头判 `platform`，不是真机就退出 |
| 跑一会儿 `Remote debug connection lost` | 音频二进制帧把调试桥顶掉（概率性） | 断言先跑完、收尾全部 `try`；掉线就重新连真机 |

### 7.1 关于「AI 点不了按钮」这件事

把这一条写进来，是为了让下次不用再解释一遍：

- 需要**物理手机扫码**（手工真机调试模式）→ AI 做不到，只能人扫一次。
- 需要**点工具里的「编译并自动调试」** → 桌面点击也不一定能做到：
  Windows 上聚焦窗口 + 发快捷键要 `Add-Type`（P/Invoke）或 `New-Object -ComObject WScript.Shell`，
  很多受管环境会以安全策略直接拦截（实测这两条都被 block）。
- 但**除此之外的一切都能脚本化**：等真机接入、判端、进页面、点业务按钮、填文本、量几何、读样式、跑断言、收尾。
  所以正确的问法是「谁来点那一下」，而不是「能不能测真机」。

## 8. 给 AI 的工作流（复制这段当提示词）

```text
我要在微信小程序真机上验证一个只有真机才能复现的问题。请按 docs/前端/wechat/真机自动化.md 执行：

1. 先判断这问题是否只有真机才有（模拟器里 textarea/input 是 DOM、安全区恒 0）。
2. 用 cli.bat auto 起自动化端口；用 automator.connect（不要 automator.launch）。
3. 先读 platform 确认是 ios/android，不是 devtools 就停下来提示我点「编译并自动调试」。
4. 需要首帧时间线时用页内 30ms createSelectorQuery 采样，不要逐帧 RPC。
5. 断言写在收尾动作之前，截图/结束会话/disconnect 全部 try 包住。
6. 每轮结束报告：真机还是模拟器、量到的数字、改动前后对比、还剩什么没法验证。
```

React 是一个**函数式 UI 框架**。理解它的关键在于建立正确的心智模型：把副作用隔离出去，让渲染保持纯净。

本文是 React 笔记的入门总览，先建立整体心智模型；具体的 Hook 用法见 [useState 与 useRef](./useState-useRef.md)、[useEffect 基础](./useEffect基础.md)、[性能优化 Hook](./性能优化hooks.md)。

## 副作用（Side Effect）

一句话定义：

> **副作用 = 代码执行时，影响了函数外部世界的行为**

如果一个函数不只是“计算并返回结果”，而是**改变了外部状态、环境、数据、网络、DOM 等东西**，那它就有副作用。

在 React 里这些都算副作用：

- 修改 `ref.current`
- `setTimeout` / `setInterval`
- `fetch` / `WebSocket`
- 操作 DOM
- 添加事件监听 / 订阅
- `console.log`（严格来说也算）

函数式编程强调：尽量减少副作用，让数据流可预测。副作用越多，越难调试、测试、维护。

## React 的执行顺序

```
render 阶段（纯函数阶段）
↓
commit 阶段（DOM 更新）
↓
effect 阶段（useEffect 执行）
```

在 render 阶段：

- 不允许有副作用
- 不允许修改外部可变对象（`ref` 属于可变对象）

否则在并发模式下可能会出现状态错乱。

## 组件本质

```typescript
UI = f(state)
```

React 希望 render 阶段是**纯函数**：

- 只根据 `state` / `props` 计算 UI
- 不做任何“影响外部世界”的事

因为在 React 18 中，render 可能执行多次、被丢弃、被中断、并发执行。如果 render 里有副作用，结果就会乱掉。

## 逻辑分两类

| 类型   | 放哪里      |
| ------ | ----------- |
| 纯计算 | render 阶段 |
| 副作用 | useEffect   |

### 属于纯计算（放在 Render 中）

只涉及数据的转换、过滤或格式化：

```javascript
function Receipt({ items }) {
  const total = items.reduce((sum, item) => sum + item.price, 0);
  const formattedTotal = `$${total.toFixed(2)}`;
  return <div>Total: {formattedTotal}</div>;
}
```

### 属于副作用（放在 useEffect 或事件处理函数中）

- 修改全局变量：`window.title = 'Hello'`
- 网络请求：`fetch('/api/data')`
- 操作 DOM：`document.getElementById('my-id').focus()`
- 定时器：`setTimeout(...)`

## 心法

React 核心模型只有一句话：

```
render 是纯函数，副作用放 effect
```

真正需要小心的场景只有几类：

1. **注册型 API**（WebSocket / `setInterval` / `addEventListener` / 第三方 SDK 回调）：这些“注册一次、长期存在”的东西才需要考虑闭包是不是旧的。
2. **useEffect 依赖数组**：effect 依赖什么就写什么，ESLint 插件会兜底。
3. **函数传给子组件 + 性能优化**（`React.memo` / `useCallback`）：这是性能问题，不是正确性问题。

三条原则：

- ① render 里不要做副作用（不改 ref、不发请求、不注册事件）
- ② 长期存在的回调 → 用 ref 或 `useEvent`
- ③ 如果函数不依赖 state，就不用紧张

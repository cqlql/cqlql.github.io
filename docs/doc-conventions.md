# 文档约定（notes-rag 实例）

> **母本在 `cqlql-notes/docs/工程/文档约定.md`**。本文件是它的实例：下面「通用条款」逐字照抄母本，
> **不许在本仓自行修改**；改通用条款 → 改母本 → 再逐仓同步实例，**不要反向**。
> 实例只允许**追加**本仓特有的内容 —— 见最后一节「本仓文档表」。
>
> 母本自己的状态行、「已实例化」清单与跨项目提醒属于母本记账，不复制到实例。
> 本仓的母本实际位于同一仓库的 `note` 分支（`note/docs/工程/文档约定.md`），跨分支写法见 §7.3。
>
> 目的：不让文档越加越多、越读越乱。起因：一个功能堆到 11 份文档，其中两份互相宣称自己是表结构权威。

## 一、四个问题（有一个答不上就别新建）

**1. 这是「契约」「口径」还是「为什么」？**

| 类型 | 放哪 | 判据 |
| :--- | :--- | :--- |
| 契约（表 / 接口 / 消息帧 / 错误码） | **生产方那一仓**；跨端功能收敛到一份「施工图」 | 谁定义谁维护，消费方只放指针 |
| 产品口径（文案 / 交互 / 三态 / 期别） | 需求方那一仓 `<功能>-v<N>.md` | 会随产品决策变 |
| 实现判据（页面 / 踩坑 / 冒烟） | 实现方那一仓 `<功能>-frontend.md` / `<主题>.md` | 换个实现就失效 |
| 「为什么这么设计、哪些方案被否」 | **并进对应实现文档的决策节，不单独开一份** | 单开一份必然烂尾 |

**2. 能不能塞进已有文档的一节？**

能就不新建。**每多一份文件，就多一处要同步的地方** —— 漂移不是从「写错」开始的，是从「同一件事有两个地方写」开始的。

**3. 跨仓 / 跨端吗？**

契约放生产方，口径放需求方。🔴 **两边都不复制字段 / 接口副本，只放指针。**
典型烂法：方案文档里抄了一份表结构，三个月后字段改名，四份文档还在指着旧名。

**4. 它会过期吗？**

会（施工清单 / 旧原型 / 被否方案 / 已冻结稿）→ **建的时候就把状态写进第一行**，别等以后。见第三节。

## 二、命名

| 类型 | 命名 | 例 |
| :--- | :--- | :--- |
| 实现口径 | `<功能>-frontend.md` | `mock-interview-chat-frontend.md` |
| 产品口径 | `<功能>-v<N>.md` | `ai-interview-v1.md` |
| 后端主题方案 | `<主题>.md`（**不加 frontend 后缀**） | `ai-interview-report-ticket.md` |
| 设计稿 | `<功能>-v<版本>-<模块>.html`；基准稿固定 `*-redesign.html` | `me-page-v2-hero.html` |
| 跨仓引用 | 按相对仓名写 | `pass-up.backend/docs/xxx.md` |

## 三、每份文档第一行必须是状态

```md
> 状态：**现行**（2026-10-30）
> 状态：**已完结**（阶段 0~4 全部合入，改代码请转 full-checklist）
> 状态：**已归档**（2026-10-30，被 xxx 取代，只作历史留痕）
```

判据：**读者打开第一眼就该知道「这份还算不算数」**。
反过来，**没有状态行的文档 = 默认为「现行」**，那就必须一直维护它 —— 大多数烂尾文档都是这么来的。

## 四、索引只有一个

- 唯一入口是各仓 `AGENTS.md` 的红线表（**一行 = 一个功能 / 模块**）。
- 不在 AGENTS 里的文档，只能从入口文档的「地图」到达（例：某份 full-checklist 的 §10「按你要干什么查」）。
- 🔴 **不新增 README 类索引**：两个索引必然漂移，最后谁都不准。要补就直接补 AGENTS 那张表。
- 归档的文档在入口表里标 🗄。

## 五、新开项目 / 新仓时（第一天四件事）

1. **`AGENTS.md`**：只放红线 + 指针，目标 ≤220 行 / 16.5KB；超了说明该拆到 `docs/`。
2. **`docs/`**：第一个功能落地时就定下「契约 / 口径 / 实现」三分 —— 别等到有 20 份再回头分。
3. **每份文档第一行写状态**，并在 AGENTS 那张表里给它一行。
4. **实例化本规范**：把本文件复制成该仓 `docs/doc-conventions.md`，顶部写明「母本在 `cqlql-notes/docs/工程/文档约定.md`」，然后**只追加**本仓特有的文档表。

> ⚠️ 反例自查：如果一个功能的文档超过 6 份，先问「是不是有契约被复制了两遍」，
> 而不是「再写一份索引把它们串起来」。

## 六、母本 / 实例：双写边界在哪

「同一件事两个地方写」是漂移的起点，但这里有一处**无法避免的双写**：
AI 只加载当前项目仓的上下文，读不到别的仓 → 通用条款必须在项目仓里有一份全文。

所以把双写范围**钉死在两类内容上**：

| 内容 | 母本（本文件） | 实例（项目仓） |
| :--- | :--- | :--- |
| 4 问、命名规则、状态行、索引唯一 | ✅ 唯一权威 | 照抄，**不许自行改** |
| 本仓文档表 / 本仓路径 / 本仓专有样例 | ❌ 不写 | ✅ 只写这些 |

同步义务：改通用条款时，在本文件顶部的「已实例化」清单里逐仓打勾。

### 7.3 跨分支引用写法（本仓特有，最易踩）

同一个 git 仓库 `cqlql-notes` 有四个分支工作区：`rag`（本仓）、`learning`、`resume`、`note`。
**分支之间在 git 里互不可达**，clone 单个分支后跨分支链接必然断。

- 🔴 引用一律写 **`<分支名>/<路径>`**，例 `learning/实验台账.md`、`resume/学习计划-RAG与Agent.md`。
- 🔴 **不写 `../llm-learning/…` / `../resume/…` / `llm-learning/…`**：那是旧目录规划的名字，现在既已改名又跨分支，全是坏链。
- 确需可点链接时，用当前本地工作区的相对路径（如 `../cqlql-notes.learning/实验台账.md`）并**显式标注「仅本地有效」**；它只是便利，不是权威路径。
- 🔴 **两个 `docs/` 别混**：本仓 `docs/` 是项目文档，`note/docs/` 是语料（`CORPUS_DIR`）。ingest 扫的是后者。

### 7.4 命名与落地样例（本仓特有）

- 主题文档：`<主题>.md` → `rag-solution.md` / `rag-pipeline.md` / `evaluation.md` / `roadmap.md`；**不加 `-frontend`**、不加中文长标题。
- **不建** `docs/README.md`（第二索引）、**不建** `docs/归档/`：废弃文档直接删，git 历史即留档；「为什么不这么做」并进现行文档对应节。
- 跨分支指针样例：`learning/cards/01-rag/06-Rerank.md`、`note/docs/工程/目录结构规范.md`。

### 7.5 新加文档时的落地顺序

1. 过母本 4 问；能并进 `docs/<主题>.md` 一节就不新建。
2. 确需新建：用 `<主题>.md`，**第一行写状态**，正文只写「为什么 / 判据 / 实测怎么量」。
3. **在 `AGENTS.md` §1 速查表补一行**（路径 + 最硬的一条红线），否则这份文档没有入口。
4. 在本文件 §7.2 补一行状态；会过期的写清过期判据，归档时在速查表标 🗄。

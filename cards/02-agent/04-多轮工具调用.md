# 多轮调用时上下文怎么管

## 30 秒版

> 关键词桩，不是成稿。合上卡，用这几根桩自己连成 5 句话。

- messages 是成对结构：assistant(tool_calls) ↔ tool(tool_call_id)，缺一半就报错
- 工具返回只给模型要用的字段，别整坨塞
- 长结果三招：截断加提示、先摘要、分页式让模型自己取
- 超限先删最早的完整轮次，保留 system，绝不单独删 tool 消息

## 展开

**三轮之后的 messages 长什么样**

```
system
user: 上次面试怎么样？
assistant(tool_calls: [A: get_interview_record, B: list_questions])   ← 一次返回两个
tool(tool_call_id=A): {"rounds":3,"score":82,...}
tool(tool_call_id=B): {"items":[...]}
assistant(tool_calls: [C: score_answer])
tool(tool_call_id=C): {"score":78,"reason":"..."}
assistant: 你上次三轮面试，平均 80 分……                                ← 最终答案
```

**成对是硬约束**：每个 `tool_calls` 的 id 必须有且只有一条对应的 `tool` 消息。裁剪时必须整对删（assistant + 它所有的 tool 消息），否则 API 报 `messages with role 'tool' must be a response to a preceding message with 'tool_calls'`。

**工具结果瘦身**（最容易被忽略的省钱手段）

| 原始返回 | 给模型的 |
|---|---|
| 整条 DB 记录（含创建时间、软删标记、内部字段） | `{id, title, score}` |
| 1000 条列表 | 前 20 条 + `{"total": 1000}` |
| 5000 字文档全文 | 前 800 字 + `"...[已截断，共 5123 字]"` |

**长结果三招**：① 截断 + 省略提示（最省，但模型不知道后半段有什么）② 先用小模型摘要再回填（多一次调用，信息有损）③ 分页式工具（给 `offset`/`limit` 参数，让模型自己决定要不要下一段——最灵活，但要额外一轮）。

**裁剪顺序**：先删最早的完整轮次（保留 system + 最近 N 轮），因为当前任务依赖最近几轮。不要动「最近一轮的 tool 消息」——模型正在用它。也永远不要单独删中间的 tool 消息：结构会不成对；就算 API 不报错，assistant 里还留着 tool_calls 记录，模型会以为「我调了但没结果」，可能重复调用。

**预留输出空间**：算上下文预算时要扣掉 `max_tokens`，别把窗口塞满导致输出被截断。

## 追问预演

- **Q**：三轮工具调用之后，messages 里具体有哪些消息？顺序是什么？
  **A**：**要点**：按顺序背出来——system → user → assistant(tool_calls A,B) → tool(A) → tool(B) → assistant(tool_calls C) → tool(C) → assistant(最终文本)。强调两点：每个 id 有且只有一条对应 tool 消息；顺序要能对上（虽然靠 id 匹配，但乱序容易在裁剪时出错）。

- **Q**：工具返回 5000 字，你直接塞回去吗？
  **A**：**要点**：不。先问「模型要用它干什么」——只是判断有没有记录，就返回 `{found, id, title}`；要引用原文，就返回截断版 + 总字数。5000 字 ≈ 3000+ token，一次问答就吃掉大半窗口，而且长文本会稀释注意力（lost in the middle），塞进去不等于用上了。

- **Q**：上下文超了，先裁哪部分？为什么不能裁中间的 tool 消息？
  **A**：**要点**：先删最早的完整轮次（最老的一问一答），保留 system 和最近几轮。不能单独裁 tool 消息有两个原因：结构不成对，API 直接报错；就算不报错，assistant 里还留着 tool_calls，模型会以为「调了但没结果」，可能重复调用。

- **Q**：怎么让模型知道某个工具已经调过了，避免重复调？
  **A**：**要点**：上下文里本来就有记录，问题出在**结果为空**时模型会重试。做法：空结果显式写清 `{"found": false, "note": "已查询，该条件无记录，不要重复查询"}`；system 里加「同一工具同一参数最多 2 次」；代码层做幂等缓存，相同参数直接返回缓存 + `cached: true`。

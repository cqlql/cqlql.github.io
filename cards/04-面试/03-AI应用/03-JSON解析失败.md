# 模型输出的 JSON 解析失败怎么办

## 30 秒版

三层。第一层 Schema 约束，从源头减少非法输出；第二层解析失败重试一次，仍失败就返回可读错误，不把异常抛给用户；第三层能降级的降级，比如填表失败就保留手动填写。

## 展开

- 为什么只重试一次：两次都失败说明不是抖动，是 prompt 或 Schema 有问题，多试只是烧钱
- 为什么不抛异常给用户：用户看不懂栈，只想知道「现在能不能继续」
- 降级设计：每个 AI 能力都要有「模型不可用时的兜底路径」，不是可选项

## 我的数字

- 三层：Schema / 重试 1 次 / 降级
- 重试放大了成本，所以结构化输出本身就是在省钱

## 追问预演

- **Q**：为什么不是三次五次？
  **A**：一次重试已经能覆盖大部分抖动。再失败基本是结构性问题，多试只增加成本和延迟，不如把错误暴露出来。
- **Q**：降级之后用户会不会觉得功能坏了？
  **A**：会，所以文案要给下一步动作——「自动填充失败，请手动填写」，而不是一个红叉。

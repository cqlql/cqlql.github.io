# 你是做算法还是做应用

## 30 秒版

我是 AI 应用开发，负责把模型能力接进产品并保证稳定，不训模型、不做微调。具体是 prompt 设计、结构化输出约束、流式链路、超时与降级、多模型适配。我能判断哪些环节不该用模型，这比会调 API 重要。

## 展开

- 边界先立住：训模型、微调、蒸馏都不做，含糊到技术面一定露
- 应用侧的价值：同样接一个模型，能不能稳定、可预期、可回滚
- 不该用模型的地方：判分、权限、计费，一律走规则

## 我的数字

- 四类生产经验：prompt / 结构化输出 / 流式链路 / 多模型适配
- 训练与微调经验 0 次（如实说）

## 追问预演

- **Q**：那你懂模型吗？
  **A**：懂调用和约束，不懂训练。知道 temperature、上下文窗口、指令跟随强弱这些影响输出的因素，也知道本地部署能干什么。
- **Q**：为什么不学微调？
  **A**：我这个场景不需要。结构化输出加 Schema 约束已经能把输出限住，微调解决的是风格和领域语言，性价比不高。

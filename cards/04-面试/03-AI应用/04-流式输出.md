# 流式输出怎么做的

## 30 秒版

LLM 增量 token 按句聚合，通过 WebSocket 下发 LLM_REPLY 分片，前端收到就追加渲染。结束信号只认最后一片带的 final:true。坑是 Java 字段叫 isFinal，Jackson 序列化后成了 final，只按 isFinal 找会得出「信号不存在」的错误结论。

## 展开

- 为什么按句聚合而不是逐 token 推：逐 token 前端渲染成本高，按句更稳，断连时丢的也少
- 结束信号为什么必须唯一：多个结束判据会打架，前端只能认一个
- 那个 isFinal 的坑：序列化后的字段名和 Java 属性名不一致，排查了很久

## 我的数字

- 分片 + `final:true` 单一结束信号
- 一个真实的序列化命名坑（`isFinal` → `final`）

## 追问预演

- **Q**：丢片了怎么办？
  **A**：按序号补齐，缺片就整轮重下。前端不做「猜测补全」，猜错比重来更贵。
- **Q**：前端怎么防重复渲染？
  **A**：按消息 ID 和片序号去重，同一片到两次直接丢弃，不追加。

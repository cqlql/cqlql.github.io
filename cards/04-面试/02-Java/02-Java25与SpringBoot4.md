# 为什么用 Java 25 和 Spring Boot 4

## 30 秒版

新项目从 0 开始，直接选当时最新的 LTS 和配套主线，避免上线即落后——等业务长起来再升级，代价比一开始就用大得多。代价也要认：部分 starter 适配滞后，Hibernate 与 JPA 的行为有变化，是真踩过坑的。

## 展开

- 为什么敢用：没有历史包袱，没有存量依赖逼着你留在旧版本
- 代价分类：starter 生态滞后、JPA 行为变化、文档与社区答案少（遇到问题搜不到现成的）
- 落点：选版本不是炫技，是算过升级成本和生命周期

⚠️ **这张卡必须自己补一个真实踩坑**：具体哪个依赖不兼容、现象是什么、怎么绕过的。讲不出细节，就别把版本号当卖点。

## 我的数字

- Java 25 / Spring Boot 4 / Maven 按业务域拆 20 个模块
- 47 个 Flyway 迁移、72 个实体，全部在新版本上跑通
- 待补：⚠️ 一个具体的 starter 或 JPA 行为不兼容案例

## 追问预演

- **Q**：不怕生态不成熟吗？
  **A**：怕，所以先跑通最小闭环再铺业务。真遇到 starter 没跟上就临时自己接，不阻塞主线。

# 47 个迁移怎么管

## 30 秒版

Flyway 版本化，禁止改已经执行过的脚本，只能新增。回滚靠备份恢复，不靠 down 脚本，因为社区版没有 undo。加字段这类变更要单独想清楚默认值和锁级别，不能顺手塞进老脚本里。

## 展开

- 为什么只增不改：线上已经跑过的脚本一改，各环境的库就和代码分叉了，而且没人知道自己那份到底是什么状态
- 回滚策略：备份恢复是主线，业务层的兼容靠新迁移里的兜底，不指望逆向脚本
- 大表加列的注意点：默认值、锁级别、是否需要分批，能讲清 `ALTER TABLE` 的行为最好

## 我的数字

- 47 个 Flyway 迁移、72 个实体
- 「迁移只增不改」是 AGENTS.md 里的不变量之一，AI 改动前必须先读

## 追问预演

- **Q**：要改一个字段类型怎么办？
  **A**：新加一列 → 迁移数据 → 双写或读时兼容 → 下线旧列。不直接改已执行过的脚本。
- **Q**：多人并行开发迁移版本号冲突呢？
  **A**：约定时间戳命名并先拉最新，冲突了改自己的版本号，不合并别人的脚本。真要撞了，宁可重排也不改已执行的。

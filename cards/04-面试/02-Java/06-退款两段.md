# 退款为什么是两段

## 30 秒版

钱在微信侧退，系统回滚不了微信的退款，所以资金事实和资产收口必须用两个字段表达。乱序时退款通知可能比发货回调先到，这时先原子改状态抢占幂等，再扣资产——不是先扣后改，顺序反了会把资产重复补出去。

## 展开

- 两个字段各管什么：`pay_status` 是资金事实，`refund_settle_status` 是资产收口，两者的推进不完全同步
- 乱序场景走一遍：通知到 → 改状态为已退款 → 检查资产是否已发 → 已发才扣，未发就不扣但记标记
- 为什么先改状态：状态是幂等闸门，先抢住闸门，后面的动作才不会重复执行

## 我的数字

- 两个状态字段：`pay_status` / `refund_settle_status`
- 管理后台 17 个功能模块，其中计费与退款是一个独立模块

## 追问预演

- **Q**：为什么不能一个字段搞定？
  **A**：一个是外部资金事实，一个是内部资产处理。资金退了但资产还没扣完，这个中间态必须能被表达出来，否则补偿任务无从下手。
- **Q**：乱序导致资产多发了怎么办？
  **A**：这就是先改状态的意义。状态先落成已退款，补发任务查到它就不会再发，等于用状态兜住了乱序。

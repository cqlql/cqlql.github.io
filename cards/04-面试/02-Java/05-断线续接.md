# 断线续接怎么做的

## 30 秒版

物理连接会断——切后台、杀进程、心跳超时——但逻辑会话不能丢。逻辑会话 ID 取首次建连的 session id，重连时复用。双 TTL：paused 15 分钟是内存态，resumable 1 小时可恢复，判据是数据库里的 paused_at，不是内存。

## 展开

- 两个 TTL 的语义不同：15 分钟是「用户可能马上回来」的短窗，1 小时是「服务端还愿意为它保留状态」的长窗
- 为什么判据在 DB：内存态重启就没了，会话能不能恢复必须有个持久的事实
- 为什么 ID 取首次建连而不是每次新建：否则每次重连都是新会话，历史全丢

## 我的数字

- 15 分钟 pause / 1 小时 resumable / `paused_at` 落库
- 42 个小程序页面与 Web 端共用同一套会话接口

## 追问预演

- **Q**：为什么两个 TTL？
  **A**：一个是用户体验上的「还算连续」，一个是系统愿意付存储代价的上限。合成一个，要么用户回来发现没了，要么长期占着状态。
- **Q**：重连后上下文怎么恢复？
  **A**：会话消息按序存在库里，重连按逻辑 ID 取回来重灌给 LLM，不依赖内存里的那一份。

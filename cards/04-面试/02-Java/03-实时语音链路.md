# 实时语音链路怎么设计

## 30 秒版

上行用 WebSocket 传 PCM 帧，建连即创建会话；豆包 ASR 实时返回，只有 final 才触发 LLM，避免同一句话反复生成；下行 LLM_REPLY 分片推送，最后一片带 final:true。每一环都要有超时和降级，因为任何一环抖动，用户都会以为卡住了。

## 展开

- 为什么中间结果不触发 LLM：ASR 会反复修正，触发一次就多一轮生成和一次计费
- 为什么每个环节都要超时：ASR、LLM、TTS 都是外部服务，链路越长越容易被最慢的一环拖住
- 降级顺序：TTS 失败转纯文本、模型超时返回明确错误，不静默重试到用户失去耐心

## 我的数字

- 六步主链路：取票据 → 建连（建连即创建 Interview）→ ASR → final 触发 LLM → 增量下发 → 上行 END 才真正结束
- 豆包 ASR 8 秒收不到音频就终结连接，静默是常态

## 追问预演

- **Q**：为什么不用 MediaRecorder？
  **A**：它出的是压缩容器格式，服务端还要解一遍。AudioWorklet 直接拿 PCM，采样率和位深自己控，链路上少一层。
- **Q**：用户说一半停住怎么办？
  **A**：ASR 8 秒无音频就终结连接，所以静默要保活，断连要能自动重建，逻辑会话不能跟着断。

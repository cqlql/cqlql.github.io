# 677 个单测怎么写的

## 30 秒版

JUnit 5 + Mockito，重点覆盖状态机和边界：会话续接、计费门槛、退款乱序、权限归属。ASR、LLM、微信回调全部 mock，不依赖真实网络。也有故意不测的，比如第三方 SDK 的薄封装。

## 展开

- 为什么集中在这四类：这四处错了不是「不好用」，是「钱错了」或「数据错了」，属于不可接受的错误
- 怎么 mock 外部服务：接口层抽象好，测试里替换成桩，不穿透到真实网络
- 故意不测的：第三方 SDK 的薄封装、纯 DTO 的 getter，测了只增加维护成本

## 我的数字

- 677 个 `@Test` / 91 个测试类 / 6.3 万行
- 覆盖四组：会话续接、计费门槛、退款乱序、权限归属

## 追问预演

- **Q**：覆盖率多少？
  **A**：没统计行覆盖率，按「关键路径必测」来定的。行覆盖率对这类项目是虚荣指标，状态迁移漏测才是风险。
- **Q**：这些测试能拦住 AI 改坏代码吗？
  **A**：能拦住状态机和边界被改坏。重构类改动先跑测试，红了就回退，不靠解释。

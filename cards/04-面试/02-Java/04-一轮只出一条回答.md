# 怎么保证一轮只出一条回答

## 30 秒版

同一会话内用状态机串行化，同一时刻只允许一个在途回合；首问和用户作答共享同一份在途状态，不会各自起一条。没用锁，因为锁是跨会话的，这里要的是同一会话内的串行。

## 展开

- 为什么不用分布式锁：锁的粒度错了。跨会话加锁会互相拖累，这里只需要单会话内排队
- 状态机比布尔标记好在哪：能表达「进行中 / 待确认 / 已结束」，且非法状态转移能直接拒绝
- 单线程执行：同一会话的回合按队列推进，避免并发写同一份会话状态

## 我的数字

- `ConversationTurnRunner` 负责串行化
- 踩过的坑：一轮收到两条 final，界面会重复插入分隔符

## 追问预演

- **Q**：多实例部署时怎么保证？
  **A**：会话有归属节点，粘性路由到同一实例；跨实例续接靠 DB 里的会话状态，不靠内存里的锁。
- **Q**：用户连点两次发送呢？
  **A**：在途状态存在就拒绝新的回合，返回当前进度，不排队也不并发。

# AI 填表怎么保证输出可用

## 30 秒版

按表单字段定义递归生成 JSON Schema：子表转 array、分组转 object、下拉只允许 option id 走 enum、数值字段转 number，再用 `response_format` 的 json_schema 约束模型只能输出合法结构。没开 strict 是业务取舍，因为空值字段允许不输出。

## 展开

- 为什么不用 function call：这里要的是一次性拿到整张表单的填充结果，不是让模型逐步调工具
- 为什么不开 strict：strict 要求所有字段都出现并 `additionalProperties:false`，而很多字段本来就该留空
- 数据不出内网：模型是本地 vLLM 部署，走 OpenAI 兼容接口

## 我的数字

- 32 种控件 → 递归生成的 Schema
- 本地 Qwen3.5-4B（vLLM），数据不出内网；OCR 侧用 PaddleOCR-VL

## 追问预演

- **Q**：模型乱输出怎么办？
  **A**：两重。Schema 先把形状限死，枚举限死取值；再解析失败就重试一次，仍失败返回可读错误，让用户手动填。
- **Q**：strict 三条硬要求是什么？
  **A**：所有 object 加 `additionalProperties:false`、所有字段进 `required`、不能出现 `$ref` 要内联展开。少一条就不是严格模式。

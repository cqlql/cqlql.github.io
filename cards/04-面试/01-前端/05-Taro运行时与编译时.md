# Taro 运行时方案和编译时方案的区别

## 30 秒版

运行时方案在 JS 层跑框架的响应式，把小程序生命周期桥接过去，好处是生态能复用、写法一致，代价是包体积和启动时间；编译时方案直接把代码编译成小程序的结构，体积小、启动快，但跨端一致性难做。坑一般在生命周期映射和小程序样式限制上。

## 展开

- 两条路的取舍：运行时换兼容性，编译时换性能
- 常见坑：生命周期映射（`onShow` 和 `mounted` 的时机差）、小程序不支持的选择器与样式、setData 的数据量
- 我的实际用法是编译时方案，运行时方案讲原理为主

⚠️ 别声称深用过 Taro 3 运行时解析 Vue，会被追问到具体源码细节。

## 我的数字

- PassUp 小程序：Taro 4.3 + React 18，42 个页面，与 Web 端共用同一套接口契约

## 追问预演

- **Q**：你实际用哪种？
  **A**：编译时。PassUp 小程序是 Taro 4.3 编译方案，42 个页面。运行时方案我清楚原理，但没在生产项目里深用过。
- **Q**：小程序端最麻烦的是什么？
  **A**：样式和生命周期。Flex 之外的选择器支持有限，`onShow` 触发时机和 Web 的 mounted 不一样，登录态刷新常常要在这里补一次。

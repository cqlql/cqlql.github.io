JAR vs WAR 如何选择？

对于 Spring Boot Web API 项目，绝大多数情况下的标准答案是：JAR。

维度JAR (推荐)WAR (传统)
部署难度极低（单文件，一行命令）中（需预装服务器软件）
启动速度快较慢（涉及解压过程）
云原生/Docker完美适配兼容，但显得笨重
适合场景Web API、微服务、独立应用必须共享旧版 Tomcat 的传统环境

JAR 的优势

  1. 内嵌服务器：运行 java -jar app.jar 即可，自带 Tomcat
  2. 开发与运维一致：本地和服务器逻辑完全一致
  3. 微服务与容器化绝配：Dockerfile 只需一行 ENTRYPOINT ["java", "-jar", "app.jar"]

什么时候必须用 WAR？

只有一种情况：甲方或运维要求所有 API 必须统一扔到外部 Tomcat 容器里跑。

部署难度简单中等较高 (编译慢)

打包命令

mvn clean package

本地依赖 mvn install

把当前项目的打包结果放到本地仓库里，供其他项目引用。

<dependency>
    <groupId>com.example</groupId>
    <artifactId>my-utils</artifactId>
    <version>1.0-SNAPSHOT</version>
</dependency>

SNAPSHOT vs RELEASE

类型版本号示例行为
Release1.0.0本地有了就永远不更新
Snapshot1.0-SNAPSHOT定期检查更新，-U 强制刷新

工具份额特征核心标签

核心建议

  1. 不管用哪种，先做 CI/CD：永远不要手动 scp 一个 Jar 包覆盖生产
  2. 关注 Java 版本：生产环境至少 Java 21 (LTS)，利用虚拟线程提升并发能力
  3. 可观测性：集成 Prometheus 和 Grafana
